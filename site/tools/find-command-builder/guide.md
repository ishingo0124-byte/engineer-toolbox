find のオプション、毎回 man を開いて確かめている。
-mtime +7 は何日前のことなのか。
-delete を付ける前に、何が消えるのか見ておきたい。
起点パスや名前、日時、サイズなどをフォームで選ぶと、-exec や -delete、xargs まで付いた find コマンドが1行できあがります。

## 使い方

1. 起点パスと、名前パターン、種別、更新日時、サイズなどの条件を入力します。必要な項目だけで足ります。
2. 空欄や「指定しない」の項目は、コマンドに出ません。
3. 最後に、後段のアクション（-exec、-delete、xargs）を選びます。

条件を変えるたびに、コマンドと「生成された条件の意味」の一覧が更新されます。意味の一覧を読むと、コマンドを覚えていなくても確認できます。

4. 「コマンドをコピー」で、生成結果をそのまま貼り付けられます。

条件はすべて AND でつながります。OR（-o）や括弧の組み立ては、このツールでは扱いません。

## 仕組み・計算式

根拠は、GNU findutils の find(1) と、POSIX の find です。条件は左から順に評価され、並べた条件はすべて真のときだけ一致します。ツールは次の順に組み立てます。

- 起点パス。次に、あれば -maxdepth。
- -type、-name または -iname、-mtime または -mmin、-size、-user、-perm、-empty の順。

-maxdepth を先頭に置くのは、find(1) が他の条件より前に書くよう勧めているからです。

- 最後に、-exec か -delete か -print0 です。

ここまでが並び順で、中身にも約束事があります。

- -mtime n: 最終更新からの経過時間を24時間単位で切り捨てて比べます。-mtime +7 は「8日以上前」、-mtime -7 は「7日未満（直近7日）」、-mtime 7 は「7日以上8日未満」です。
- -size n[ckMG]: サイズを単位に切り上げて比べます。M は MiB（1,048,576 バイト）で、10 の6乗ではありません。

切り上げの境目は、計算例で数字にしました。

- -perm: 数値だけなら完全一致、-mode は指定ビットをすべて含む、/mode は指定ビットのどれかを含む、です。

名前パターンは、シェルに展開されないよう、必要なときだけシングルクォートで囲みます。

## 計算例

ツールの script.js をそのまま node で動かして、実際に出たコマンドを書きました。サイズの丸めだけは、find(1) の規則から手で検算した値です。

**例1: 初期値のまま。** find . -type f -name '*.log' -mtime +7 -size +10M です。8日以上前に更新された、10 MiB を超える .log ファイルが対象です。10 MiB ちょうど（10,485,760 バイト）は対象外で、10,485,761 バイトから一致します。切り上げの規則で、11 単位として数えられるからです。

**例2: 直近30分。** 更新日時を「-N」、N を30、単位を「分」に替えると、-mmin -30 に変わりました。find . -type f -name '*.log' -mmin -30 -size +10M です。

**例3: 深さを1に絞って削除。** -maxdepth を1、名前を *.tmp、マッチ方式を -iname、日時とサイズを「指定しない」、アクションを -delete にします。結果は find . -maxdepth 1 -type f -iname '*.tmp' -delete でした。-maxdepth が起点の直後に置かれ、-delete は末尾です。

**例4: setuid の洗い出し。** 所有者に root、-perm の方式を「/mode」、値に 4000 を入れます。find . -type f -user root -perm /4000 になりました。

**例5: 境界値のN=0と、-size -1k。** 更新日時を「N」の方式で 0 にすると -mtime 0 で、「経過24時間未満」の意味です。サイズを「-N」で 1、単位を k にすると -size -1k になります。find(1) の規則では、-size -1k が一致するのは空のファイルだけです。

**例6: xargs でまとめて渡す。** アクションを xargs にして rm -f を指定すると、find . -type f -name '*.log' -mtime +7 -size +10M -print0 | xargs -0 rm -f が出ます。

## よくある間違い

**-mtime +7 を「7日前」だと思う。** 実際は8日以上前です。意外だったのは、-mtime 7 が「ちょうど7日前」ではなく、7日以上8日未満になることでした。ツールの説明欄には、丸めの都合で実際の日数が出ます。

**-delete を条件の途中に置く。** find は左から評価するので、-delete に到達した時点で削除が実行されます。その後ろの -name などは、削除を止められません。まず -delete を外して一致するものを確認し、最後に付けてください。このツールは -delete を末尾に置きます。

**パターンをクォートしない。** find . -name *.log と打つと、シェルが先に *.log を展開します。カレントディレクトリにログがあれば、find には別の引数が渡ります。ツールが付ける '*.log' のクォートは、そのためです。

**-name にディレクトリ区切りを入れる。** -name はファイル名の部分だけと比べます。「logs/*.log」のようにスラッシュを含めても、期待どおりには一致しません。ディレクトリで絞るなら、起点パスを変えるか -path を使います。

## よくある質問

### Q. GNU find と macOS（BSD）の find で、同じコマンドが使えますか？
A. -name、-type、-mtime、-size、-delete などの基本は共通です。-printf や -regextype は GNU 独自で、macOS 標準の find にはありません。起点パスの省略を許さない実装もあるので、macOS では「.」を明示しておくと安全です。

### Q. -maxdepth は、どこに置くのですか？
A. 起点パスの直後です。GNU の find は、他の条件のあとに置くと警告を出します。ツールは自動で、この位置に生成します。

### Q. -exec の {} + と {} \; は、どちらを使うべきですか？
A. {} \; は1件ずつコマンドを起動するので確実ですが、遅くなります。{} + は複数のファイルをまとめて渡すので速いです。ファイルが多いときは {} + をおすすめします。

### Q. スペースを含むファイル名は、どう渡せばいいですか？
A. -print0 | xargs -0 か、-exec を使ってください。GNU の xargs では、一致が0件のときも1回コマンドが走るので、-r を付けると安心です。

画面のレイアウトを確かめたいのに、手元にテストデータがない。
本物の個人情報は、開発環境には入れたくない。
しかも、後からもう一度、同じデータを出したい。
件数と列を選ぶと、氏名・住所・メールなどの架空データを、CSV・JSON・SQL の INSERT 文で出力します。シードを決めれば、同じ顔ぶれを繰り返し作れます。

## 使い方

1. 「件数」に 1〜1,000 の数字を入れ、欲しい列にチェックを入れます。連番ID、氏名（漢字・かな・ローマ字）、性別、生年月日、年齢、メール、電話、郵便番号、都道府県、市区町村・番地、会社名、UUID、価格、登録日時から選べます。
2. 「シード」に好きな文字や数字を入れると、同じシードなら同じデータが出ます。空欄なら、そのたびに別のデータです。
3. 「出力形式」を CSV・JSON・SQL INSERT 文から選びます。SQL のときだけ「テーブル名」が使われます。
4. 「結果をコピー」で、出力欄をまとめてコピーできます。

設定を変えるたびに、結果は自動で作り直されます。

## 仕組み・計算式

姓20種、男女の名それぞれ12種と10種、都道府県47と代表的な市区、町名などの部品を、乱数で組み合わせています。実在の人物や企業を指すものではありません。

乱数は、シード空欄のときは JavaScript の `Math.random` です。シードを入れると、mulberry32 という小さな擬似乱数生成器に切り替わります。32ビット整数を種にして、いつも同じ順番で数を出す方式です。数字だけのシードはその数値を種にし、文字を含むシードは文字列から計算した整数を種にします。全角の数字は半角にそろえるので、`2026` と `２０２６` は同じ結果になりました。

生成される値には、次の規則があります。

- 年齢は 18〜89 歳の範囲で決め、そこから生年月日を逆算します。「年齢」の列は、生年月日と今日の日付から計算し直します。
- メールのドメインは example.com と example.org です。どちらも RFC 2606 が文書・例示用に予約しているドメインです。
- 電話は 090 か 03 で始まり、残りは乱数の数字です。郵便番号は 100〜999 の3桁と、乱数の4桁です。
- 価格は 100〜49,999 の整数、登録日時は今から3年以内です。

最後に、出力の書式です。CSV は列に `,` `"` や改行が含まれるときだけ二重引用符で囲み、改行は CRLF です。JSON は整形された配列、SQL の INSERT 文は ANSI 系の書式で、id・age・price だけ数値として引用符なしで出ます。

現場の落とし穴を1つ。シードが同じでも、年齢や生年月日の年、登録日時は、日付が変わると変わります。「今日」を基準に作っているためです。

## 計算例

出力は、このツールの script.js を node で実行して得ました。実行日は 2026-11-13 で、年齢と生年月日はこの日付が基準です。

**例1: シード `2026`、3件、既定の列**

1件目は、`1,加藤 健一,かとう けんいち,男性,1964-02-07,62,kenichi.kato714@example.org,090-0063-1134,928-5022,香川県,高松市新町5-16-3` でした。2件目は渡辺 健太（`kenta.watanabe790@example.org`、栃木県）、3件目は山田 一郎（`ichiro.yamada302@example.com`、熊本県）です。同じ設定で2回出すと、全行が一致しました。シードを `２０２６`（全角）にして1件だけ出すと、1行目は上と同じでした。

**例2: SQL INSERT 文**

シード `2026`、2件、テーブル名 customers、列を id・氏名（漢字）・メール・価格にすると、次の文になりました。

```
INSERT INTO customers (id, name_kanji, email, price) VALUES
  (1, '加藤 健一', 'kenichi.kato714@example.org', 41566),
  (2, '渡辺 健太', 'kenta.watanabe790@example.org', 45778);
```

氏名は、例1と同じ人物です。列の選び方を変えても、人物は変わりません。

**例3: JSON と別のシード**

シード `sample-01`、2件、列を id・氏名・年齢・メールにして JSON で出すと、1件目は清水 浩二（21歳、`koji.shimizu397@example.org`）、2件目は佐々木 大輔（30歳）でした。年齢は実行日で変わる部分です。

**例4: 境界値**

件数に 5000 と入れると 1000 件に直され、「1000件で生成」と注記が出ました。CSV は見出し行を含めて 1001 行です。0 と入れた場合は 1 件になりました。列を1つも選ばないとエラーになり、出力は空です。

## よくある間違い

### 1. 郵便番号と住所が対応していると思う

郵便番号は乱数で、都道府県とは無関係です。例1の1件目は、香川県に 928- から始まる番号が付いています。住所の正しさを検証する機能のテスト（郵便番号から住所を引く処理など）には、使えません。

### 2. 同じシードなら、いつまでも同じと思う

名前、メール、電話、住所は変わりません。ただし生年月日の年、年齢、登録日時は、実行日で動きます。固定したデータが必要なら、出力を保存してください。

### 3. 電話番号やメールを、実際に使ってしまう

電話番号は乱数の数字なので、実在の番号と一致する可能性がゼロではありません。実際の発信には使わないでください。メールも、送信テストに使う前に、宛先が自分の管理下にあるか確かめてください。送信まで試すなら、自分のテスト用アドレスに置き換えてください。

### 4. 乱数を、パスワードや鍵に使う

`Math.random` も mulberry32 も、暗号用の乱数ではありません。UUID の列も同じ乱数から作っているので、本物の識別子やトークンの代わりにはなりません。

## よくある質問

### Q. 生成されるデータは、実在の人物と関係ありますか？
A. ありません。姓名は一般的な部品を組み合わせただけです。ただし、たまたま実在の人と同じ名前になる可能性は、組み合わせの性質上ありえます。

### Q. 後日、同じデータをもう一度作れますか？
A. シードと件数、同じ列の選択があれば、人物・メール・電話・住所は再現できます。列の選択を変えても人物は変わりませんでした。ただし年齢・生年月日・登録日時は、日付の影響を受けます。

### Q. SQL INSERT 文は、どのデータベースでも動きますか？
A. 文字列のシングルクォートは、2つ重ねてエスケープしています。標準的な書き方で、主要なデータベースで使える形です。ただしテーブル名に英数字とアンダースコア以外が含まれると、バッククォートで囲みます。この囲み方は MySQL 系の書式なので、ほかのデータベースでは書き換えてください。

### Q. 件数の上限はありますか？
A. 1,000 件です。それを超えて入力しても、1,000 件に直されます。

1TB のSSDを買ったのに、PCでは931GBしかない。
回線は100Mbpsなのに、ダウンロードは10MB/s台しか出ない。
数値と単位を入れると、B・bit・10進（KB〜TB）・2進（KiB〜TiB）にまとめて換算し、どの単位の差で数字がずれたのかを並べて確かめられます。

## 使い方

1. 数値を入れ、単位をセレクトから選びます（B・KB・MB・GB・TB・KiB・MiB・GiB・TiB・bit）。初期値は 1.5 と GB です。
2. 入力と同時に、B と bit、10進と2進を並べた表が更新されます。全角の数字や「．」も半角として読まれます。
3. 小数も入れられます。内部は BigInt を使った固定小数点の計算なので、0.1 のような値で2進数特有の誤差は出ません。
4. 桁区切りのカンマ（1,500 など）や、`1e3` のような指数表記は受け付けず、「数値を入力してください」と出ます。

マイナスの値は符号つきのまま換算されます。差分の計算用です。

## 仕組み・計算式

「キロ」「メガ」「ギガ」には、2つの意味があります。

- 10進接頭辞（SI）: K=1,000、M=1,000²、G=1,000³、T=1,000⁴
- 2進接頭辞（IEC）: Ki=1,024、Mi=1,024²、Gi=1,024³、Ti=1,024⁴

あと、bit は別の話で、1バイト=8ビットです。

2進接頭辞は、IEC 60027-2 と、それを引き継いだ IEC 80000-13 で定義されています。読み方は「キビ」「メビ」「ギビ」です。10進のほうは、国際単位系（SI）の接頭辞の定義そのものです。

このツールは、入力を一度バイトに直し、そこから各単位へ割ります。bit は 1/8 バイトです。

```
バイト数 = 入力値 × 単位の大きさ
各単位の値 = バイト数 ÷ その単位の大きさ
```

数値は10の18乗分の1を単位にした整数（BigInt）として持っています。通常の浮動小数点数は、2進数で小数を近似するので、繰り返し換算すると誤差がたまります。それを避けるための作りです。

ただし、表示は小数第18位で切り捨てです。四捨五入ではありません。

## 計算例

数字は、このツールの script.js を node で動かして出した結果です。

**例1: 1TB のSSDは、2進で何GiB か**

1 TB を入れると、GiB の欄は 931.322574615478515625、TiB は 0.909494701772928237 です。GB の欄は 1,000 のまま。10進の1TBは 1,000,000,000,000 B で、1GiB は 1,073,741,824 B なので、割ると約931.3GiB になります。

「容量が足りない」という問い合わせの定番は、これです。減ったのではなく、数え方が違うだけです。

**例2: 512GB、500GB、2TB**

512 GB は 476.837158203125 GiB、500 GB は 465.661287307739257812 GiB、2 TB は 1,862.64514923095703125 GiB でした。

**例3: 境界値。1 GiB と 1 KiB**

1 GiB は 1,073,741,824 B、1.073741824 GB です。2進から10進に直すと、約7.4%大きく見えます。差は単位が上がるほど開き、KiB と KB なら2.4%（1 KiB は 1.024 KB）です。

最小側も見ておきます。1 bit は 0.125 B、8 bit は 1 B でした。1 KiB を TiB に直すと、本当は 0.0000000009313225746154785… ですが、表示は 0.000000000931322574 で切れます。

**例4: 100MB のファイルを100Mbpsで送る**

100 MB を入れると、bit の欄は 800,000,000 bit でした。回線が100Mbps（10⁸ bit/秒）なら、800,000,000 ÷ 100,000,000 で、理論上は8秒です。この最後の割り算は手計算で、ツールがやるのは bit への換算までです。

## よくある間違い

### 1. メーカー表示の「1TB」と、OSの表示を同じ単位だと思う

ストレージの容量表示は10進のTBが一般的です。一方で、OS やツールによっては、2進で計算した値に「TB」「GB」と書くことがあります。Windows のエクスプローラーはその例とされています。GNU coreutils の `df` なら `-h` が1024単位、`-H` が1000単位と、オプションで分かれています。

同じ「GB」の文字でも、基準が違うことがあります。切り分けるときは、まず10進か2進かを聞いてください。

### 2. Mbps と MB/s を同じものとして計算する

回線速度はビット、ファイルの大きさはバイトです。100Mbps は、最大でも12.5MB/s 前後（100 ÷ 8）にしかなりません。8倍の差を見落とすと、「回線が遅い」と思い込みます。

### 3. MB と MiB を混ぜて計算する

100 MB を MiB に直すと 95.367431640625 MiB です。ここを100のまま扱うと、約4.6%ずれます。1つの表計算シートの中で、片方は10進、もう片方は2進で数えていないか、見直してください。

### 4. 小数の誤差は気にしなくていい、と思い込む

ふつうの `Number` で 0.1 + 0.2 を計算すると、0.30000000000000004 になります。このツールは整数で持つので、0.1 B を入れれば 0.1 B と 0.8 bit で返ります。自分で作る換算スクリプトでは、同じ誤差が出ていないか確認したほうがいいです。

## よくある質問

### Q. 1バイトは何ビットですか？
A. 8ビットです。8 bit を入れると 1 B になりました。

### Q. 回線の「Mbps」はどう入れますか？
A. 単位には Mbps がないので、換算したい量を bit か B で入れてください。100 MB なら 800,000,000 bit と出ます。

### Q. マイナスの値は入力できますか？
A. できます。-1 KB を入れると、-1,000 B と -8,000 bit になりました。データ量としては意味を持たないので、差分の計算用です。

### Q. 桁の大きい数や小さい数でも正確ですか？
A. 整数の計算なので、桁が大きくても精度は落ちません。ただし、表示は小数第18位で切り捨てます。0.000000000000000001 B を入れると、KB 以上の欄は 0 になりました。

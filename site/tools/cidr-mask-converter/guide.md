ACL に `255.255.255.0` と書いたら、意図と逆の範囲に効いてしまった。
`/22` のマスクは何だったか、毎回指折り数えている。
`/31` のホスト数は 0 なのか 2 なのか。
CIDR、サブネットマスク、ワイルドカードマスクのどれか1つを入れれば、残り2つとアドレス総数・使用可能ホスト数が出ます。

## 使い方

1. CIDR（例: `24`）、サブネットマスク（例: `255.255.255.0`）、ワイルドカードマスク（例: `0.0.0.255`）のどれか1欄に入力します。初期値は `/24` です。
2. 残り2欄と、結果欄のアドレス総数・使用可能ホスト数が自動で埋まります。どの欄から入れても構いません。
3. CIDR 欄は `/22` のように先頭に `/` を付けても、全角数字でも読みます。
4. ページ下の早見表に、`/0` から `/32` までの33行が並んでいます。

不正な値を入れると、結果欄は「-」になり、理由がエラーとして出ます。

## 仕組み・計算式

CIDR 表記（RFC 4632）の `/n` は、32ビットのマスクの先頭から1が n 個続くことを表します。`/24` なら、1が24個とゼロが8個で `255.255.255.0` です。ワイルドカードマスクは、サブネットマスクのビットを全部反転したものです。`255.255.255.0` の反転が `0.0.0.255` になります。

アドレス総数は 2 の (32 − n) 乗です。使用可能ホスト数は、そこからネットワークアドレスとブロードキャストアドレスの2つを引いた数になります。`/24` なら 256 − 2 = 254 です。

例外が2つあります。`/31` は RFC 3021 の特例で、ポイントツーポイントのリンクに使い、2アドレスとも使えます。`/32` は1台のホストだけを指す表記で、ネットワークとブロードキャストという考え方がありません。このツールは `/32` を1件と表示します。

サブネットマスクとして有効なのは、1が連続したあとにゼロが連続する値だけです。`255.0.255.0` のように途中で切れる値は、このツールではエラーにします。ワイルドカード側は、反転した結果が不連続になるものをエラーにします。

**現場の落とし穴**: Cisco の ACL などで使うワイルドカードマスクは、サブネットマスクの逆です。`255.255.255.0` を ACL にそのまま書くと、意図と違う範囲に効きます。ACL に貼るときは、必ずワイルドカード欄の値を使ってください。

## 計算例

このツールのロジックを node で動かして確かめた結果です。

**例1: CIDR `24`**
サブネットマスクは `255.255.255.0`、ワイルドカードは `0.0.0.255`。アドレス総数は 256、使用可能ホスト数は 254 です。

**例2: サブネットマスク `255.255.252.0`**
CIDR は `/22`、ワイルドカードは `0.0.3.255`。アドレス総数は 1,024、使用可能ホスト数は 1,022 です。

**例3: ワイルドカード `0.0.0.63`**
`/26` に直り、サブネットマスクは `255.255.255.192`。アドレス総数は 64、ホストは 62 です。

**境界値: `/31`、`/32`、`/0`**
`/31` は `255.255.255.254`、アドレス総数 2、ホスト数も 2 で「（/31・RFC 3021、両方とも使用可）」と出ます。`/32` は `255.255.255.255`、ワイルドカードが `0.0.0.0`、ホスト数 1 です。`/0` は `0.0.0.0` と `255.255.255.255` の組で、アドレス総数は 4,294,967,296 件です。

エラーも確認しました。`255.0.255.0` は「不連続なサブネットマスクです」、`33` は「CIDR は 0〜32 の範囲で入力してください」と出ます。ワイルドカードに `255.255.255.0` を入れると、反転した `0.0.0.255` は先頭がゼロなのでエラーになります。

## よくある間違い

**ACL にサブネットマスクを書く。**
`10.1.1.0 255.255.255.0` と書いてしまう、よくある形です。ワイルドカードで書く場面では `10.1.1.0 0.0.0.255` が正解です。装置によってはサブネットマスクの形で受け付けるものもあるので、使う機器の仕様を先に見てください。

**`/31` を「使えない」と決めつける。**
昔の習慣で、ネットワークとブロードキャストの2つを引くと 0 になるからです。`/31` は RFC 3021 のおかげで、ルーター間の接続用に使えます。ただし機器が対応しているかは別問題です。

**ワイルドカードの不連続を「入力ミス」と断言する。**
このツールは不連続のワイルドカードをエラーにします。一方、Cisco の ACL には、`0.0.255.0` のように不連続なワイルドカードを許す使い方もあります。その場合、このツールでは変換できません。意図した設定なら、手で計算してください。正直なところ、私もこの仕様を確認するまで、不連続を全部ミスだと思っていました。

## よくある質問

### Q. ワイルドカードマスクとサブネットマスクはどう違いますか？
ビットが全部反転した関係にあります。サブネットマスクは、ネットワーク部を1で示します。ワイルドカードマスクは、比較しなくてよい部分を1で示します。

### Q. `255.255.0.255` はなぜエラーですか？
1のビットが連続していない不連続マスクで、`/n` の形で表せないからです。

### Q. `/31` と `/32` のホスト数が特殊なのはなぜですか？
`/31` はRFC 3021で2アドレスとも使えます。`/32` は単一ホストを指す書き方で、引き算の対象になるアドレスがありません。

### Q. 早見表はどの範囲ですか？
`/0` から `/32` まで33種類をすべて載せています。

ファイル名に ' が入っていて、コマンドが途中で切れた。
bash で動いたものが PowerShell では動かない。
cmd の ^ とダブルクォートの関係が、いつまでも覚えられない。
このツールは文字列を bash・PowerShell・cmd.exe・JSON・正規表現の書き方に一度で直し、引数のリストからそのまま貼れる1行のコマンドも組み立てます。

## 使い方

1. 上の欄に文字列を入れると、bash、PowerShell、cmd.exe、JSON、正規表現それぞれの表記が並びます。
2. 下の「引数リスト」に、1行1引数でファイル名などを入れます。先頭に付けるコマンドも入れておくと、貼り付けて使える1行になります。
3. 各行の「コピー」ボタンで、結果をクリップボードに取れます。

手順は3つだけですが、結果の見方は少し癖があります。同じ `&` でも、どこで効くのか分かりますか。次の節で、どの欄が何の層に効くのかを整理します。

## 仕組み・計算式

bash のクォートは、bash(1) マニュアルの QUOTING の節と、POSIX の「シェルコマンド言語」のクォートの規則に沿っています。シングルクォートの中は全部リテラルですが、`'` 自体は書けません。そこで `'` の前で一度閉じ、バックスラッシュで逃がした `'` を挟んで、また開きます。`it's` が `'it'\''s'` になるのはこのためです。ダブルクォートの中では `\` `$` `` ` `` `"` の4文字だけがバックスラッシュで逃がせます。

PowerShell は about_Quoting_Rules に従います。シングルクォートの中は `'` を2つ重ねる以外すべてリテラルです。ダブルクォートの中は、エスケープ文字がバッククォートで、`` ` `` `$` `"` を逃がします。

cmd.exe には、性質の違う欄が2つあります。「^ メタ文字エスケープ」は、cmd 自身が解釈する `& | < > ^ ( ) !` の前に `^` を置きます。「Windows引数解析」は、起動されたプログラムが argv を組み立てるときの規則です。Microsoft の C ランタイムの引数解析と CommandLineToArgvW が使う規則で、`"` の直前にあるバックスラッシュを数え、2倍に1本足して逃がします。

JSON は JSON.stringify と同じ結果で、RFC 8259 の文字列の書き方です。正規表現は `. * + ? ^ $ { } ( ) | [ ] \ /` の前にバックスラッシュを付けます。

## 計算例

ツールの変換処理を Node.js で動かして確かめた値です。

**例1: `it's`。** bash のシングルクォートは `'it'\''s'`、PowerShell のシングルクォートは `'it''s'` になります。ダブルクォートなら、bash も PowerShell も `"it's"` のままで足ります。

**例2: `$HOME `date` "x"`。** bash のシングルクォートは `'$HOME `date` "x"'` で、中身は一切変わりません。bash のダブルクォートは `"\$HOME \`date\` \"x\""`、PowerShell のダブルクォートは `` "`$HOME ``date`` `"x`"" `` です。ダブルクォートは逃がす文字が多く、1文字でも漏れると展開されてしまいます。

**例3: 境界値。** 空文字は bash が `''`、PowerShell が `''`、Windows引数解析が `""` で、空の引数として渡せます。末尾が `\` の `C:\Program Files\App\` は、Windows引数解析で `"C:\Program Files\App\\"` になりました。末尾のバックスラッシュが2本になるのは、閉じる `"` を逃がしてしまわないためです。

**引数リストの例。** 先頭に `grep -rn TODO --` を付け、`report 2024.csv`、`data's_backup.txt`、`"quoted name".log` を入れると、bash 用は次の1行です。

`grep -rn TODO -- 'report 2024.csv' 'data'\''s_backup.txt' '"quoted name".log'`

cmd 用は `"report 2024.csv" data's_backup.txt ^"\^"quoted name\^".log^"` です。引用符を含む引数だけ `^` が付きます。

## よくある間違い

**PowerShell のクォートが、外部コマンドにそのまま届くと思う。** 意外だったのは、PowerShell 5.1 で実際に試すと、`node argv.js 'say "hi"'` の argv は `say hi` になり、中のダブルクォートが消えました。`'say \"hi\"'` と書き直すと `say "hi"` で届きます。クォートの規則は PowerShell が文字列を作るまでの話で、その先の exe への渡し方は別の層だからです。PowerShell 7 の新しい版では挙動が違う場合があり、ここでは確かめていません。

**cmd の `^` と引数解析を混ぜる。** `^` は cmd が読む段階、`"` の逃がしは起動されたプログラムが読む段階です。引数リストの cmd 用の1行は、この2段階を両方かけて作ります。まず引数解析の規則で引用符を整え、そのうえで `& | < > ^ ( ) % ! "` を `^` で無効化します。`a&b` は `a^&b` になり、cmd に実際に通して、受け取った側の argv が元の7つの引数と一致するのを確かめました。バッチファイルの中では `%` を `%%` にする必要がありますが、そこはツールでは変えません。

**bash のダブルクォートで `!` を逃がし忘れる。** `!` は対話シェルの履歴展開が有効なときだけ効きます。スクリプトの中では普通の文字ですが、ターミナルに貼ると、`!` の直後に文字が続く場合に `event not found` になることがあります。ツールはこの `!` を変換しません。

## よくある質問

### Q. なぜ JSON と正規表現も同じ画面にあるのですか?
A. ログの検索や API を呼ぶコマンドでは、シェル、JSON、正規表現のクォートが重なります。1つの文字列を3種類に直す場面が多いので、並べて確認できるようにしました。

### Q. PowerShell はシングルとダブル、どちらを使えばいいですか?
A. 変数を展開したくないなら、シングルクォートが安全です。逃がす文字が `'` だけで済みます。変数を埋め込みたいときだけダブルクォートにして、文字としての `$` は `` `$ `` にします。

### Q. スペースを含むファイル名を xargs に渡すと壊れます。
A. 既定では空白で区切られるためです。`find . -print0 | xargs -0 コマンド` のようにNUL区切りにするか、`find . -exec コマンド {} \;` で1件ずつ実行すると、名前が分割されません。

### Q. 日本語の文字も変換されますか?
A. クォートの対象にならないので、そのまま通ります。JSON も、`\u` 形式には直さずそのまま出力されます。

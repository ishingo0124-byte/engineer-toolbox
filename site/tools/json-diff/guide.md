差分ツールに JSON を2つ貼ったら、キーの並びが違うだけで全行が「差分あり」になった。
本当に変わったのは1項目だけのはずなのに、どこか分からない。
API のレスポンスを比べるたびに、目で追って疲れる。
このツールは、2つの JSON を貼るだけで、追加・削除・値変更・型変更を `$.users[2].name` のようなキーのパス単位で一覧にします。

## 使い方

1. 左の欄に JSON A（比較元）、右の欄に JSON B（比較先）を貼ります。入力と同時に、下の表に差分が出ます。
2. 表の各行には、種類（追加・削除・値変更・型変更）と、変更箇所のパス、内容が並びます。「A⇄B を入れ替え」で、比較の向きを逆にできます。
3. 配列の並びが入れ替わっただけなら、「配列の順序を無視して比較」にチェックを入れます。ここまでが基本の操作で、次からは仕組みの話です。
4. どちらかの JSON が壊れていると、その欄の下に構文エラーが出ます。ブラウザが文字位置を返したときは、「4行目 3文字目付近」の形で場所も付きます。

エラーが出ている間は差分の表を出さず、「JSON を修正してください。」とだけ表示します。

## 仕組み・計算式

JSON の文法は ECMA-404 と RFC 8259 が定めています。ECMA-404 はオブジェクトのメンバーの順序に意味を持たせていないので、このツールもキーの並びは見ません。どちらの JSON にそのキーがあるか、あれば値が同じか、の2点だけを比べます。

比べ方は型ごとに決まっています。

- オブジェクトは、キーの和集合を取って、片方にしかないキーを「追加」「削除」にします。両方にあれば、中身を再帰して比べます。
- 配列は、既定ではインデックスが同じ要素どうしを比べます。長さが違うときは、はみ出した分が「追加」か「削除」です。
- 文字列・数値・真偽値は `!==` で比べます。型が違うもの（`null` と数値、文字列 `"1"` と数値 `1` など）は、中身を見ずに「型変更」です。

「順序を無視」をオンにすると、配列は「同じ値がいくつあるか」の集合比較になります。要素がオブジェクトなら、キーを並べ替えたうえで文字列にして同じかを見るので、キーの順番が違うだけの要素は同じ値と数えます。パスは `$.tags[]` のように、番号なしで出ます。

数値はもう1つ注意があります。JSON の数値には整数と小数の区別がなく、JavaScript は64ビット浮動小数点で読みます。`1` と `1.0` はどちらも同じ数値なので、差分にはなりません。ただし、2の53乗（9007199254740992）を超える整数は、読み込んだ時点で丸まります。

## 計算例

script.js の差分ロジックを node で動かして確かめた値です。

**例1:初期表示の2つの JSON。**
A は users に2人（田中の active が false）、count が数値の 2、version が `"1.0"` です。B は田中に role: admin があり、count が文字列の `"2"`、note が追加されています。結果は5件でした。

- 削除 `$.users[1].active` false
- 追加 `$.users[1].role` "admin"
- 型変更 `$.count` number 2 → string "2"
- 削除 `$.version` "1.0"
- 追加 `$.note` "updated"

users の1人目（佐藤）は同じなので出ません。田中の行は、値が変わったのではなく、キーが1つ減って1つ増えた扱いです。

**例2:配列の先頭に要素を足す。**
A の tags が `["a","b","c"]`、B の tags が `["z","a","b","c"]` のとき、既定のインデックス比較では4件出ます。`$.tags[0]` が "a" → "z"、`[1]` が "b" → "a"、`[2]` が "c" → "b"、`[3]` が追加の "c" です。中身は1つ増えただけなのに、全部ずれて見えます。「順序を無視」にすると、`$.tags[]` に追加 "z" の1件だけになりました。

**例3（境界値）:同じ値が重なる配列。**
A の b が `[1,2,2,2]`、B の b が `[2]` で順序を無視すると、削除 `$.b[]` の 1 と、削除 `$.b[]` の 2 ×2 の2行が出ます。2は3個から1個に減ったので、減った2個分が「×2」です。

**数値の例。** `1` と `1.0` を比べても差分は出ません。一方、`9007199254740993` と `9007199254740992` を比べても、差分は「ありません」と出ました。読み込みの時点で同じ数値になるためです。

## よくある間違い

**配列の追加を「全部変わった」と読む。** 例2のように、インデックス比較は先頭への挿入に弱いです。正直なところ、最初にこれを見たときは、ツールが壊れたのかと思いました。個数の増減だけを知りたいなら、「順序を無視」に切り替えてください。ただし、要素の位置が意味を持つデータ（座標の並びなど）では、順序を無視すると本当の変更を見落とします。

**`"1"` と `1` を同じ値だと思う。** 画面上は同じに見えても、文字列と数値は別の型です。API の仕様変更で、数値が文字列に変わることがあります。このツールは「型変更」の行で教えるので、`$.count` のような行が出たら、型を最初に疑ってください。

**ID が大きな整数のとき、一致と出たので安心する。** 2の53乗を超える整数は、ブラウザの `JSON.parse` で丸まります。長い ID を数値で持つデータは、文字列にして比べるのが確実です。この件は、ツールの外で気づくのが難しいところですよね。

## よくある質問

### Q. キーの順序が違うだけでも差分になりますか？
A. なりません。オブジェクトは、どちらにそのキーがあるかと値だけを見ます。入れ子の中でも同じです。

### Q. 配列の要素を先頭に1つ足すと、後ろの要素も全部「値変更」になりますか？
A. 既定のインデックス比較ではそうなります。例2の4件がその形です。個数の増減だけを見たいときは、「順序を無視」を使います。

### Q. 同じキーが2回出てくる JSON はどうなりますか？
A. RFC 8259 では、名前は一意であるべきだ（SHOULD）とされていて、重複したときの挙動は決まっていません。このツールはブラウザの `JSON.parse` を使うので、通常は後に書いたほうだけが残ります。エラーは出ません。

### Q. 末尾のカンマや、コメント入りの JSON は比べられますか？
A. 比べられません。どちらも JSON の仕様にないので、貼った時点で構文エラーになります。`NaN` や `undefined` も同じです。数万行規模の大きな JSON は試していないので、動作は保証できません。

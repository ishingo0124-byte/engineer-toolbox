新しいサービスに登録するたびに、パスワードを考えるのが面倒になる。
記号は使えるのか、何文字まで通るのか、登録画面で毎回迷う。
電話で読み上げるとき、0とOと1とlで聞き返された。
このツールは、長さと文字種を指定して、暗号用の乱数で作ったパスワードを5個まとめて出します。紛らわしい文字を除く設定と、使う記号を絞る設定もあります。

## 使い方

1. スライダーで長さ（8〜64文字）を決め、使う文字種（英大文字・英小文字・数字・記号）にチェックを入れます。初期状態は16文字で、4種類すべてオンです。
2. 手入力や電話での読み合わせがありそうなら、「紛らわしい文字を除外する」をオンのままにします。0・O・1・l・I・| の6文字が候補から消えます。
3. 登録先が使える記号を限っているときは、「記号セット」の欄に使いたい記号だけを入れます。空欄なら `!@#$%^&*()-_=+[]{};:,.<>/?` の26文字から選びます。
4. 5個の候補が並ぶので、気に入ったものの「コピー」を押します。

設定を変えると、その場で5個が作り直されます。ボタンの「5個生成しなおす」は、同じ設定のまま引き直したいときに使います。

## 仕組み・計算式

乱数は `Math.random()` ではなく、Web Crypto API の `crypto.getRandomValues()` から取っています。`Math.random()` は ECMAScript の仕様で品質が定められておらず、秘密の値には使えません。

文字を選ぶときに「乱数を文字数で割った余り」を使うと、範囲の端の文字が少しだけ出やすくなります（剰余バイアス）。このツールは、2の32乗を文字数で割り切れる範囲の外に落ちた値を捨てて引き直す方式（棄却法）で、偏りを避けています。選んだ文字種ごとに最低1文字を入れてから、残りを全文字種の混合から引き、最後に並べ替えを行います。並べ替えも同じ乱数を使います。

画面に出る「理論エントロピーの目安」は、`長さ × log2(使える文字の数)` です。使える文字が83種類で16文字なら、16 × log2(83) = 約102.0 bit になります。各文字種を最低1文字入れる制約の分だけ、実際は数字よりわずかに小さくなります。

パスワードの考え方は NIST SP 800-63B（デジタル認証のガイドライン）に沿っています。同ガイドラインは、記号を必ず混ぜるといった構成の規則や、定期的な強制変更を求めず、長さを確保する方向です。

## 計算例

ツールのロジックを node で動かして確かめた値です。パスワード本体は毎回変わるので、決まって出るのは文字数と bit の表示です。

**例1:初期設定（16文字・4種類・紛らわしい文字を除外）。** 使える文字は83種類（大文字24・小文字25・数字8・記号26）で、表示は約102.0 bit でした。

**例2:同じ設定で、除外をオフにした場合。** 文字は88種類に増え、約103.4 bit です。除外で失うのは1.4 bit ほどでした。読み間違いが減ることを考えると、安い代償だと思います。

**例3:8文字、英小文字と数字だけ（除外オン）。** 25 + 8 で33種類、約40.4 bit です。同じ16文字の英数字だけ（57種類）だと約93.3 bit、20文字にすると約116.7 bit になりました。

**例4:20文字で、記号セットを `!@#-_.` の6文字に絞った場合。** 24 + 25 + 8 + 6 で63種類、約119.5 bit です。

**境界値:64文字で4種類すべて。** 約408.0 bit と表示されます。記号セットを `|` だけにして除外をオンにすると、記号の文字が残らず、文字種が0個になるため、エラーが出ます。数字だけを選んだ16文字は、使える文字が8種類（2〜9）なので48.0 bit でした。

## よくある間違い

**表示された bit 数を「破られない保証」と受け取る。** あの数字は、攻撃者が全く情報を持たない前提の理論値です。ここが落とし穴です。生成した文字列の末尾に「!」や年号を足すと、その分の強さは崩れます。

**登録先ごとに使い回す。** 強いパスワードを1つ作って、あちこちに流用しても、どこか1か所から漏れた時点で全部が危うくなります。今使っているパスワードは、いくつのサービスで共通でしょうか。サービスごとに別のものを作り、パスワードマネージャーに入れておく運用が現実的です。

**記号を絞りすぎる。** 記号が使えないサービスに合わせて、記号のチェックを外したとします。同じ16文字でも、約102.0 bit が約93.3 bit に下がりました。減った分は、長さを2〜3文字足せば取り戻せます。

**共有するとき、そのままチャットに貼る。** 画面共有やチャットに平文で残るので、共有が必要ならパスワードマネージャーの共有機能など、平文が残らない手段にします。

## よくある質問

### Q. 生成したパスワードは、どこかに保存されますか？
A. いいえ。生成も表示もブラウザ内だけで完結していて、どこにも送っていません。ページを閉じれば消えます。控えるのは自分の役目なので、パスワードマネージャーに入れるのを忘れないでください。

### Q. すべての文字種のチェックを外すとどうなりますか？
A. 「文字種を1つ以上選んでください」というエラーが出て、生成しません。除外の設定の結果、文字が残らない組み合わせも同じエラーになります。

### Q. 5個の中から選ぶのは、強さに影響しますか？
A. 5個から1つを選ぶのは、2.3 bit（log2 5）ほどの絞り込みです。覚えやすそうなものを選ぶくらいなら、実用上は気にならない差です。ただ、「気に入るまで引き直す」を繰り返すと、人の好みという偏りが入ってきます。

### Q. スライダーの最小値が8文字なのはなぜですか？
A. 8文字だと、4種類を選んでも約50 bit 台にとどまります。実際に使うなら、12〜16文字以上をおすすめします。下限の8は、古いシステムが8文字までしか通さない場合のために残しています。

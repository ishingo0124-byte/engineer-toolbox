## 使い方

1. 上の「UTC±hh:mm の時刻 → 日本時間」で、UTCオフセットを選び、時刻を `2:00` や `14:30` の形で入れます。
2. 結果は「日本時間 18:00（同日）」のように出ます。日付がまたぐときは「翌日」「前日」と表示されます。

ここまでが、UTCオフセットから日本時間へ向かう順方向の使い方です。

3. 逆に日本時間から調べるなら、「日本時間 → 任意のUTCオフセット」に日本時間を入れ、変換先を選びます。
4. 下の「代表都市の現在のオフセット」では、日付を変えると、ロサンゼルスやパリが夏時間かどうかが切り替わります。

最後の手順まで、入力はその場で結果に反映されます。UTC自体の時刻を知りたいときは、オフセットに `UTC+00:00` を選べば足ります。

一覧表には30分刻み（+05:30 のインドなど）と45分刻み（+05:45 のネパールなど）も入れてあります。

## 仕組み・計算式

UTC（協定世界時）は、世界の時刻の基準です。各地の時刻は「UTC + オフセット」で表し、日本標準時（JST）は UTC+09:00 です。オフセットの書き方（`+09:00`、`-07:00`）は ISO 8601 の日付・時刻の表記と、インターネットの時刻表記を定めた RFC 3339 に出てきます。

計算式は、時刻を分に直して足し引きするだけです。

```
日本時間（分） = 現地時刻（分） − 現地のオフセット（分） + 540
```

540 は JST の 9 時間を分にした数です。たとえば UTC-07:00 の 2:00 なら、2:00 − (−7:00) + 9:00 で、18:00 になります。結果が 24:00 を超えたら翌日、0:00 を下回ったら前日です。

地域とオフセットの対応表は、IANA Time Zone Database（tz database）が、世界中のOSやブラウザの元データになっています。「America/Los_Angeles」のような名前で、過去から現在までの夏時間の切り替えを記録しています。ブラウザの Intl.DateTimeFormat は、この名前を渡すとその日のオフセットを返してくれます。ツールの都市表は、この仕組みで判定しています。

夏時間は、国や地域が制度を持つ限りで、標準時のオフセットが1時間（ロード・ハウ島のように30分）進みます。開始と終了の日付は国ごとに違い、年によって制度が変わることもあります。一覧表の夏時間の欄は、確信の持てる代表例だけを載せました。

## 計算例

ツールの計算ロジックを手元の node で動かして確かめた値です。

**例1：UTC-07:00 の 2:00。** 日本時間は 18:00（同日）です。日本はこの地域より16時間進んでいます。逆に日本時間の 11:00 は、UTC-07:00 の 19:00（前日）になりました。

**例2：UTC の 2:00 と 11:00。** `UTC+00:00` の 2:00 は日本時間の 11:00（同日）、UTC の 11:00 は日本時間の 20:00（同日）です。「UTC 11時」を調べに来た方は、この足し算9時間で足ります。

**例3：UTC+05:45 の 9:15。** ネパールの 9:15 は、日本時間の 12:30 になりました。45分刻みの地域でも、分に直せば同じ式です。

**境界の例。** UTC-12:00 の 23:30 は日本時間の 20:30（翌日）、UTC+14:00 の 0:30 は日本時間の 19:30（前日）でした。日本とは、最大で21時間遅れと5時間進みの幅があります。

**夏時間の例。** 2026年10月8日と1月15日で代表都市を見ると、ロサンゼルスは UTC-07:00（夏時間中）から UTC-08:00（標準時）に切り替わりました。フェニックスは両方の日で UTC-07:00 のままです。アリゾナ州は夏時間を使わないからです。

## よくある間違い

**UTC-7 と書いてあるだけで、地域が決まると思う。** UTC-7 は、冬のデンバー（山岳標準時 MST）と、夏のロサンゼルス（太平洋夏時間 PDT）のどちらにも当てはまります。オフセットは「その時点の数字」で、都市名の代わりにはなりません。会議の案内に UTC-7 とだけあったら、どの都市の予定か分かりますか？ 都市名と、夏時間を含むかを確認してください。

**POSIX の `TZ` や `Etc/GMT+7` の符号を、そのまま読む。** 「GMT+7」と書いてあるのに、実際は UTC-07:00 です。IANA の `Etc/GMT+7` や、POSIX の `TZ=UTC+7` は、符号が逆になっています。「西がプラス」という決まりのためです。Linux の `date` や設定ファイルで見かけるので、正直なところ、ここが一番ひっかかりやすいと感じます。

**夏時間の切り替えを、毎年同じ日だと思う。** 国ごとに日付が違い、制度そのものの廃止も起こります。メキシコシティやブラジルは夏時間をやめました。「去年はこの時期ずれていたから今年も」と考えるより、日付を指定して調べ直すのが確実です。

## よくある質問

### Q. UTC-7 とは何ですか？
A. UTC より7時間遅い時刻帯です。日本（UTC+09:00）との差は16時間で、UTC-07:00 の 2:00 は日本時間の 18:00 です。代表例は、冬のデンバーとフェニックス、夏のロサンゼルスでした。

### Q. UTC+4 はどこの時間ですか？
A. ドバイなどが当てはまります。日本より5時間遅く、UTC+04:00 の 12:00 は日本時間の 17:00 です。この地域に夏時間はありません。

### Q. 夏時間があるのは何時から何時までですか？
A. 国ごとに違うため、一律には言えません。ツールの都市表では、日付を入れるとその日が夏時間中かどうかを判定します。アメリカ、ヨーロッパ、オーストラリアなどは制度があり、日本は実施していません。

### Q. 30分や45分ずれた地域はありますか？
A. あります。インドは UTC+05:30、ネパールは UTC+05:45、オーストラリアのアデレードは標準時が UTC+09:30 です。一覧表に載せてあります。

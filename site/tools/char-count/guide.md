応募フォームの「400字以内」に収まっているはずなのに、貼り付けたらエラーになった。
スペースと改行は数えるのか、全角と半角はどう扱われるのか、判断がつかない。
文章を貼るだけで、改行や空白を除いた文字数、行数、UTF-8 と Shift_JIS 換算のバイト数、原稿用紙換算までまとめて表示します。

## 使い方

1. 上の欄に文章を貼り付けます。入力と同時に数えるので、ボタンを押す必要はありません。
2. 提出先の数え方に合う行を見ます。改行込みなら「文字数（すべて）」、改行だけ除くなら「文字数（改行を除く）」、スペースも抜くなら「文字数（改行・空白を除く）」です。
3. 文字数ではなくバイト数の上限があるときは、「バイト数（UTF-8）」か「バイト数（Shift_JIS 換算）」を見ます。

手順は以上です。ただ、最初に迷うのは「どの行を信じるか」だと思います。提出先の募集要項やシステム仕様に「空白を含む」「改行を含まない」といった一文があれば、それに合う行を選んでください。書いていないときは、先方に確認するのが確実です。

## 仕組み・計算式

このツールは、見た目の1文字（書記素クラスタ）を1文字と数えます。分割にはブラウザの `Intl.Segmenter`（ECMA-402）を使っています。書記素の境界は Unicode 標準附属書 UAX #29 の規則に沿ったものです。たとえば「か」に結合文字の濁点（U+3099）を続けた2コードポイントは、見た目が「が」1文字なので1と数えます。

バイト数は2種類あります。UTF-8 は RFC 3629 の形式で、`TextEncoder` が実際にエンコードした長さをそのまま出しています。ASCII は1バイト、ひらがな・カタカナ・漢字の大半は3バイト、絵文字は4バイトです。「コードポイント」の数は括弧の中に併記します。

Shift_JIS 換算は概算です。コードポイントごとに、ASCII と半角カナ（U+FF61〜U+FF9F）を1バイト、それ以外をすべて2バイトとして足しています。JIS X 0201 の1バイト文字と JIS X 0208 の2バイト文字の区別を、そのまま簡略化した形です。実際の Shift_JIS に無い文字（絵文字など）も2バイトとして数えるので、旧システムの帳票や固定長ファイルの「当たりを付ける」ために使ってください。

そのほかの欄は次のとおりです。

- 行数: 改行（`\n` または `\r\n`）で区切った数。空欄は0行です。
- 段落数: 空行（空白だけの行を含む）で区切った数。前後の空白は無視します。
- 単語数: 英数字・アンダースコア・アポストロフィ・ハイフンの連続を1語とします。日本語の分かち書きはしないので、日本語の文では単語数になりません。
- 原稿用紙換算: 改行を除いた文字数を 400 で割り、小数第2位で丸めます。

ここまでが数え方のルールで、細かい差が出るのは次の計算例です。

## 計算例

数字は、このツールの script.js と同じ処理を node で実行して確かめた値です。

**例1: 初期表示の2行**

「サーバーの設定変更は、必ずバックアップを取ってから行う。」と「特に /etc 配下は、変更前後の diff を残しておくと後で助かる。」を2行で入れた場合です。

| 欄 | 値 |
|---|---|
| 文字数（すべて） | 65 |
| 文字数（改行を除く） | 64 |
| 文字数（改行・空白を除く） | 60 |
| 行数 | 2 |
| 単語数 | 2（etc と diff） |
| UTF-8 | 169 バイト |
| Shift_JIS 換算 | 117 バイト |
| 原稿用紙 | 0.16 枚 |

空白を除くと4文字減ります（2行目の半角スペース4つ）。改行は1つなので、「すべて」と「改行を除く」の差は1です。

**例2: 日本語と英語が混ざる「Hello 世界」**

すべて8文字、空白を除いて7文字です。UTF-8 は 12 バイトで、内訳は「Hello」の5バイトと空白の1バイト、「世界」の6バイトです。Shift_JIS 換算は 10 バイトでした。同じ8文字でも、数え方で 12 と 10 に分かれます。

**例3: 境界値。家族の絵文字 1 つ**

👨‍👩‍👧‍👦 を1つだけ入れると、文字数は 1、UTF-8 の欄は「25（コードポイント 7）」になります。人・人・子・子の4つの絵文字を、ZWJ（ゼロ幅接合子）3つがつないだ並びだからです。見た目は1文字でも、データとしては25バイトを使います。

画面の1文字を「何バイトか」と聞かれたら、答えが1から25まで動く例です。

## よくある間違い

### 1. 改行コードの違いを見落とす

Windows のアプリは改行を `CRLF`（2バイト）で、Linux や Mac は `LF`（1バイト）で保存することが多いです。「a」と「b」の間に改行を入れて試すと、`LF` なら UTF-8 は 3 バイト、`CRLF` なら 4 バイトでした。文字数は、どちらも3です。このツールは `CRLF` も1つの改行として扱うためです。

バイト数の上限があるシステムで「1行だけ長さが合わない」ときは、まず改行コードを疑ってください。

### 2. 末尾の改行が行数を1つ増やす

「あ」のあとに改行を1つ入れただけで、行数は2になります。文字数（改行を除く）は1のままです。末尾の改行が貼り付けに紛れ込んでいると、行数の上限に1行足りなくなることがあります。気づきにくい落とし穴です。

### 3. 原稿用紙の「枚数」を端数まで信じる

400字ちょうどなら 1 枚と出ます。では401字ならどうでしょう。計算は 401 ÷ 400 = 1.0025 を小数第2位で丸めるので、表示は「1 枚」のままです。意外だったのは、1文字はみ出しても表示が変わらないことでした。実際の原稿用紙では、2枚目に1文字はみ出します。

枚数を提出条件に使うときは、必ず切り上げで考えてください。段落の頭を1マス空ける、改行で行が余るなどの理由で、実際の枚数はこの欄より多くなるのが普通です。

### 4. Shift_JIS 換算を正確な値だと思う

この欄は半角と全角の区別だけの簡易計算です。たとえば💩のような Shift_JIS に無い文字も、2バイトとして数えます。文字コード変換でどうなるかは、変換ソフトや環境で変わります。正確な値が必要なら、実際に変換したファイルの大きさを見てください。

## よくある質問

### Q. 原稿用紙換算はどう計算していますか？
A. 改行を除いた文字数（空白は含む）を 400 で割って、小数第2位で丸めています。100字なら 0.25 枚と表示されました。

### Q. 空白は全角スペースも除かれますか？
A. 除かれます。「改行・空白を除く」は、半角スペース、タブ、全角スペース（U+3000）などをまとめて取ります。「a b　c\td」と入力すると、すべてで7文字、空白を除いて4文字でした。

### Q. 絵文字や結合文字は何文字ですか？
A. 見た目で数えます。「か」に結合の濁点を付けた形は、コードポイントでは2つでも1文字です。コードポイントを知りたいときは、UTF-8 の欄の括弧の中を見てください。

### Q. 入力した文章は保存されますか？
A. 処理はブラウザの中だけで行い、サーバーには送りません。ページを閉じれば消えます。

`0 0 1 * MON` と書いたのに、月初の月曜だけでなく毎週月曜に動いていた。
`*/15` は結局、何時何分に動くのか。
次に走るのが明日なのか来週なのか、書いた本人も自信がない。
5フィールドの cron 式を入れると、日本語での意味と次回実行日時が5回分出ます。日と曜日を両方指定したときの OR 条件も、その場で確かめられます。

## 使い方

1. 上の欄に「分 時 日 月 曜日」の順で、空白区切りの5フィールドを入力します。初期値は `15 3 * * *`（毎日 3:15）です。
2. 入力するたびに、日本語の説明と次回実行日時（最大5回）が更新されます。全角数字や全角スペースも半角に直して読みます。
3. 式を覚えていないときは、下のセレクトで分・時・日・月・曜日を選び、「生成した式を上に反映」を押します。
4. エラーが出たときは、赤い文字にどのフィールドのどの値が悪いかが書いてあります。

ここまでが基本で、実際に使うときは次回実行日時の欄が一番役に立ちます。式の意味より先に「いつ走るか」を目で見て確かめられるからです。

次回実行日時はブラウザのローカル時刻で、現在時刻の1分後から1年先までを探します。1年以内に一致がなければ、その旨が表示されます。

## 仕組み・計算式

書式の元になっているのは POSIX の crontab の仕様と、Linux で広く使われる Vixie cron 系の crontab(5) の man ページです。各フィールドには、`*`（すべての値）、単一の値（`5`）、範囲（`1-5`）、列挙（`1,15`）、ステップ（`*/10` や `0-30/10`）が使えます。これらは組み合わせられます。ステップは範囲の開始値から数えるので、分の `*/15` は 0・15・30・45 分です。

フィールドごとの有効範囲は、分が 0〜59、時が 0〜23、日が 1〜31、月が 1〜12、曜日が 0〜7 です。曜日の 0 と 7 はどちらも日曜日として扱います。月は `JAN`〜`DEC`、曜日は `SUN`〜`SAT` の英字でも書けます。

次回実行日時は、1分ずつ時刻を進めながら「月・日（または曜日）・時・分」がすべて条件に合うかを調べて求めています。計算の中身はこれだけです。

**現場の落とし穴**: 「日」と「曜日」を両方とも `*` 以外にすると、AND ではなく OR になります。POSIX の crontab の仕様にも crontab(5) にも書かれている挙動です。`0 0 1 * MON` は「毎月1日」と「毎週月曜」のどちらかに合う日に走ります。月初の月曜だけにしたいなら、cron の式では書けません。スクリプトの先頭で `date` を使って日付を判定します。

どちらか一方が `*` のときは、もう一方だけで絞り込まれます。OR になるのは両方指定したときだけです。

## 計算例

次回実行日時は現在時刻で変わるので、2026年11月13日（金）10:00 の時点で、このツールのロジックを node で動かした結果を載せます。

**例1: `15 3 * * *`**
説明は「毎日 3時15分 に実行」。次回は 2026/11/14（土） 03:15、11/15、11/16 と続きます。10:00 の時点では今日の 3:15 は過ぎているので、今日は数えません。

**例2: `*/15 * * * *`**
説明は「毎日 毎時 0・15・30・45分 に実行」。次回は 10:15、10:30、10:45、11:00、11:15 です。

**例3: `0 9 * * 1-5`**
平日の 9:00 です。次回は 11/16（月）から 11/20（金）まで5回並びます。金曜の今日は 9:00 を過ぎているため、来週の月曜が最初です。

**境界値: `0 0 1 * MON`**
次回は 11/16（月）、11/23（月）、11/30（月）、12/01（火）、12/07（月）の順に出ました。12/01 は火曜日ですが、「1日」に一致するので入ります。月曜だけの式と思っていると、ここで驚きます。

**存在しない日: `0 0 30 2 *`**
2月30日はないので、「1年以内に条件を満たす日時が見つかりませんでした」と出ます。`0 0 31 * *` は 12/31、1/31、3/31、5/31 と、31日がある月だけを飛び飛びに拾います。

## よくある間違い

**月初の月曜日を `0 0 1 * MON` と書く。**
上の境界値のとおり、毎週月曜と毎月1日の和集合になります。日と曜日の両方を指定するときは、まず次回実行日時を見てください。意図と違う日が混じっていれば気づけます。

**`*/n` を「n 回ごとに割り切れる」と思い込む。**
`*/7` を分に使うと、0・7・14・21・28・35・42・49・56 分に動きます。56 分の次は 60 分ではなく、次の時間の 0 分です。間隔が 4 分しかない箇所ができます。7 分おきに動かしたいなら、cron ではなくタイマー側で組むほうが確実です。

**曜日の 0 と 7 や、1 始まりの数え方を取り違える。**
このツールは 0 も 7 も日曜として表示します。月曜は 1 です。数字で書いて自信がなければ `MON` のような英字にすると読み間違えません。正直なところ、私は曜日を数字で書くたびに日曜始まりかどうか迷います。

## よくある質問

### Q. 秒単位の指定はできますか？
標準の cron は分が最小です。秒を加えた6フィールド形式は Quartz などジョブスケジューラの拡張で、このツールは5フィールドだけを扱います。6個入れると「フィールドは「分 時 日 月 曜日」の5個が必要です（入力は 6 個）」とエラーになります。

### Q. 次回実行日時が実際の cron の動きとずれました。
このツールはブラウザのローカル時刻で計算します。サーバーの cron はサーバー側のタイムゾーン設定に従うので、日本から海外のサーバーを見るとずれます。ずれていないかは、サーバー側で `date` を打って確かめてください。

### Q. 夏時間の切り替え日はどうなりますか？
このツールは夏時間の切り替えを考慮した検証をしていません。夏時間のある地域のサーバーで、切り替え時刻付近に走らせる式は、実機で確かめてください。

### Q. 「1年以内に見つかりません」と出たら間違いですか？
式が文法的に正しくても、2月30日のように存在しない日付だと出ます。日と月の組み合わせを見直します。

tar のオプション、毎回「czvf だっけ、xzvf だっけ」と迷う。
展開したら余計なフォルダが1階層増えた。
zip と tar.gz の書き方も、頭の中でごちゃ混ぜになる。
このツールは、操作と形式と対象パスを選ぶだけで tar や zip / unzip のコマンドを1行に組み、中身を確かめる一覧コマンドも並べて出します。

## 使い方

1. 「操作」で作成・展開・一覧のどれかを、「形式」で tar.gz・tar.bz2・tar.xz・tar・zip のどれかを選びます。
2. アーカイブのファイル名と、対象パス（1行に1つ）、除外パターン（1行に1つ）を入れます。
3. 展開のときは、展開先ディレクトリと strip-components も指定できます。
4. 「コマンドをコピー」で貼り付けて実行します。下の確認コマンドで、中身を一覧で見られます。

形式は、ファイル名の拡張子ではなく「形式」の選択で決まります。ファイル名を `backup.tar.gz` にしても、形式が tar.bz2 のままなら、コマンドは bzip2 用の `-j` で出ます。

## 仕組み・計算式

tar(1) では、動作を決める `c`（作成）・`x`（展開）・`t`（一覧）は排他的で、1回に1つしか指定できません。圧縮は GNU tar の `z`（gzip）・`j`（bzip2）・`J`（xz）で指定します。無圧縮なら付けません。

短いオプションを `-czvf` のようにまとめるとき、`f` は直後にアーカイブ名を取ります。そのため `f` は最後に置きます。このツールは `f` を常に末尾にして出力します。

`--exclude=パターン` と `--strip-components=N`（先頭 N 階層を取り除く）は、GNU tar の拡張オプションです。`-C ディレクトリ` は、展開先を切り替えます。

zip は Info-ZIP の zip(1) と unzip(1) の書き方です。`zip -r` でディレクトリの中身まで含め、`-x` で除外します。`unzip -d` が展開先、`unzip -l` が一覧です。

zip には `--strip-components` に相当するオプションがありません。ツールで zip を選んでから strip-components に数字を入れると、「反映されません」という注記が出ます。

## 計算例

次のコマンドは、script.js と同じ処理を node で実行して出力を確かめたものです。tar や zip そのものを、実際に動かしたわけではありません。

**例1: src/ と README.md を、ログと .git を除いて tar.gz にする。** 初期状態のまま、次の1行が出ました。

```
tar -czvf backup.tar.gz --exclude='*.log' --exclude=.git src/ README.md
```

確認コマンドは `tar -tzvf backup.tar.gz` です。`*.log` は、シェルに展開されないよう引用符が付きます。

**例2: project-v1.2.3.tar.gz を /opt/app に展開し、先頭1階層を除く。** 操作を「展開」にして、対象パスと除外を空にし、展開先に `/opt/app`、strip-components に `1` を入れました。

```
tar -xzvf project-v1.2.3.tar.gz -C /opt/app --strip-components=1
```

アーカイブの中身が `project-v1.2.3/src/main.c` の形なら、`/opt/app/src/main.c` に置かれる想定です。

**例3: zip で作成する。** 形式を zip にしてアーカイブ名を `site.zip` にすると、次の1行でした。

```
zip -r site.zip src/ README.md -x '*.log' .git
```

**境界値: 一覧の xz と、対象パスが空の作成。** 操作を「一覧」、形式を tar.xz にして `data.tar.xz` を入れると、`tar -tJvf data.tar.xz` が出ます。ここでは大文字の `J` です。一方、作成で対象パスを空にすると、コマンドは出ますが、「作成する対象パスを1つ以上入力してください」というエラーが同時に出ました。

## よくある間違い

**f を途中に置く。** `-fzxv` のように書くと、`f` の次の文字がファイル名として読まれます。自分で組むときは、`-czvf archive.tar.gz` の形で、`f` と名前を隣に並べると覚えやすいです。

**tar の c・x・t を混ぜる。** `-cxf` のように2つ指定すると、エラーになります。作ったつもりが展開コマンドだった、ということも起こります。意図した動作かどうかは、実行前に先頭の文字で確認してください。

**拡張子と圧縮形式がずれる。** `backup.tar.gz` という名前で bzip2 圧縮したアーカイブを作っても、ファイルは作れてしまいます。名前だけ見て展開コマンドを選ぶと、失敗します。ツールの「形式」とファイル名の拡張子は、自分で合わせます。

**zip の除外が効いていない。** ツールは `-x` の後ろに入力したパターンをそのまま並べます。`.git` のようにディレクトリ名だけ書いて、中身が除外されなかった経験はありませんか？ zip のパターンはパス全体に対して照合されるので、ディレクトリの中身を除くなら `.git/*` のように書きます。この点は Info-ZIP の zip(1) の説明に基づくもので、今回の確認では実際には zip を実行していません。

もう1点あります。Windows で作った日本語ファイル名の zip を Linux の unzip で開くと、文字化けすることがあります。逆も同じです。

## よくある質問

### Q. strip-components は、どんなときに使いますか？
A. アーカイブが `project-v1.2.3/` のような親ディレクトリを1つ含んでいて、その階層を取り除いて展開したいときです。例2のように `1` を入れると、先頭の1階層が除かれます。

### Q. 展開先（-C）は、事前に作る必要がありますか？
A. GNU tar の `-C` は、既にあるディレクトリに移動するだけです。作ってはくれないので、先に `mkdir` しておくと安全です。ツールの注記にも、事前作成が必要と出ます。

### Q. tar.gz と zip は、どちらを使えばよいですか？
A. Linux や macOS の間でやり取りするなら、パーミッションを保ちやすい tar 系が定番です。Windows の相手には、標準機能で開ける zip が楽です。正直なところ、相手の環境が分からないときは、先に聞くのが一番早いです。

### Q. 権限を保持する（-p）は、どこに付きますか？
A. tar の展開のときだけ付きます。bzip2 の展開にチェックを入れると、`tar -xjvpf a.tar.bz2` の形になりました。zip では専用のオプションを出さず、説明だけが出ます。

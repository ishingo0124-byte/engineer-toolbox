## 使い方

1. 操作（作成・展開・一覧）と形式（tar.gz / tar.bz2 / tar.xz / tar / zip）を選ぶ。
2. アーカイブ名、対象パス、除外パターンを入力すると tar または zip/unzip のコマンドが自動生成される。
3. 展開時は展開先ディレクトリや strip-components（tar限定）も指定できる。
4. 併記される「確認コマンド」でアーカイブの中身を一覧表示して結果を確認できる。

## 仕組み・計算式

tar(1) の仕様では、動作モードを決める `c`（create）・`x`（extract）・`t`（list）は互いに排他的で1回につき1つしか指定できない。短いオプションをまとめる慣習（`-czvf`）では、`f` がアーカイブファイル名という引数を直後に取る唯一の文字のため必ず末尾に置く必要があり、途中に置くと次の文字列をファイル名と誤認識してエラーになる。圧縮形式は `z`(gzip)・`j`(bzip2)・`J`(xz) で指定し、無圧縮なら付けない。`--exclude=パターン` と `--strip-components=N`（先頭N階層を除去）は GNU tar の拡張オプション（tar(1)）。zip は info-zip の zip(1)/unzip(1) の仕様上、格納ファイル名の文字コードが作成環境によって異なり、古い実装との組み合わせで日本語ファイル名が文字化けすることがある。

**現場の落とし穴**:c/x/t を1コマンドに複数指定する間違いはエラーの典型例。`-zxvf` のように f を最後に置く慣習を崩すと直後の文字列がファイル名と誤認識される。作成・展開後は一覧コマンドで中身を確認する習慣をつけると事故を防ぎやすい。

## よくある質問

### Q. strip-components はどんなときに使いますか？
A. アーカイブ内が `project-v1.2.3/src/main.c` のように余分な親ディレクトリを含む場合、その階層を除いて展開したいときに使う。`--strip-components=1` で先頭の `project-v1.2.3/` が取り除かれる。

### Q. tar.gz と zip はどちらを使うべきですか？
A. Linux/macOS間ではUnixパーミッションやシンボリックリンクを扱いやすいtar系が一般的。Windows環境とやり取りするならOS標準で展開できるzipが扱いやすい。

### Q. 展開先ディレクトリ（-C）は事前に作成が必要ですか？
A. tarの-Cは既存ディレクトリへの移動のみでディレクトリ自体は作成しない実装が一般的なため、事前にmkdirしておくのが安全。

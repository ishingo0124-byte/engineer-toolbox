貼り付けた一覧から、重複だけ消したい。
空行と余計な空白も、まとめて片付けたい。
file10 が file2 より前に来るのも、そろそろ直したい。
行ごとのテキストを、並べ替え・重複削除・空行削除・トリムまで一度に整えるツールです。結果はコピーして使えます。

## 使い方

1. テキストエリアに、1行1項目でデータを貼り付けます（ファイル名、ログの一部、ID の一覧など）。
2. 「並べ替え」で、そのまま、昇順、降順、自然順、数値順、シャッフルから選びます。
3. トリム、空行削除、重複削除、出現回数、順序反転、行番号のチェックボックスを組み合わせます。

設定を変えるたびに結果が更新されるので、ボタンを押す必要はありません。

4. 「コピー」を押すと、処理結果をそのままコピーできます。

画面の上には「入力 8 行 → 処理後 5 行（3 行削除、うち重複削除 2 行）」のような件数が出ます。

## 仕組み・根拠

処理の順番は固定で、「前後の空白をトリム、空行を削除、並べ替え、重複削除、順序反転、行番号付与」です。重複削除は、POSIX の uniq コマンドと同じ仕様で、隣り合う同一行だけを1つにまとめます。出現回数（uniq -c 相当）も、同じ行が続いた回数です。

- 昇順・降順: JavaScript の文字列比較、つまり UTF-16 の文字コード順です。
- 自然順: 数字の連なりを数値として比べます。file2 が file10 より前になり、GNU sort の -V（バージョンソート）に近い考え方です。
数値順だけは、行全体ではなく先頭の数値を見ます。

- 数値順: 各行の先頭から読める数値（parseFloat）で比べます。読めない行は、昇順でも降順でも末尾です。

シェルの sort は、ロケール設定によって並びが変わります。文字コード順にそろえたいときは、LC_ALL=C を付けて実行するのが定番です。このツールの昇順は、その文字コード順に近いものです。

行番号と出現回数を両方オンにすると、出現回数、行番号、本文の順に並びます。

## 計算例

ツールの script.js をそのまま node で動かして確かめた値です。

**例1: 初期入力のまま（自然順、トリム、空行削除、重複削除がオン）。** 入力の8行は、file10.txt、file2.txt、「  banana」、apple、banana、apple、空行、file1.txt です。結果は apple、banana、file1.txt、file2.txt、file10.txt の5行でした。空行1つと重複2つが消えています。「昇順（文字コード順）」に替えると、file1.txt、file10.txt、file2.txt の順になります。意外だったのは、自然順をやめるだけで file10 が file2 より前に来ることでした。

**例2: 出現回数。** b、a、b、a、c、b の6行を、昇順で重複削除と出現回数をオンにして処理します。結果は「   2 a」「   3 b」「   1 c」でした。表示は4桁の右揃えで、GNU の uniq -c の桁数とは違います。

**例3: 並べ替えなしの重複削除（境界）。** 同じ6行を「そのまま」で処理すると、6行のまま1行も減りません。b、a、b、a と、同じ行が隣り合っていないからです。

**例4: 数値順。** 10、9、-3、abc、2.5、空行、1e2、10 を数値昇順にすると、-3、2.5、9、10、1e2、abc でした。1e2 は100として扱われ、abc は末尾です。10は2つが隣り合って1つになります。

## よくある間違い

**sort を通さずに uniq だけを使う。** 離れた位置の同じ行は消えません。このツールも同じ仕様です。全部の重複を消したいなら、並べ替えをオンにしてから重複削除を使ってください。

**大文字小文字を無視すれば重複も消えると思う。** 「並べ替え時に大文字小文字を無視」は並べ替えだけに効きます。Banana、apple、Cherry、apple、Apple を、昇順と大文字小文字無視で処理すると、apple、Apple、Banana、Cherry になりました。apple と Apple は別の行のままです。

**全角と半角を同じものとして並べる。** 昇順は文字コード順なので、A、a、あ、ア、ｱ の順になります。実際、辞書の並びとは違いますよね。人に見せる一覧なら、別の方法で確認してください。

**トリムをオフにして重複を探す。** 「 a」と「a」は別の行です。末尾にスペースが付いた行も別扱いです。重複が消えないときは、トリムがオンか見てください。

## よくある質問

### Q. 重複削除をしても行数が減りません。
A. 隣り合う同じ行だけが対象だからです。並べ替えを「そのまま」にしていると、離れた同じ行は残ります。並べ替えをオンにしてから、もう一度試してください。

### Q. 数値順で、数字でない行はどこに行きますか？
A. 昇順でも降順でも、末尾にまとまります。例4の abc がそうでした。

### Q. 全体の重複を、順番を保ったまま消せますか？
A. このツールではできません。重複削除は隣り合う行だけを見るため、元の順を保つ全体の重複除去は対象外です。

### Q. 出力に Windows の改行コードは残りますか？
A. 残りません。CRLF と CR は入力時に LF に直しています。出力は LF で、末尾の空行も消えます（空行削除がオンの場合）。

rsync のオプション、-avz までは覚えているが、その先が出てこない。
送信元の末尾に `/` を付けるかどうかで、毎回不安になる。
--delete を付けたいけれど、本番で消したくない。
このツールは、送信元・宛先とオプションを選ぶだけで rsync コマンドを1行に組み、各オプションの意味と、末尾スラッシュの効き方も画面に出します。

## 使い方

1. 送信元と宛先を入れます。ローカルのパスでも、`user@host:path` の形でも構いません。
2. 基本オプション（-a・-v・-z・-h・-P・-n・--delete）のチェックを、必要なものに合わせます。
3. 除外したいものは --exclude 欄、除外から外したいものは --include 欄に、1行に1つずつ書きます。
4. SSH のポートを変えるなら SSH ポート欄、速度を絞るなら --bwlimit 欄に数字を入れます。

操作はここまでです。送信元の欄の下には、末尾の `/` の有無でコピーのされ方がどう変わるかが、その場で出ます。

実行する前に、まず -n（--dry-run）を付けて試してください。特に --delete を使うときは、これを飛ばさないほうが安全です。

## 仕組み・計算式

rsync(1) では、`-a`（archive）は `-rlptgoD` をまとめて指定したものと同じです。再帰、シンボリックリンク、パーミッション、更新時刻、グループ、所有者、デバイスファイルを保ちます。バックアップ用途では、まず `-a` から始めるのが定番です。

`--exclude` と `--include` は、どちらも rsync のフィルタルールです。ルールは書いた順に調べられ、最初に一致したものが適用されます。ツールは、`--include` を `--exclude` より前に並べて出力します。

送信元の末尾の `/` は、rsync(1) の説明でも触れられている挙動です。`dir/` なら中身が宛先の直下にコピーされ、`dir` なら `dir` というディレクトリ自体が宛先の中に作られます。宛先の末尾の `/` は、結果に影響しません。

`-P` は `--partial --progress` の略で、中断したファイルの再開と進捗の表示を行います。`-n` は `--dry-run` で、実際には転送も削除もしません。`--bwlimit` の数字は、既定ではキロバイト毎秒です。

SSH のポートを変えるときは、`-e 'ssh -p 2222'` の形で、ssh を起動するコマンドごと渡します。ツールもこの形で出力します。

## 計算例

次のコマンドは、script.js と同じ処理を node で実行して確かめました。rsync を実際に動かして、転送結果を確かめたものではありません。

**例1: 初期状態。** 次の1行が出ました。

```
rsync -avh --exclude=.git/ --exclude='*.tmp' --exclude=node_modules/ ./local/dir/ user@remote.example.com:/var/backup/dir/
```

`*.tmp` には引用符が付きます。シェルがファイル名として展開してしまうのを防ぐためです。

**例2: 本番前の確認。** 例1に -n と --delete のチェックを足すと、次のようになりました。

```
rsync -avhn --delete --exclude=.git/ --exclude='*.tmp' --exclude=node_modules/ ./local/dir/ user@remote.example.com:/var/backup/dir/
```

-n は、`-avhn` のように一文字オプションにまとまります。--delete を付けると、画面に削除への注意書きが出ました。

**例3: SSH ポート、帯域制限、圧縮、進捗表示。** SSH ポートに 2222、--bwlimit に 5000 を入れ、-z と -P にもチェックを入れると、こうなります。

```
rsync -avzhP --exclude=.git/ --exclude='*.tmp' --exclude=node_modules/ -e 'ssh -p 2222' --bwlimit=5000 ./local/dir/ user@remote.example.com:/var/backup/dir/
```

**境界値: 送信元の末尾スラッシュ。** 送信元を `./local/dir/` から `./local/dir` に変えると、コマンドの違いは送信元の末尾の1文字だけです。ただし、ツールの説明は「中身だけが直下にコピーされる」から「ディレクトリ自体が宛先の中にコピーされる」に変わりました。たった1文字で、宛先の構造が変わります。

**空欄の扱い。** 送信元と宛先を両方空にすると、`rsync -avh --exclude=... . .` が出ます。意図せず出たコマンドをそのまま貼ると、カレントディレクトリ同士になります。

## よくある間違い

**末尾スラッシュを付け忘れる。** `/home/me/site` を `/var/www/` へ送ると、`/var/www/site/` ができます。中身だけがほしかったなら、送信元を `/home/me/site/` にします。コピー後に、宛先に同名のディレクトリが増えていないかを見てください。

**--delete を、送信元を確かめずに付ける。** 送信元のパスを間違えたまま --delete を付けると、宛先のファイルが、送信元に無いものとして大量に消えます。確かめる手順は単純です。-n と --delete を両方付けて実行し、出力の `deleting` で始まる行を眺めます。正直なところ、この一手間を省いた経験がある人は、少なくないと思います。

**--include を --exclude の後ろに書く。** 先に一致したルールが勝つので、順番が逆だと、復活させたかったものが除外されたままになります。ツールは常に --include を前に出すので、手で書き足すときに順番を崩さないよう注意してください。

もう1点、ディレクトリだけ残して中身を除くような指定では、親ディレクトリ側の --include も必要です。たとえば `logs/keep/` を残して `logs/*` を除くなら、`--include=logs/keep/` を先に、`--exclude='logs/*'` を後に置きます。

## よくある質問

### Q. -z（圧縮）は、常に付けたほうがよいですか？
A. 付けなくても構いません。遅い回線や、圧縮がよく効くテキストなら効果があります。圧縮済みの画像や動画、速い LAN の中では、CPU を使うだけで速くならないことがあります。

### Q. --exclude で除外したものを、一部だけ戻すには？
A. --include 欄に戻したいパターンを入れます。ツールが --exclude より前に並べるので、順番を気にせず使えます。ただし、親ディレクトリが除外されていると、その中身には届かないので、親側も --include に入れてください。

### Q. SSH の秘密鍵も、指定できますか？
A. このツールには、鍵を指定する欄がありません。出力された `-e 'ssh -p 2222'` の中に、`-i ~/.ssh/id_ed25519` のような ssh のオプションを手で書き足す形になります。引用符の中に収めてください。

### Q. ポートや --bwlimit に、数字以外を入れるとどうなりますか？
A. 「SSH ポートは数字で入力してください」「--bwlimit は数字（KB/s）で入力してください」というエラーが出て、その部分はコマンドに入りません。他のオプションは出力されます。

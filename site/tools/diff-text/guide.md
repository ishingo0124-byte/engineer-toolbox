設定ファイルのどこを変えたのか、目で追っていると見落とす。
差分を貼りたいのに、git に入れるほどのものでもない。
このツールは、2つのテキストを行単位で比べて追加・削除・変更を色分けし、変更行は文字単位でも強調します。そのまま貼れる unified diff 形式のテキストもコピーできます。

## 使い方

1. 「テキストA（変更前）」と「テキストB（変更後）」に、比べたい文章を貼ります。
2. 入力すると、すぐに行単位の差分が出ます。赤が削除、緑が追加です。一部だけ変わった行は、変わった文字がさらに濃く光ります。
3. 必要なら「空白を無視」「大文字小文字を無視」を切り替えます。判定が変わるだけで、表示は元の文字のままです。
4. 下の unified diff 形式のテキストは、「コピー」ボタンでそのまま取れます。

差分の上には「追加・削除・変更・一致」の行数も出ます。入力はブラウザの中だけで処理され、送信されません。

## 仕組み・計算式

行単位の差分には、Eugene W. Myers が1986年に発表した「An O(ND) Difference Algorithm and Its Variations」の方法を使っています。2つの行の列から、挿入と削除の回数が最小になる経路を探し、そこから差分を組み立てます。変更行の文字単位のハイライトも、同じ方法を文字の列に当てはめています。

出力の書式は、GNU diffutils のマニュアルにある unified format に沿っています。ヘッダは `--- a` と `+++ b`、塊の先頭は `@@ -旧開始,旧行数 +新開始,新行数 @@` です。前後の文脈は3行で、これは GNU diff の `-u` の初期値と同じです。近い変更は1つの塊にまとめ、離れていれば塊を分けます。

異なる点もあります。GNU diff は、範囲が1行だけの塊で `,1` を省きます。このツールは、いつも `,行数` を付けます。タイムスタンプも付けません。

行の数え方は、改行コードを `\n` にそろえ、末尾の改行1つ分を行数に入れません。差分が極端に大きいときは、計算量の上限に達して、共通の先頭と末尾だけを見つける簡易表示に切り替わります。

## 計算例

ツールの計算ロジックを手元で動かして確かめた値です。

**例1:初期値の nginx 設定。** 追加が1行、削除が0行、変更が3行、一致が3行でした。unified diff の塊は `@@ -1,6 +1,7 @@` です。文字単位では、`listen 80;` の「80」が「443 ssl」に、`server_name` の行では「 www.example.com」が、`index` の行では「 index.htm」が足されたと出ます。`gzip on;` の行は丸ごと追加です。

**例2:離れた変更。** 20行のテキストの2行目と19行目だけを書き換えると、塊は `@@ -1,5 +1,5 @@` と `@@ -16,5 +16,5 @@` の2つに分かれました。変更と変更の間に挟まる変更なしの行が6行以内なら、1つの塊にまとまりました。7行あると、塊が分かれます。

**例3(境界値):空のテキストと末尾の改行。** Aが空でBが2行なら、塊は `@@ -0,0 +1,2 @@` です。`"a\nb\n"` と `"a\nb"` は、同じ2行として扱われ、「差分はありません」と出ました。

行の並べ替えも試しました。`a, b, c` を `c, a, b` に変えると、追加1行と削除1行です。`c, b, a` にすると、追加2行と削除2行でした。

## よくある間違い

**「空白を無視」で空行の有無も無視されると思う。** 無視されるのは、行の中の空白だけです。`a`、空行、`b` と `a`、`b` を比べると、空白を無視にしても、削除1行の差分が残りました。

**空白を無視したまま、unified diff をコピーしてしまう。** 空白だけが違う行は「一致」になるので、unified diff には出ません。インデントが意味を持つ YAML や Makefile のタブでは、変更を見落とします。パッチとして渡す前に、チェックを外して見直してください。ここを一番気にしています。

**改行コードや末尾の改行の違いを、差分として期待する。** CRLF と LF の違いは、このツールでは同じ行です。実際の `git diff` は、末尾に改行があるかどうかを区別して `\ No newline at end of file` と注記します。CI で意図しない差分が出たときは、本物の diff コマンドも併用してください。

## よくある質問

### Q. 行の順番が入れ替わっただけなのに、削除と追加になります。
A. この方法は、並びが一致する行を探すので、移動を「移動」としては表せません。動いた行は、削除と追加の組み合わせで出ます。`git diff` の標準の挙動も同じです。

### Q. 「空白を無視」は、タブとスペースの違いも無視しますか？
A. 無視します。行の中の空白文字をすべて取り除いてから比べるので、`a b` と `ab` も同じ行です。単語の間の空白が意味を持つ文では、使い方に気をつけてください。

### Q. 数万行でも使えますか？
A. 動きますが、差分の量が多いほど計算が重くなります。差が大きすぎると、簡易表示に自動で切り替わり、精度より応答の速さを優先します。

### Q. 文字単位のハイライトは、すべての変更行に出ますか？
A. 削除と追加の行が対になった変更行だけに出ます。行が丸ごと追加または削除された場合は、行全体が色づくだけです。対になる2行の文字数の合計が4,000を超えるときも、文字単位は省略します。

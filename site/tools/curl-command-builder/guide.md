API を試したいだけなのに、curl の引用符でいつも詰まる。
JSON を送ったはずが、PowerShell ではなぜか届かない。
-X は付けるべきなのか、付けなくていいのか。
メソッド・URL・ヘッダー・ボディ・認証・タイムアウトを選ぶと、bash、PowerShell、cmd それぞれの引用符に合わせた curl コマンドを組み立てて、コピーまでできます。

## 使い方

1. 「メソッド」と「URL」を入れます。ヘッダーは「Name: value」の形で1行に1つ書きます。
2. 「ボディの形式」を選んで、ボディを書きます。JSON、フォーム、multipart、そのままの文字列から選べます。
3. 認証は Basic（-u）か Bearer を選びます。必要ならタイムアウトの秒数と、-L や -v などのオプションにチェックを入れます。
4. 最後に「シェル」を選びます。これが一番大事な選択です。
5. 下に出たコマンドをコピーして、貼り付けます。

シェルを切り替えても、変わるのは引用符とエスケープの部分だけで、入力はそのままです。自分のシェルを選び間違えて、貼ったコマンドが動かなかった経験はありませんか？ 入力した値はこのページの中だけで処理し、外には送信しません。

## 仕組み・計算式

オプション名は curl の公式マニュアル（curl man page）に沿っています。-X（--request）はメソッド、-H（--header）はヘッダー、-d（--data）はボディ、-u（--user）は Basic 認証、-I（--head）は HEAD、-L（--location）はリダイレクト追従、-k（--insecure）は証明書の検証省略です。タイムアウトは --max-time（全体）と --connect-timeout（接続）で、単位は秒です。

-d を付けると、curl は既定で POST にし、Content-Type は application/x-www-form-urlencoded になります。ツールはこの性質を使い、POST でボディがあるときは -X を省いています。GET にボディを付けたり、PUT・PATCH・DELETE にしたりする場合だけ -X を出します。HEAD は、-X HEAD ではなく -I を出します。

--json は curl 7.82.0 以降のオプションで、POST で JSON を送り、Content-Type と Accept に application/json を付けます。古い curl では使えないので、チェックを入れたときだけ出力します。

HTTP のメソッドやヘッダー名の規則は RFC 9110（HTTP Semantics）です。Basic 認証は RFC 7617 で、ユーザー名に : を含められません。Bearer トークンは RFC 6750 です。

シェルごとの引用符は次のとおりです。

- bash / zsh: 単一引用符で囲み、中の ' は '\'' に置き換えます。
- PowerShell: 単一引用符で囲み、中の ' は '' と重ねます。コマンド名は curl.exe にします。
- cmd: 二重引用符で囲み、中の " は \" にします。

PowerShell には、Windows PowerShell 5.1 で内側の二重引用符が落ちるという落とし穴があります。詳しくは次の計算例に書きました。

## 計算例

手元の簡易サーバー（届いたメソッド・ヘッダー・ボディを記録するだけのもの）に向けて、生成したコマンドを実際に実行して確かめました。curl は 8.22.0（Windows）、シェルは Git Bash、Windows PowerShell 5.1、cmd です。PowerShell 7 系では動かしていません。

**例1: JSON に ' や & を含む POST。** ボディは `{"name": "Taro", "note": "it's ok & <b> | ^ (x)"}`、認証は Bearer です。出力に -X はなく、`-d` に JSON が入りました。bash では `it'\''s ok`、PowerShell 5.1 では `it''s ok`、cmd では `it's ok`（& や < などは ^ で守られます）という出力です。3つのシェルとも、サーバーに届いたボディは入力と同じ文字列でした。

**例2: JSON を --json で PUT（境界値）。** ボディ `{"a":"b"}`、メソッド PUT のとき、出力に `-X PUT` と `--json` が並びます。Windows PowerShell 5.1 向けの出力は `'{\"a\":\"b\"}'` で、サーバーには `{"a":"b"}` が届きました。同じ JSON を「PowerShell 7.3 以降」向けの出力（`'{"a":"b"}'`）のまま Windows PowerShell 5.1 で実行すると、届いたのは `{a:b}` でした。意外だったのは、エラーにならず、黙って中身が変わることです。

**例3: Basic 認証でパスワードに ' と " と & を含む。** ユーザー名 alice、パスワード `p'w "q" &x` を入れました。bash の出力は `-u 'alice:p'\''w "q" &x'` で、PowerShell は `-u 'alice:p''w "q" &x'` です。サーバーが受け取った Authorization ヘッダーを戻すと、alice:p'w "q" &x でした。

あと、メソッドが DELETE でボディなしのときは `-X DELETE` が出て、届いたメソッドも DELETE でした。

## よくある間違い

**PowerShell で curl とだけ打つ。** Windows PowerShell 5.1 では、curl は Invoke-WebRequest の別名です。手元で Get-Alias curl を打つと、そう表示されました。オプションの意味が違うため、curl.exe と書く必要があります。ツールは PowerShell のときだけ curl.exe で出力します。

**-X POST と -d を両方付ける、または -X HEAD を使う。** -d だけで POST になるので、-X POST は余計です。-X HEAD はサーバーの応答を待つ状態になることがあり、curl の公式マニュアルにも注意書きがあります。HEAD は -I を使ってください。

**cmd で単一引用符を使う。** bash の癖で 'text' と書くと、cmd では引用符がそのまま値に入ります。cmd は二重引用符で囲む決まりです。JSON の中に二重引用符があるときは \" にします。

## よくある質問

### Q. -d と --json はどちらを使えばいいですか？
A. curl 7.82.0 以降なら --json が短く書けます。それより古い curl や、手元の curl のバージョンが分からないときは、-d と Content-Type ヘッダーの組み合わせが安全です。ツールの既定は後者です。

### Q. cmd で、複数行の JSON を送るには？
A. cmd は値の途中の改行を扱えません。「JSON を1行に整える」にチェックを入れるか、JSON をファイルに保存して -d @ファイル名 で読み込んでください。

### Q. -L と -X を一緒に付けると、何が起きますか？
A. -X で指定したメソッドが、リダイレクト先にも使われます。POST が 301 や 302 で別の URL に飛ぶと、本来メソッドが変わる場面でも変わりません。ツールは、この組み合わせのときに注意を表示します。

### Q. パスワードやトークンをコマンドに書いて大丈夫ですか？
A. シェルの履歴やプロセス一覧に残ることがあります。共有端末や、履歴を保存する設定のときは、避けるほうが無難です。ツールの入力欄に書いた値は、ページの外には送られません。

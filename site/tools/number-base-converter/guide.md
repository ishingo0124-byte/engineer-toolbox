0xFF って、符号つきだと結局いくつだったか。
-1 を 16進で書くと、8bit と 32bit で桁数が変わるのが毎回ややこしい。
AND や シフトの結果も、2進で並べて目で確かめたい。
2進・8進・10進・16進を相互に変換し、負数は 8/16/32/64bit の2の補数で表示します。下半分はビット演算の電卓です。

## 使い方

1. 10進・16進・8進・2進のどれかの欄に値を入れます。入力と同時に、ほかの3つの欄と下の結果欄が更新されます。
2. 負数を扱うなら、まず「ビット幅」を選びます。初期値は 8bit です。
3. 「入力欄の解釈」は、符号ありと符号なしから選びます。16進などの欄に `ff` と入れたとき、-1 と読むか 255 と読むかがここで決まります。
4. 先頭に `-`、または `0x` `0b` `0o` を付けると、その書き方が優先されます。全角の数字やマイナスも使えます。

手順の2と3が、この種のツールで一番つまずくところです。

5. 下の「ビット演算電卓」では、A と B（NOT とシフトでは B は使いません）、演算、シフト量を入れます。結果は16進・2進・符号なし10進・符号あり10進で出ます。

## 仕組み・計算式

nビットの2の補数では、負数 v のビットパターンは「(2^n + v) を 2^n で割った余り」です。8bit の -1 なら 256 − 1 = 255、つまり `ff` です。逆に、最上位ビットが1のパターンは、2^n を引いて負数に読み替えます。8bit の `80` は 128 − 256 = -128 です。

値は JavaScript の BigInt で保持しています。ECMAScript の言語仕様（ECMA-262）では、BigInt のビット演算子（`&` `|` `^` `~` `<<` `>>`）は無限桁の2の補数として定義されています。そこで、選んだ幅のマスク（2^n − 1）と AND するだけで、n ビットのパターンが得られます。64bit を超える整数も、桁を落とさずに扱えます。

右シフトは2種類あります。算術右シフト（`>>`）は符号ビットを保ちます。論理右シフト（`>>>`）は、幅の中で上位に 0 を詰めます。電卓はどちらも選べます。

現場の落とし穴は、ツールの入力解釈にあります。10進欄に 255 と入れると 255 のままです。ところが16進欄に ff と入れると、符号ありの初期設定では -1 になります。意外だったのは、同じ値のつもりで入れた2つが別の数になることでした。引っかかりませんか？

符号なし前提のバイト列を貼るときは、先に「符号なし」へ切り替えてください。

## 計算例

数字はすべて、このツールの script.js を node で実行して得た値です。画面の表示と同じ値になります。

**例1: 8bit で -1**

10進欄に -1 を入れると、16進は `ff`、2進は `1111 1111`、8進は `377`、符号なし10進は 255、立っているビットは 0〜7 でした。同じ -1 を 32bit にすると `ff ff ff ff`（符号なし 4294967295）、16bit の -2 なら `ff fe`（符号なし 65534）です。

**例2: 符号ありと符号なし**

16進欄に `80` を入れます。符号ありなら10進欄は -128、符号なしなら 128 になります。ビットパターンはどちらも `1000 0000` です。同じ並びを、どう読むかだけが違います。

**例3: ビット演算**

A = 12、B = 10、8bit で次のとおりでした。

| 演算 | 結果（2進） | 符号なし | 符号あり |
|---|---|---|---|
| AND | 0000 1000 | 8 | 8 |
| OR | 0000 1110 | 14 | 14 |
| XOR | 0000 0110 | 6 | 6 |
| NOT（A のみ） | 1111 0011 | 243 | -13 |

シフトは A = -8 で、1ビットずらします。算術右シフトは `1111 1100`（-4）、論理右シフトは `0111 1100`（124）、左シフトは `1111 0000`（-16）になりました。

**例4: 境界値**

8bit で -128 を入れると `80` です。-200 は8bit に収まらないので、2の補数にはならず、符号＋絶対値の `-c8`（2進で `-1100 1000`）で表示され、その理由の注記が出ました。幅を 16bit に変えると `ff38` で表示されます。

1 を 7ビット左シフトすると `80`（符号ありで -128）、8ビットなら `00` です。幅いっぱいずらすと、全ビットが消えます。

## よくある間違い

### 1. 符号なしのつもりで貼ったのに、負数になる

16進で `80` 以上の1バイトを貼ったら、-128 以下で表示されて驚く。符号ありの初期設定のままだと起きます。ネットワークのバイト列や unsigned char の値を見るときは、「符号なし」に切り替えてください。

### 2. 有効ビット数を、使われている幅だと思う

「有効ビット数」は、符号を除いた絶対値の桁数です。8bit の -1 は 1 bit と出ます。2の補数で 8bit 全部が使われていることを示す数字ではありません。幅を知りたいときは、2進の表示を見るほうが確実です。

### 3. 負数を直接入れて、2の補数が出ると思う

16進欄に `-ff` と入れると、-255 という符号＋絶対値として扱われ、8bit には収まりません。ビットパターンが見たいなら、符号なしの `ff` を符号ありの状態で入れるか、10進欄に -1 と入れてください。

### 4. NOT の結果を、符号なしでしか読まない

~12 は、8bit では `1111 0011` です。符号なしで読めば 243、符号ありで読めば -13 です。C の `~` と比べるときは、変数の型が符号つきかどうかを先に確認してください。

## よくある質問

### Q. 64bit より大きい値は扱えますか？
A. 10進で 18446744073709551615 を入れて 64bit にすると、`ff` が8つ並びました。64bit を超える値は桁を落とさず変換できますが、2の補数で表示できる幅は 8/16/32/64bit までです。

### Q. 接頭辞は、どの欄でも使えますか？
A. 使えます。10進欄に `0xFF` と入れると、16進として読まれて 255 になりました。接頭辞があるときは、2の補数としての読み替えは行われません。

### Q. 8進が3桁なのはなぜですか？
A. 8bit を表すのに必要な8進の桁数が3桁（ceil(8/3)）だからです。-1 で `377` と出ます。

### Q. ビット演算電卓の A に 16進を入れたいときは？
A. `0xFF` のように接頭辞を付けます。付けなければ10進として読まれます。

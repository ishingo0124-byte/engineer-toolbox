ルーターの画面はコロン、Windows はハイフン、Cisco はドット。
同じ MAC アドレスなのに、貼るたびに書き換えている。
ACL に登録する一覧が、大文字と小文字でばらばらになった。
このツールは、MAC アドレスを1行に1つずつ貼ると、コロン・ハイフン・Cisco ドット・区切りなしの表記へ一括変換し、ユニキャスト/マルチキャストとローカル管理の判定、EUI-64 のインターフェース ID も出します。

## 使い方

1. MAC アドレスを1行に1つ入力します。コロン、ハイフン、ドット、区切りなし、空白区切りのどれでも、大文字小文字が混ざっていても構いません。全角の英数字も半角に直して読みます。
2. 各行について、コロン（小文字・大文字）、ハイフン（小文字・大文字）、Cisco ドット、区切りなしの6形式が表に並びます。
3. 同じ行の「種別」と「EUI-64」の列で、先頭バイトの意味と、IPv6 のインターフェース ID を確認できます。

読み取れない行は表に出さず、まとめて赤字で知らせます。

4. 手元の一覧に貼り付けるときは、表のセルを選んでコピーします。

## 仕組み・計算式

MAC アドレスは48ビット、つまり6バイトです。区切り文字を取り除いて、16進数の12桁になれば受け付けます。12桁にならない入力は、エラー行として扱います。

先頭バイトの下位2ビットに意味があります。IEEE 802 の規格で、次のように決められています。

- 最下位ビット（I/G ビット）が0ならユニキャスト、1ならマルチキャストです。`ff:ff:ff:ff:ff:ff` はブロードキャストです。
- 下から2番目のビット（U/L ビット）が0なら、製造元が割り当てたユニバーサル管理アドレス（UAA）です。1ならローカル管理アドレス（LAA）で、ソフトウェアや仮想化基盤が割り当てます。

下位2ビットだけの話なので、先頭バイトが `00`・`01`・`02`・`03` かどうかで、判定結果が変わります。

EUI-64 は、RFC 4291（IPv6 Addressing Architecture）の付録で定義された Modified EUI-64 です。手順は2つです。MAC の3バイト目と4バイト目の間に `ff:fe` を挟んで64ビットにします。そのあと、先頭バイトの U/L ビットを反転します。この反転があるので、`00:1a:2b:3c:4d:5e` の先頭の `00` は `02` になります。

## 計算例

数字はすべて、このツールと同じロジックを node で動かして確かめました。

**例1: 初期表示の `00:1A:2B:3C:4D:5E`。** コロン小文字は `00:1a:2b:3c:4d:5e`、ハイフン大文字は `00-1A-2B-3C-4D-5E`、Cisco ドットは `001a.2b3c.4d5e` です。種別は「ユニキャスト / ユニバーサル管理(UAA)」で、EUI-64 は `021a:2bff:fe3c:4d5e` になります。IPv6 のリンクローカルアドレスに直すと、`fe80::21a:2bff:fe3c:4d5e` です。

**例2: `0050.5601.0203`（ドット区切り）。** コロン小文字は `00:50:56:01:02:03`、区切りなしは `005056010203` です。EUI-64 は `0250:56ff:fe01:0203`。この `00:50:56` は VMware の仮想 NIC でよく見る先頭3バイトです。ただし、このツールはベンダー名を調べないので、画面には出ません。

**例3: `02:42:ac:11:00:02`（Docker の既定のブリッジで見かける形）。** 先頭の `02` は U/L ビットが1です。種別は「ユニキャスト / ローカル管理(LAA)」になりました。EUI-64 は先頭が `00` に戻り、`0042:acff:fe11:0002` です。

**境界値。** `01:00:5e:00:00:fb` は先頭バイトの最下位ビットが1なので、「マルチキャスト / ユニバーサル管理(UAA)」です。`ff:ff:ff:ff:ff:ff` は「マルチキャスト（ブロードキャスト）」と出ます。`00-00-00-00-00-00` は「ユニキャスト（全ビット0）」で、EUI-64 は `0200:00ff:fe00:0000` です。`01:00:5e` のように6バイトに足りない入力、`5g` のように16進数ではない文字を含む入力は、エラー行になります。

## よくある間違い

**ブロードキャストが「ローカル管理」と出て驚く。** `ff:ff:ff:ff:ff:ff` は全ビットが1なので、U/L ビットも1です。ツールはビットをそのまま読むため、「ブロードキャスト / ローカル管理(LAA)」と表示します。実際の機器が書き換えたという意味ではありません。

**ローカル管理アドレスを不正な機器と決めつける。** 仮想マシンやコンテナ、スマートフォンの Wi-Fi 用のランダム MAC は、ローカル管理ビットが立っているのがふつうです。ネットワーク上で見慣れない LAA を見たとき、すぐ疑う前に、仮想化基盤やスマホの設定を確認してみませんか。

**EUI-64 を、いま使っているアドレスだと思い込む。** 最近の OS は、MAC から作る固定の ID ではなく、ランダムなインターフェース ID を使うことがあります（RFC 7217、RFC 8981）。表の EUI-64 は、MAC から導ける値の計算結果です。実機の IPv6 アドレスと一致するとは限りません。

正直なところ、EUI-64 の先頭バイトが `00` から `02` に変わる理由は、初めて見たときに戸惑う人が多いと思います。U/L ビットを反転するのがその理由です。

## よくある質問

### Q. 区切り文字がそろっていなくても変換できますか？
A. できます。コロン、ハイフン、ドット、空白をすべて取り除いてから、12桁の16進数かどうかを調べます。`00:1a-2b.3c 4d5e` のように混ざっていても、桁が合えば読み取れます。

### Q. 6バイトに足りない入力はどうなりますか？
A. 12桁の16進数にならないので、読み取れない行として画面上部に列挙されます。`0x` のような接頭辞も、同じ扱いです。

### Q. ベンダー名は表示されませんか？
A. 表示しません。OUI のデータベースは大きく、更新も必要です。オフラインで完結する方針のため、内蔵していません。

### Q. 大文字と小文字、どちらを使うべきですか？
A. 意味は同じです。ただ、機器や OS が出力する形式に合わせるのが、あとで検索したり比較したりするときに楽です。一覧を作るなら、小文字のコロン区切りか、大文字のハイフン区切りのどちらかにそろえておくと、grep や差分で見落としにくくなります。

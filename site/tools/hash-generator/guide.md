ダウンロードしたファイルが、配布元と同じものか確かめたい。
手元のコマンドと、サイトの表示が合わない。
同じ文字列なのに、ハッシュ値だけが違う。
テキストとファイルから MD5・SHA-1・SHA-256・SHA-512 を同時に計算します。処理はすべてブラウザの中で完結します。

## 使い方

1. テキスト欄に文字列を入れると、4種類のハッシュが入力と同時に更新されます。初期値は `Hello, World!` です。
2. 「大文字（A-F）で表示」で、16進の表記だけを切り替えます。値そのものは変わりません。
3. ファイルのハッシュは「ファイルを選択」から、1つ選びます。選ぶと、同じ4種類が下の欄に出ます。
4. 各行の「コピー」で、その行の値だけをコピーできます。

配布元が出している値と見比べるときは、まず桁数を確認してください。

5. 桁数は、MD5 が32桁、SHA-1 が40桁、SHA-256 が64桁、SHA-512 が128桁です。16進の1桁は4ビットなので、128ビット、160ビット、256ビット、512ビットに対応します。

## 仕組み・計算式

SHA-1・SHA-256・SHA-512 は、ブラウザ標準の Web Crypto API（`crypto.subtle.digest`）で計算しています。アルゴリズムの定義は、NIST の FIPS 180-4（Secure Hash Standard）です。

MD5 は Web Crypto API が提供していないため、RFC 1321 の手順どおりに JavaScript で実装しています。ページを開いたとき、MD5 の空文字列と "abc"、SHA-256 の "abc" を既知の値と照合する自己チェックも走る作りです。失敗してもコンソールに出るだけで、画面には何も出ません。

文字列は UTF-8 のバイト列にしてからハッシュ関数に渡します。計算するのは文字ではなくバイトです。ですから、改行コードが1つ違えば別の値になります。

衝突（異なる入力が同じハッシュ値になること）については、MD5 の弱点が RFC 6151 に整理されています。SHA-1 にも、実際に衝突が作られた事例があります。その結果、署名や改ざん検知に MD5 と SHA-1 を新しく使うのは避けられています。パスワードの保存については、NIST SP 800-63B が、計算コストを高くした専用の方式を使うよう求めています。

## 計算例

下の値は、このツールの script.js を node で実行して得ました。さらに、node 標準の crypto モジュールの出力と全桁一致することも確かめています。

**例1: `abc`**

- MD5: `900150983cd24fb0d6963f7d28e17f72`
- SHA-256: `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`

MD5 と SHA-256 の `abc` は、仕様書のテストベクタとして有名な値です。実装を疑うときの基準になります。

**例2: 初期表示の `Hello, World!`**

- MD5: `65a8e27d8879283831b664bd8b7f0ad4`
- SHA-1: `0a0a9f2a6772942557ab5355d76af442f8f65e01`
- SHA-256: `dffd6021bb2bd5b0af676290809ec3a53191dd81c7f70a4b28688a362182986f`

**例3: 小さな違いで、まるごと変わる**

末尾に改行を1つ足した `Hello, World!`＋改行の MD5 は `bea8252ff4e80f41719ea13cdf007273` です。例2の `65a8e27d…` とは似ても似つきません。先頭を小文字にした `hello, world!` の MD5 は `3adbbad1791fbae3ec908894c4963870` でした。

**例4: 境界値（空文字）**

テキスト欄を空にした場合の MD5 は `d41d8cd98f00b204e9800998ecf8427e`、SHA-256 は `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` です。空でも、ハッシュ値はきちんと出ます。

日本語も試しました。`あ` の MD5 は `8c0c3027e3cfc3d644caab3847a505b0` で、UTF-8 の3バイトとして計算されています。

## よくある間違い

### 1. 末尾の改行に気づかない

正直なところ、このツールを使う場面で一番多い食い違いはこれだと思います。コマンドラインで `echo Hello, World!` のように文字列を渡すと、末尾に改行が付く環境が多くあります。その状態でハッシュを取れば、例3のように別の値になります。サイトの値と違ったら、まず改行を疑ってください。

### 2. 「見た目は同じ」文字列を同じだと思う

全角と半角のスペース、全角の英数字、行頭や行末の空白は、見た目で区別がつきにくいです。バイトが1つ違えば、ハッシュはまったく別の値になります。コピーしたテキストで合わないときは、いったん貼り付け直して試してみてください。

### 3. MD5 や SHA-1 を、改ざん検知やパスワード保存に使う

ファイルの破損チェックのように、悪意のある相手がいない場面なら、MD5 でも役に立ちます。ところが、攻撃者が相手になる場面では話が変わります。署名や配布物の検証には SHA-256 以上を、パスワードの保存には bcrypt や Argon2 などの専用方式を使ってください。

### 4. 大きなファイルを、そのまま選ぶ

ファイルは全体をメモリに読み込んでから計算します。数百MBを超えるファイルでは、端末によって重くなったり、止まったように見えたりします。進捗バーはありません。「計算中…」の表示が「計算完了」に変わるまで待ってください。

## よくある質問

### Q. 同じテキストなのに、以前と違うハッシュ値になりました。なぜですか？
A. 末尾の改行や全角スペースなど、見えにくい文字の違いが原因のことが多いです。UTF-8 のバイトが1つでも違えば、値は別物になります。

### Q. 入力したテキストやファイルは、サーバーに送られますか？
A. 送られません。計算はブラウザの JavaScript の中だけで行います。画面にも「サーバーに送信していません」と出る作りです。ただし、機密性の高いデータは、自分で管理できる端末でだけ扱ってください。

### Q. どのアルゴリズムを使えばよいですか？
A. 新しく何かを作るなら、SHA-256 か SHA-512 です。MD5 と SHA-1 は、既存の仕組みとの互換性や、破損チェックのような用途にとどめてください。

### Q. 大文字と小文字で、値は変わりますか？
A. 16進の表記が違うだけで、値は同じです。比較するときは、どちらかにそろえてください。

どこまでがサブクエリで、どこからがWHEREなのか。
このツールはSQLを貼るだけで、キーワードの大文字化・改行・インデントをそろえ、1行への圧縮もできます。文字列やコメントの中身は書き換えません。

## 使い方

1. SQLを貼ります。`;` で区切った複数の文も、まとめて整形されます。
2. キーワードの大文字・小文字、インデント幅（1〜8）、カンマの位置（行末か行頭か）を選びます。
3. 選ぶたびに結果が更新されます。
4. ログに貼る用の1行にしたいときは、「1行に圧縮する」にチェックを入れます。
5. 「コピー」で、整形結果をそのままコピーできます。

操作はこれだけです。手順は多く見えますが、最初の貼り付け以外は、気に入るまで設定を切り替えるだけです。

## 仕組み・計算式

これはSQLのパーサではなく、字句を切り出して並べ直す整形ツールです。SQLの文法はISO/IEC 9075が定めていますが、ツールはその文法を解析せず、構文の正しさも調べません。

最初に、文字列（`'...'`、`''` のエスケープを含む）、`--` の行コメント、`/* */` のブロックコメント、引用符つきの名前（`"..."`・`` `...` ``・`[...]`）を、1かたまりとして取り出します。この中身は書き換えません。だから文字列の中に `select` や `--` があっても壊れません。

残りは、単語・数字・記号・かっこに分けます。`SELECT`・`FROM`・`WHERE`・`GROUP BY`・`ORDER BY`・`HAVING`・`LIMIT`・`JOIN` の手前で改行し、`AND`・`OR` は `WHERE` や `ON` の中で改行します。`CASE` は `WHEN`・`ELSE`・`END` を別々の行にします。

かっこの扱いは3種類です。直後が `SELECT` か `WITH` ならサブクエリで、改行して展開します。`CREATE TABLE` の列定義と、`INSERT INTO` の列名は、カンマごとに改行します。それ以外（`count(*)` や `IN (1, 2, 3)`）は折り返しません。この判定は、前後の単語から決める経験則です。

大文字にする単語は、ツールが持つ約70語のリストにあるものだけです。`COUNT` や `SUM` のような関数名は、そのリストにありません。入力のまま残ります。

## 計算例

初期表示のSQLと、いくつかの入力を、ツールのスクリプトをNode.jsで動かして整形しました。

**例1：初期表示（大文字・インデント2・カンマ後置）。** `SELECT u.id,` から始まり、列が1行ずつ並びます。`(select count(*) …)` は括弧の中が `SELECT`・`FROM`・`WHERE` の3行に展開されました。`CASE` は `WHEN … THEN`、`ELSE`、`END AS status_label` の行に分かれ、`FROM users u` の次が `LEFT JOIN profiles p ON p.user_id = u.id` です。`WHERE` の `AND` は、2文字ぶん字下げして次の行に置かれます。最後は `ORDER BY u.name ASC` と `LIMIT 50;` でした。

**例2：カンマ前置・インデント4。** 2列目以降が `    , u.name` のように、行頭にカンマを付けた形になります。字下げの幅は、`CASE` やサブクエリの中でも4になります。

**例3：1行に圧縮。** 例1の入力は、`SELECT u.id, u.name, (SELECT count(*) FROM orders o WHERE …` と、1行でつながって出ます。

**例4：境界値。** インデント幅に 0 を入れると 2 になり、99 を入れると 8 になりました。`select a from t;;` のように `;` が続くと、`SELECT a` / `FROM t;` の後に空行と `;` が残ります。`insert into users (id, name, email) values (1, 'a', 'a@x.com'), (2, 'b', 'b@x.com');` は、列名が1行ずつ、`VALUES` の後は1組ごとに1行になりました。

**例5：日本語の名前。** `select 名前 as 氏名, count(*) from 社員　where 年齢 >= 20 and 部署 = '営業部'`（`社員` の後ろは全角スペース）は、`SELECT 名前 AS 氏名,` / `count(*)` / `FROM 社員` / `WHERE 年齢 >= 20` / `AND 部署 = '営業部'` に分かれました。日本語の列名やテーブル名は、引用符がなくても1つの名前として扱われます。

## よくある間違い

**関数名も大文字になると思う。** `count(*)` や `sum(x)` は、キーワードを大文字にしても `count(*)`、`sum(x)` のまま残ります。大文字にするのは、ツールが持つ単語のリストにあるものだけだからです。正直なところ、`COUNT(*)` までそろえてほしかった点です。社内の書き方をそろえたいときは、関数名だけ手で直してください。

**「1行に圧縮」を、コメントつきのSQLに使う。** `select a -- note` の改行の後に `from t where b=1` が続く入力は、`SELECT a -- note FROM t WHERE b = 1` の1行になります。`--` 以降はすべてコメントなので、`FROM` 以降が実行されません。圧縮の前に、`--` コメントを `/* */` に直すか、消してください。

**ANDとORの優先順位が、見た目で分かると思う。** 読み違えたことはありませんか？ `where a=1 and b=2 or c=3` は、3つの条件が同じ位置にそろって並びます。実際の評価は `AND` が先で、`(a=1 and b=2) or c=3` です。かっこは、自分で付けてください。同じ理由で、`BETWEEN 1 AND 5` の `AND` も改行されて、見た目は条件の区切りに見えます。

## よくある質問

### Q. 文字列の中の `SELECT` や `--` は書き換えられませんか？
A. 書き換えません。文字列とコメントは、最初に丸ごと切り出してから処理します。

### Q. `MERGE` やストアドプロシージャも整形できますか？
A. 向いていません。`merge into t using s on …` は、`merge INTO t USING s ON …` のように、途中で崩れた結果になりました。主な対象は、`SELECT`・`INSERT`・`UPDATE`・`DELETE`・`CREATE TABLE`・`JOIN`・サブクエリ・`CASE`・`WITH` です。

### Q. `IN (1, 2, 3)` が改行されないのはなぜですか？
A. かっこの中が `SELECT` で始まらなければ、折り返さない仕様だからです。長いリストでも1行のままです。

### Q. 整形したSQLをそのまま本番に流して大丈夫ですか？
A. 整形は見た目の調整です。かっこが閉じていない入力でも、エラーにならずに「それらしく」出力されます。流す前に、開発環境で実行して確かめてください。

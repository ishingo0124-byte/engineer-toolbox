リクエストパスマッチした location判定理由

優先順位（nginx公式ドキュメント ngx_http_core_module の location による）: ① = 完全一致（一致した時点で即決定）→ ② ^~ 付きの中で最も長く前方一致するもの（一致した時点で正規表現の検査を飛ばして即決定）→ ③ ~（大小文字区別）・~*（区別なし）の正規表現を設定ファイルに書かれた順番に検査し、最初に一致したもの → ④ どの正規表現にも一致しなければ、②で除外した ^~ なしも含めた通常の前方一致の中で最も長いもの、の順に決定されます。

よくある誤解: 正規表現の location（~ / ~*）は「より条件が厳しいもの」や「後に書いたもの」が優先されるわけではなく、あくまで設定ファイルに書いた順番で最初に一致したものが採用されます。一方、通常の前方一致（modifier なし、または ^~）は逆に書いた順番ではなく一致する文字列が最も長いものが優先されます。この2つの優先ルールの違いを混同すると、意図しない location にリクエストが振り分けられます。このツールの正規表現判定は JavaScript の正規表現エンジンで簡易的に行っており、PCRE固有の構文には完全には対応していません。

ブランドカラーの HEX を、CSS では rgb() で書き直したい。
この文字色、白背景で本当に読めるのか。
hsl() で少し暗くしたいだけなのに、頭の中では計算できない。
このツールは色を1つ入れると、HEX・rgb()・hsl() の3形式と CSS 色名を一度に出し、背景色との WCAG コントラスト比、補色、明暗9段階まで確認できます。

## 使い方

1. 「色」の欄に、HEX（`#3b82f6`、3桁の `#39f`、透明度つきの `#ff000080`）、`rgb()`、`hsl()`、CSS 色名（`royalblue`）のどれかを入れます。全角の数字でも読み取ります。
2. 入力と同時に、HEX・RGB・HSL・明度（HSL の L）・一致する CSS 色名が出ます。それぞれのコピーボタンは、そのまま CSS に貼れる書き方で書き出します。
3. 「背景色」の欄に重ねたい色を入れると、コントラスト比と AA / AAA の適合・不適合が出ます。ボタンで前景色と背景色を入れ替えられます。
4. 補色と、暗い方から明るい方へ並ぶ9段階の色を見て、配色の候補を拾います。

初期値は `#3b82f6`（青）と白背景です。開いた時点で、結果の見方が分かるようにしてあります。

## 仕組み・計算式

RGB と HSL の相互変換は、CSS Color Module Level 3 に載っている HSL の変換式と同じ考え方です。HSL は色相（0〜360度）、彩度、明度で色を表します。同じ色相のまま明るさだけ動かす、という操作が RGB より楽になります。`hsl()` の色相は360で割った余りに直すので、`-30` は `330` と同じ色です。

コントラスト比は WCAG 2.x（Web Content Accessibility Guidelines）の相対輝度で求めます。各チャンネルを0〜1にして、0.03928 以下なら12.92で割り、超えるなら `((c + 0.055) / 1.055)` の2.4乗にします。係数 0.2126・0.7152・0.0722 を掛けて足したものが相対輝度 L で、明るい方を L1、暗い方を L2 として `(L1 + 0.05) / (L2 + 0.05)` がコントラスト比です。

判定の基準は WCAG の達成基準 1.4.3（AA）と 1.4.6（AAA）です。

- 通常の文字は AA で 4.5:1、AAA で 7:1
- 大きな文字（18pt 以上、太字なら 14pt 以上が目安）は AA で 3:1、AAA で 4.5:1
- アイコンや入力欄の枠線のような文字以外の部品は、達成基準 1.4.11 で 3:1

ここまでが、画面に出る判定の全部です。本文の太さや行間まで見ているわけではありません。

CSS 色名は SVG 1.1 / CSS Color Module Level 3 の147色を内蔵しています。HEX が完全に一致したときだけ名前を出し、近い色の推測はしません。`gray` と `grey` のように同じ色の別名があるときは、先に登録した方を1つだけ表示します。

## 計算例

ツールの script.js を node で動かして出した値です。

**例1:`#3b82f6` を白背景に置く。** 出力は `rgb(59, 130, 246)`、`hsl(217, 91%, 60%)`、明度 59.8% でした。CSS 色名は「一致なし」です。コントラスト比は 3.68 : 1 で、AA の大きな文字だけが適合し、通常文字は AA・AAA ともに不適合でした。補色は `#f6af3b` です。9段階の一番暗い色は `#03183a`、一番明るい色は `#d8e6fd` でした。

**例2:境界の灰色。** 白背景で `#777777` は 4.48 : 1、`#767676` は 4.54 : 1 です。AA の通常文字は 4.5 以上なので、1だけ違う灰色で判定が分かれます。意外だったのは、見た目がほぼ同じ2色の間に基準線が入っていることでした。`#595959` は 7.00 : 1 ちょうどで、AAA の通常文字まで適合しました。

**例3:書き方の違いを入れる。** `hsl(-30, 100%, 50%)` は `#ff0080`（`hsl(330, 100%, 50%)`）になり、白背景では 3.77 : 1 です。`#39f` は各桁を重ねて `#3399ff` になり、白背景で 2.94 : 1 でした。`rgb(23%, 51%, 96%)` は `#3b82f5` で、例1の `#3b82f6` と青が1だけ違います。パーセントを0〜255へ換算するときに四捨五入が入るためです。

## よくある間違い

**ブランドカラーをそのまま本文の文字色にする。** 例1のとおり、彩度の高い中間の明るさの色は、白の上で 4.5 : 1 に届かないことがあります。ボタンの文字色や背景色を決める前に、実際に重なる2色を入れてみてください。

**半透明の色をそのまま比べる。** `#ff000080` を入れると `rgba(255, 0, 0, 0.5)` と出ますが、コントラスト比は透明度を無視して赤 `#ff0000` と背景の比（白なら 4.00 : 1）を出します。実際に見える色は背景と混ざった色です。半透明を使うなら、混ざった後の色を自分で計算して入れ直す必要があります。色名の欄にも `red` と出ますが、これは透明度を除いた RGB が一致したからです。

**3桁の HEX を「後ろに0を足す」と思う。** `#39f` は `#390f00` ではなく `#3399ff` です。各桁を2回ずつ書いた省略形なので、ここを取り違えると色がまったく変わります。

## よくある質問

### Q. `rgb()` にパーセントは使えますか。
A. 使えます。入れてみると `rgb(23%, 51%, 96%)` は `rgb(59, 130, 245)` になりました。0〜100%を0〜255に直して四捨五入するので、元の HEX と1ずれることがあります。

### Q. コントラスト比がちょうど基準の値のときは適合ですか。
A. このツールは「以上」で判定します。計算は丸める前の値で行うので、表示が `4.50 : 1` でも、実際は 4.496 のような値で不適合のことがあります。境界に近いときは、色を少し動かして余裕を持たせるのが安全です。

### Q. 補色はデザインの正解ですか。
A. 色相を180度回しただけの色です。例1の青の補色はオレンジ系の `#f6af3b` でした。配色の候補として眺める用途で、読みやすさは別にコントラスト比で確かめてください。

### Q. 入れた色はどこかに送られますか。
A. 計算はすべてブラウザの中で行います。外部に送ることはありません。

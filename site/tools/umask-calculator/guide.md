umask 022 って、結局どの権限になるんだっけ。
共有ディレクトリで、同僚が作ったファイルに書き込めない。
かといって、逆算するたびにビット演算を頭の中でやりたくない。
このツールは、umask の値から新規ファイルと新規ディレクトリの権限を8進数と記号表記で出し、欲しいディレクトリ権限から umask を逆算します。

## 使い方

1. umask を8進数で入力します。3桁か4桁（`022`、`0022`）が基本で、`22` のように短い入力は先頭を0で埋めて読みます。
2. 新規ファイルと新規ディレクトリの権限が、`644` と `-rw-r--r--` のような形で並びます。
3. よく使う値は、022・027・077・002 のボタンで入ります。

ここまでが順方向の計算です。逆方向は下の欄で使います。

4. 「逆算」では、所有者・グループ・その他のチェックボックスに、新規ディレクトリに持たせたい権限を入れます。「計算されたumask」と、同じ umask での新規ファイルの権限が出ます。コピーボタンで値を持ち出せます。

## 仕組み・計算式

umask は、新しく作るファイルやディレクトリから「取り上げる権限のビット」を表す数値です。POSIX（IEEE Std 1003.1）の umask ユーティリティと、Linux の man ページ `umask(2)` に定義があります。プログラムが要求した権限から、umask のビットを消した値が実際の権限になります。

```
新規ファイル     = 0666 & ~umask
新規ディレクトリ = 0777 & ~umask
```

計算は所有者・グループ・その他の3つの桁ごとに独立して行います。各桁は r=4、w=2、x=1 の合計です。

`umask 027` なら、所有者は0、グループは2（wを取り上げる）、その他は7（すべて取り上げる）です。ファイルは、6から0を取り上げて6、6から2を取り上げて4、6から7を取り上げて0になり、`640`、ディレクトリは `750` になります。

逆算はもっと単純で、欲しい権限の各桁を3ビットで反転するだけです。750 が欲しければ、7→0、5→2、0→7 で umask は `027` です。ディレクトリを基準にしているのは、上限が777で、r・w・x を全部指定できるからです。

4桁目（`0027` の先頭の0）は、setuid などの特別なビット用です。新規作成の権限計算には使わないので、このツールは無視します。

## 計算例

下の値は、このツールと同じ計算式を node で動かして確かめました。

| umask | 新規ファイル | 新規ディレクトリ |
|---|---|---|
| 022 | 644（-rw-r--r--） | 755（drwxr-xr-x） |
| 027 | 640（-rw-r-----） | 750（drwxr-x---） |
| 002 | 664（-rw-rw-r--） | 775（drwxrwxr-x） |
| 077 | 600（-rw-------） | 700（drwx------） |

**逆算の例。** 所有者 rwx、グループ r-x、その他なしの `750` を指定すると、umask は `027`、同じ umask でのファイルは `640` と出ました。グループに書き込みも許す `775` なら、umask は `002`、ファイルは `664` です。

**境界値。** umask `000` ならファイルは `666`、ディレクトリは `777` です。逆の `777` は、ファイルが `000`（`----------`）、ディレクトリが `d---------` になります。入力が `0027` でも `027` と同じ結果で、`22` は `022` と同じ結果でした。`8` や `9` を含む値はエラー表示になります。

## よくある間違い

**新規ファイルに実行権限が付くと思っている。** 基準は 666 なので、umask をどう変えても x は付きません。エディタで保存したシェルスクリプトを実行できないのは、umask の不具合ではなく仕様です。`chmod +x` が必要になります。なお、gcc で作った実行ファイルに最初から x が付くのは、一般にリンカが 777 を基準にファイルを作るためです。ビット演算で覚えるより「取り上げる数」と考えたほうが間違えにくい、というのが私の好みです。

**既存ファイルの権限が変わると思っている。** umask が効くのは新規作成の瞬間だけです。すでにあるファイルは `chmod` で直します。

**umask を設定した場所と、実際に動く環境が違う。** 自分のシェルでは 002 なのに、cron やサービスから作られたファイルが 644 になった、という話はよくあります。systemd のサービスでは `UMask=` という設定項目があり、シェルの設定は引き継がれません。ファイルを作るプロセスの umask を、そのプロセスの中で確かめてみてください。

親ディレクトリに default ACL が設定されている場合も、その ACL が優先されます（`acl(5)`）。この場合は umask の計算結果と一致しません。

## よくある質問

### Q. umask を077にするとどうなりますか？
A. グループとその他の権限をすべて取り上げます。新規ファイルは600、新規ディレクトリは700になり、所有者以外は読めません。個人用の作業領域や秘密鍵を置く場所で使います。

### Q. umask 002 と 022 の違いは何ですか？
A. 002 はグループの書き込みを残すので、新規ファイルは664です。同じグループの複数人で共同編集する場所に向いています。022 はグループに書き込みを許さないので、新規ファイルは644です。

### Q. いまのシェルの umask はどう確かめますか？
A. シェルで `umask` と打つと、8進数で表示されます。`umask -S` なら、`u=rwx,g=rx,o=rx` のように「許可される権限」の形で出ます。取り上げるビットではなく許可のほうが出る点に注意してください。

### Q. 逆算の欄に、ファイルの権限を指定できますか？
A. できません。指定するのは新規ディレクトリの権限です。ファイルは 666 が上限なので、逆算したあとに「同じ umask での新規ファイル」の行で確かめます。

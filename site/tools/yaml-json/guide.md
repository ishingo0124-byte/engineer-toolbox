設定ファイルのYAML、本当に思った構造で読まれているのか。
`port: 8080` は数字なのか、文字なのか。
このツールはYAMLとJSONを相互に変換し、YAMLがどんなデータとして読まれるかをJSONで見せます。対応外の構文は、行番号つきのエラーで知らせます。

## 使い方

1. 「YAML → JSON」の欄にYAMLを貼ると、下にJSONが出ます。
2. 「JSON → YAML」の欄にJSONを貼ると、インデント2のブロック形式のYAMLが出ます。
3. 構文が読めないときは、欄の上に「3行目: …」のようにエラーが出ます。
4. 結果は、それぞれのコピーボタンでコピーします。

2つの欄は独立しています。片方を直しても、もう片方は変わりません。変換のたびに、貼る場所を間違えないようにしてください。

## 仕組み・計算式

YAMLの仕様は「YAML Ain't Markup Language Version 1.2.2」です。JSON（RFC 8259）はYAML 1.2の部分集合として作られていて、`{}` と `[]` で書くフロー形式のYAMLは、JSONとほぼ同じに読めます。ツールは外部のライブラリを使わず、インデントを手がかりに自作のパーサで読みます。

読めるのは、ブロック形式とフロー形式のマップとシーケンス、引用符つきと引用符なしの文字列、数値・真偽値・null、`#` のコメント、複数行文字列（`|` と `>`）、アンカー（`&名前`）とエイリアス（`*名前`）です。`!!str` のようなタグは読み飛ばします。

型の決め方は、YAML 1.2のコアスキーマ（仕様の10.3節）に沿っています。`true`・`false`（大文字小文字違いも）が真偽値、`null`・`~`・空の値が null、`0x1F` は16進、`0o17` は8進です。`yes`・`no`・`on`・`off` は、文字列のまま残します。日付の `2026-11-13` も文字列です。

JSON → YAML は、JSONを `JSON.parse` で読み、ブロック形式で書き出します。文字列が別の型と間違われそうなときは、`"yes"` のように二重引用符で囲みます。対象は、真偽値やnullに見える語（`true`・`no`・`on`・`null`・`~`・`y`・`n` と大文字違い）、数字だけの値（`123`、ゼロで始まる `0755`、`1_000`、`-5`）、`1e3`・`0x1F`・`0o17` の形、`.inf` と `.nan` です。

扱えない構文は、ツールの側で止めます。複数ドキュメント（`---`）、`>2` のような明示的なインデント指定、複数行にまたがる引用符つき文字列、タブでのインデントです。YAMLの仕様はインデントにタブを認めていません。

## 計算例

画面に出た結果を確かめるため、ツールのスクリプトをNode.jsで動かして、出力を見ました。

**例1：初期表示のYAML。** `port: 8080` は数値、`version: 1.2.3` は文字列（ドットが2つあるので数値になりません）です。`tags: [web, prod]` は配列、`options: { timeout: 30, retry: true }` はオブジェクトになりました。`description: |` の複数行は、`"複数行の説明文です。\n改行はそのまま保持されます。\n"` と、最後に改行が付きます。`|-` と書くと、この最後の改行は付きません。

**例2：NoやYesの扱い。** `country: NO`・`flag: no`・`mode: on`・`ok: yes` は、4つとも文字列です（`"NO"`、`"no"`、`"on"`、`"yes"`）。`t: true` と `T: True` は、どちらも真偽値の `true` でした。`~`、`null`、値が空の行は、`null` になります。

**例3：数値のようで数値でないもの。** `a: 0755` は文字列 `"0755"`、`b: 0o755` は 493、`c: 0x1F` は 31、`d: 1e3` は 1000 になりました。`h: '8080'` は引用符があるので `"8080"`、`1_000` も文字列です。逆向きのJSON → YAMLでは、文字列の `"0755"`・`"123"`・`"1e3"`・`"true"`・`"no"`・`"null"`・`"~"` が、すべて引用符つきで出ました。出したYAMLをもう一度YAML → JSONに通すと、元の文字列に戻ります。

**例4：エラーと境界。** 2行目の頭にタブを入れると、「2行目: インデントにタブ文字は使用できません（半角スペースを使ってください）」と出ます。`a: 1` の次の行に `---` を入れると、2行目のエラーです。逆向きでは、JSONの `12345678901234567890` が YAML に直すと `12345678901234567000` になりました。

## よくある間違い

**`no` や `NO` を書いて、falseになると思う。** 古いYAML 1.1系のパーサは、引用符のない `no` や `on` を真偽値にします。国コードの `NO`（ノルウェー）が false になる話は有名です。国コードが false に化けた経験はありませんか？パーサによって結果が変わるので、文字列にしたい値は引用符で囲んでください。ツールは1.2に合わせて、文字列のまま出します。

**`0755` が同じ値で読まれると思う。** ファイルのパーミッションで書きがちな値です。ツールでは文字列の `"0755"` ですが、YAML 1.1では8進数、1.2では10進数として読むパーサもあります。読み手しだいで 493 になったり 755 になったりします。手で書くYAMLでは、文字列にしたいなら `"0755"` と引用符を付けてください。意外だったのは、数字だけの値でも、ゼロで始まるだけで読み方が分かれることです。

**マージキー（`<<: *base`）が展開されると思う。** Docker ComposeやCI設定でよく見る書き方です。ツールはエラーにせず、`"<<"` という名前のキーとして残します。展開された結果を見たいなら、手で展開してから貼ってください。変換結果が元の設定と同じ意味だと、思い込まないでください。

**時刻やバージョンのような値を、引用符なしで書く。** `time: 12:30:45` は、ツールでは文字列 `"12:30:45"` になりました。YAML 1.1には60進数の整数という読み方があり、古いパーサだと数値になることがあります。`version: 1.2.3` は文字列ですが、ドットが1つの `1.2` は数値です。バージョン番号のように文字列として扱いたい値は、引用符で囲んでおくと安全です。

## よくある質問

### Q. 複数ドキュメント（`---` で区切るもの）は変換できますか？
A. できません。`---` が出るとエラーになります。1ドキュメントずつ貼ってください。

### Q. コメントは JSON に残りますか？
A. 残りません。JSONにはコメントがないため、YAML → JSON でコメントは消えます。

### Q. 日付の `2026-11-13` はどう読まれますか？
A. このツールでは文字列の `"2026-11-13"` になります。日付型として読むパーサもあるので、受け取る側のライブラリに合わせて引用符を付けるか決めてください。

### Q. 大きな数値は正しく変換されますか？
A. JavaScriptの数値で扱うため、約 9,007,199,254,740,991（2の53乗から1を引いた値）を超える整数は、末尾が丸められます。IDのような長い整数は、文字列にして扱うのが安全です。

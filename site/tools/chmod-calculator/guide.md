scp したファイルが実行できない。
`chmod 755` と `chmod 644` の違いを、毎回調べ直している。
`ls -l` の `-rwsr-xr-x` の `s` が何なのか分からない。
チェックボックス、8進数、記号表記のどれを触っても残り2つとコマンド例が揃うので、数字と文字列の対応を毎回頭の中で計算せずに済みます。

## 使い方

1. 8進数の欄（例: `755`）、記号表記の欄（例: `-rwxr-xr-x`）、所有者・グループ・その他のチェックボックスのどれか1つを変えます。残り2つは自動で書き換わります。
2. SUID・SGID・スティッキービットを使うときは、特殊権限のチェックを入れます。8進数の先頭に4桁目が付きます。
3. よく使う値は 644・755・600・700・777 のプリセットボタンで入れられます。
4. 「コマンドをコピー」で `chmod 755 対象ファイル` の形の文字列がコピーされます。「対象ファイル」は自分のファイル名に書き換えて使います。

入力欄は全角数字も半角に直して読みます。

8進数は 755 のように3桁でも、4755 のように4桁でも入れられます。`0644` のような先頭の0付きも通りますが、表示は `644` に戻ります。

## 仕組み・計算式

Unix のパーミッションは、所有者（u）・グループ（g）・その他（o）の3組について、読み取り（r=4）、書き込み（w=2）、実行（x=1）を足した 0〜7 の1桁で表します。r と x だけなら 4+1=5、rwx なら 7 です。3組を並べると `755` や `644` になります。定義は POSIX の chmod ユーティリティと、`man 1 chmod` にあります。

4桁目（先頭）は特殊権限です。SUID が 4、SGID が 2、スティッキービットが 1 で、これも足し算です。記号表記では、実行ビットと同じ位置に重なって出ます。実行権限があれば小文字の s / t、なければ大文字の S / T です。

SUID を付けた実行ファイルは、実行した人ではなくファイルの所有者の権限で動きます。`passwd` コマンドが有名な例です。SGID をディレクトリに付けると、中で作ったファイルが親ディレクトリのグループを引き継ぎます。スティッキービットをディレクトリに付けると、他人のファイルを消せなくなります。`/tmp` が典型です。

**現場の落とし穴**: 新しく作ったファイルの権限は、chmod ではなく umask で決まります。umask は「既定値から外すビット」を指定するものです。ファイルの既定値は 666、ディレクトリは 777 なので、umask が 022 なら、新しいファイルは 644、ディレクトリは 755 になります。（引き算に見えますが、実際はビットを外す処理です。）「新しいファイルが 755 にならない」ときは、先に umask を疑います。

## 計算例

このツールのロジックを node で動かして確かめた結果です。

**例1: 8進数 `755`**
記号表記は `-rwxr-xr-x`。所有者は読み取り・書き込み・実行、グループとその他は読み取り・実行です。コマンドは `chmod 755 対象ファイル` と出ます。

**例2: 8進数 `644` と `600`**
`644` は `-rw-r--r--`。`600` は `-rw-------` で、グループとその他は「権限なし」です。SSH の秘密鍵に 600 がよく言われるのは、他人に読めてはいけないからです。

**例3: 記号表記 `-rwsr-xr-x`**
8進数は `4755`。所有者の実行ビットがあるので s は小文字です。

**境界値: `4644` と `1777`**
`4644` は記号表記が `-rwSr--r--` になります。SUID は付いているのに所有者の実行ビットがないので、s が大文字の S になります。これは実行できない SUID で、ほぼ設定ミスのサインです。`1777` は `-rwxrwxrwt` で、`/tmp` と同じ形です。

## よくある間違い

**ディレクトリにファイルと同じ 644 を付ける。** 心当たりはありませんか？
ディレクトリは x がないと中に入れません。644 のディレクトリは、所有者でも `cd` が通りません。ディレクトリは 755 か 700 が基本です。

**とりあえず 777 にして動かす。**
正直なところ、急いでいるときは私も 777 に逆らいにくいです。権限エラーは消えますが、同じサーバーを使う全員が書き換えられる状態になります。原因が所有者かグループなら、`chown` や `chgrp` で直すほうが安全です。

**S（大文字）を見落とす。**
`ls -l` で `S` や `T` が出ているときは、実行ビットが欠けています。意図した設定かどうか、一度見直してください。

ところで、エラー表示中の挙動も知っておくと便利です。たとえば 8進数に `758` を入れるとエラーは出ますが、ほかの欄は直前の正しい値のまま残ります。コピーする前に、エラー文が消えているかを見てください。

## よくある質問

### Q. 777 は使ってよいですか？
誰でも読み書き実行できるので、Web の公開ディレクトリなどでは避けるのが基本です。必要な人にだけ必要な権限を付けます。

### Q. ディレクトリに実行権限(x)が必要なのはなぜですか？
ディレクトリの x は、その中に入ったり、中のファイルの情報を取り出したりする権限だからです。r だけだと、ファイル名の一覧は見えても中身の詳細が取れないことがあります。

### Q. 記号表記の先頭の `-` は何ですか？
ファイルの種別です。`-` が通常ファイル、`d` がディレクトリ、`l` がシンボリックリンクです。記号表記の欄に `drwxr-xr-x` と入れると、8進数は `755` になります。権限の計算には種別を使いません。

### Q. 記号表記は9文字でも入れられますか？
入れられます。`rwxr-xr-x` のように先頭の種別を省くと、通常ファイルとして扱います。

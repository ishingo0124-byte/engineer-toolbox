ログに `2001:db8::1:0:0:1` と `2001:db8:0:0:1::1` が出てきた。同じアドレスなのか、別物なのか。
`::` をどこに置くのが正解なのか、手で書くたびに迷う。
IPv6 アドレスを入れると、8ブロック4桁の完全形と、RFC 5952 の正規表記が並んで出ます。文字列で比べるときの、表記ゆれの確認に使えます。

## 使い方

1. IPv6 アドレスを入力します。省略形（`::` あり）、完全形、`/64` のようなプレフィックス付き、`::ffff:192.0.2.1` のような末尾 IPv4 の形のどれでも読めます。
2. 完全展開（8ブロック・各4桁）と正規表記（RFC 5952）が表示されます。コピーボタンで貼り付け用に取り出せます。
3. プレフィックス長、IPv4射影表記、16ビットごとの2進数も同じ画面に出ます。

大文字でも小文字でも、全角のコロンや数字でも読みます。プレフィックスを付けた場合は、`/64` がそのまま結果に引き継がれます。

アドレス全体を展開するだけで、ネットワーク部への丸めはしません。

## 仕組み・計算式

IPv6 アドレスは 128 ビットで、16 ビットずつ8ブロックに分け、コロン区切りの16進数で書きます。連続するゼロのブロックは `::` で1回だけ省略できます。書式は RFC 4291 の 2.2 節にあります。

このツールは、入力をまず8ブロックの完全形に展開します。`::` の場所に入るゼロの数は「8 − 書かれているブロック数」で決まります。そのあと、完全形から正規表記を組み立てます。

正規表記のルールは RFC 5952 の 4 節です。先頭のゼロは省きます。一番長いゼロの連続を `::` に置き換えます。長さが同じ連続が複数あるときは、左のほうを選びます。ゼロが1ブロックだけなら `::` にしません。16進数の英字は小文字にします。

IPv4射影アドレス（`::ffff:0:0/96`、RFC 4291 の 2.5.5.2 項）は、末尾 32 ビットをドット10進で書く混在形式にして出します。RFC 5952 の 5 節がこの形式を勧めているので、それに合わせました。

**現場の落とし穴**: 同じアドレスでも、文字列としては何通りにも書けます。`2001:db8::1` と `2001:0db8:0:0:0:0:0:1` は同じ値です。ログの突き合わせや重複排除を文字列の一致でやると、別のアドレスとして数えてしまいます。集計が妙に多くないですか？比べる前に正規化してください。

## 計算例

このツールのロジックを node で動かして確かめた結果です。

**例1: `2001:0db8:0000:0000:0001:0000:0000:0001`**
正規表記は `2001:db8::1:0:0:1`。ゼロの連続が2か所あり、どちらも長さ2です。同じ長さなので左側が `::` になり、右側は `0:0` のまま残ります。

**例2: `fe80::1/64`**
完全展開は `fe80:0000:0000:0000:0000:0000:0000:0001/64`、正規表記は `fe80::1/64` です。

**例3: `::ffff:192.0.2.1`**
完全展開は `0000:0000:0000:0000:0000:ffff:c000:0201`。IPv4射影の欄に `::ffff:192.0.2.1` と出ます。c000:0201 が 192.0.2.1 に当たります。

**境界値: `2001:db8:0:1:1:1:1:1`**
ゼロのブロックが1個しかないので、`::` にはなりません。正規表記は入力と同じ `2001:db8:0:1:1:1:1:1` です。`::` に直したくなるところで、直さないのが仕様です。

エラーになる例も確認しました。`2001:db8::1::2` は「:: による省略は1箇所までしか使えません」、`2001:db8:0:0:0:0:0:0:1` は「ブロック数が8個ではありません（9個）」と出ます。

## よくある間違い

**`::` を2か所に使う。**
`2001:db8::1::2` のように2回使うと、どこに何個のゼロが入るのか決まりません。手作業で書き写すときに起きがちです。

**8ブロック揃っているのに `::` を足す。**
`1:2:3:4:5:6:7::8` は、すでに8個あるので省略するゼロがありません。ツールは「:: は1個以上の0ブロックを省略する場合のみ使用できます」と始まるエラーを出します。

**ゼロ1個を `::` にして、正規表記だと思い込む。**
RFC 5952 では、1ブロックだけのゼロに `::` は使いません。`::` を使った表記が別のツールや機器から出てきても、アドレスとしては有効です。ただ、文字列比較は一致しません。正直なところ、私は最初「短いほうが正規だろう」と思っていました。

## よくある質問

### Q. 完全形だけで書いたアドレスも入力できますか？
入力できます。8ブロックが揃っていれば、`::` が無くても読めます。

### Q. `/64` を付けるとネットワークアドレスに丸まりますか？
丸まりません。プレフィックス長は表示に引き継ぐだけです。ネットワークアドレスを出したい場合は、別のサブネット計算ツールを使います。

### Q. IPv4射影以外の、末尾が IPv4 の形も扱えますか？
展開はできます。ただ、正規表記でドット混在にするのは `::ffff:0:0/96` の範囲だけです。それ以外は16進数で出します。

### Q. 不正なアドレスを入れるとどうなりますか？
`::` の2回使用、ブロック数の過不足、使えない文字などを検出して、理由つきのメッセージを出します。結果欄は「-」になります。

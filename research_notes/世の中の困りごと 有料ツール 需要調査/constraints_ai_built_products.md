## 1. 日本の法律：ツールが「できること・言えること」の制約

### Takeaway
「利用者が自分で入力し、自分の端末で計算・変換するソフトを売る」限り、士業法（税理士・弁護士・社労士・行政書士）の制限にはかかりにくい。国税庁は、申告書作成ソフトの開発・販売は税理士業務に当たらないと明言している。境界を越えるのは次の場合。
- 個別の相談に答える
- 紛争を前提にした書面を作る
- 他人の依頼で官公署向け書類を作る
- 診断・治療・予防をうたう

制度面の負担が急に増える機能も決まっている。
- 利用者同士のメッセージ → 電気通信事業の届出
- 6か月を超えて使えるポイント → 資金決済法
- サーバーでの個人データ保管 → 個人情報保護法・漏えい報告

### Cited Findings

#### 税理士法（税務計算ツールの境界）
- 税理士業務は「税務代理」「税務書類の作成」「税務相談」の3つ。「税務相談」は、申告書の作成などに関して課税標準等の計算について相談に応じること。「相談に応ずる」は「具体的な質問に対して答弁し、指示し又は意見を表明すること」（基通2-6）と定義されている — [国税庁「税理士制度のＱ＆Ａ」問2-1（令和8年7月1日現在の法令等に基づく）](https://www.nta.go.jp/taxes/zeirishi/zeirishiseido/qa/pdf/all.pdf)
- 「業とする」は反復継続して行うこと（またはその意思）をいい、**「必ずしも有償であることを要しない」**（基通2-1）。無料でも業に当たり得る — [同 問2-2](https://www.nta.go.jp/taxes/zeirishi/zeirishiseido/qa/pdf/all.pdf)
- **問6-3**「他人の求めに応じ、業として、申告書等の作成ソフトを開発又は販売することは…税理士業務に該当しますか」→ 答は「非税理士が申告書等の作成ソフトを開発又は販売することは、…税理士業務のいずれにも該当しません」 — [同 問6-3](https://www.nta.go.jp/taxes/zeirishi/zeirishiseido/qa/pdf/all.pdf)
- 法52条違反（非税理士による税理士業務）は「２年以下の拘禁刑又は 100 万円以下の罰金」（法59条1項4号） — [同 問6-1](https://www.nta.go.jp/taxes/zeirishi/zeirishiseido/qa/pdf/all.pdf)
- 令和5年改正で法54条の2が新設された。SNS などで非税理士が不特定多数に脱税相談（指南）をするリスクに対応し、財務大臣が税務相談の停止などを命令できる。違反は1年以下の拘禁刑または100万円以下の罰金 — [同 問6-1](https://www.nta.go.jp/taxes/zeirishi/zeirishiseido/qa/pdf/all.pdf)
- 財務省の法令適用事前確認手続（令和7年4月24日回答、国税庁長官官房総務課長）では、依頼企業と専門企業をつなぐマッチングプラットフォームの運営について、「『税務代理』『税務書類の作成』『税務相談』を伴うものではなく…マッチングプラットフォームの運営を行うものに留まるものであるとすれば、税理士業務に該当しない」と回答した — [財務省 回答書PDF](https://www.mof.go.jp/application-contact/procedure/jizen/zeirishi_20250424_kaitou.pdf)

#### 弁護士法72条（契約書チェック・内容証明・示談書などのツール）
- 条文:弁護士でない者は「報酬を得る目的で訴訟事件…その他一般の法律事件に関して鑑定、代理、仲裁若しくは和解その他の法律事務を取り扱い…これらの周旋をすることを業とすることができない」 — [e-Gov 弁護士法72条](https://laws.e-gov.go.jp/law/324AC1000000205)
- 法務省のガイドラインは2本ある — [法務省 弁護士法72条関連ページ](https://www.moj.go.jp/housei/shihouseido/housei10_00134.html)
  - 2023年8月「AI等を用いた契約書等関連業務支援サービスの提供と弁護士法第72条との関係について」
  - **2026年8月21日**「ビジネス分野におけるＡＩ等法務業務支援サービス提供と弁護士法第７２条の関係について」（法務副大臣のもとのタスクフォースの取りまとめ。2023年版を補完・拡充）
- 2026年ガイドライン概要の判断基準 — [法務省 2026年ガイドライン概要PDF](https://www.moj.go.jp/content/001469039.pdf)
  - 次の①②を満たし、③の体制があれば、「一般的に弁護士法第７２条に抵触しないと考えられる」。
    - ① 「事件性」のある案件に使わせることを目指した設計でない
    - ② 「事件性」案件に特化した機能を持たない
    - ③ ガバナンス措置で不適切利用を避ける体制がある
  - 一般に抵触しないとされる例:リサーチ、「書面作成・審査・管理業務支援」、コンプライアンス支援など。
  - **抵触と評価され得る例**:
    - 「法的紛議が現に顕在化している事案や法的紛議が生じることがほぼ不可避に想定され得る案件の処理を目指して設計されたサービス」
    - 「訴状等の裁判所への提出書面や和解契約書等の法的紛議を前提とした対外使用書面の作成に係るサービス」
  - 推奨されるガバナンス:
    - 弁護士による設計への実質的関与
    - 「弁護士に代わる判断を提供する…法的結論の正確性を保証する」と想起させる表現を「厳に慎む」こと
    - 事件性案件に使えない旨のディスクレーマーを入力前と出力に表示
    - 国内のインシデント対応窓口の設置
- 対象範囲について:2026年ガイドラインの題名は「**ビジネス分野**における」。一般消費者向け（個人間トラブル用など）の扱いは概要版からは読み取れなかった — [同上](https://www.moj.go.jp/content/001469039.pdf)

#### 社労士法・行政書士法（書類作成系ツール）
- 社労士法27条:社労士でない者は「他人の求めに応じ報酬を得て」、第2条第1項第1号から第2号まで（申請書等の作成・提出代行など）の事務を業として行ってはならない — [e-Gov 社会保険労務士法27条](https://laws.e-gov.go.jp/law/343AC1000000089)
- 行政書士法19条（現行条文）:行政書士でない者は「他人の依頼を受け**いかなる名目によるかを問わず**報酬を得て」、業として官公署提出書類（電磁的記録を含む）や権利義務・事実証明に関する書類を作成できない。ただし書きで、総務省令で定める定型的な手続の電磁的記録の作成に例外がある — [e-Gov 行政書士法1条の3・19条](https://laws.e-gov.go.jp/law/326AC1000000004)
- この「いかなる名目によるかを問わず」の追加は2026年1月1日施行の改正による。コンサル料や会費の名目で実質的に業務を行う無資格者を明確に違法にする趣旨で、両罰規定も新設された（解説記事による） — [jitsumu-guide.com](https://jitsumu-guide.com/administrative-scrivener-law-2026-guide/)、[契約ウォッチ](https://keiyaku-watch.jp/media/hourei/202601-gyoseishoshihou-kaisei/)

#### 薬機法・プログラム医療機器（健康ツール）
- 該当性の資料:「プログラムの医療機器該当性に関するガイドライン」（令和5年3月31日一部改正）、判断事例（同日）、医療機器プログラム事例データベース（令和8年9月8日更新・10月14日一部修正）。該当性の相談は厚労省監視指導・麻薬対策課とPMDA「医療機器プログラム総合相談」 — [厚労省 医療機器プログラムページ](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/0000179749_00004.html)
- 該当性の判断は「製造販売業者等による当該製品の表示、説明資料、広告等に基づき、当該プログラムの使用目的及びリスクの程度」で行う。「同じ機能を有するプログラムであっても、使用目的が異なれば…判断は異なる可能性がある」 — [ガイドライン本文 3](https://www.mhlw.go.jp/content/11120000/001082227.pdf)
- 医療機器に該当しない典型例 — [同 4](https://www.mhlw.go.jp/content/11120000/001082227.pdf)
  - 個人の健康記録（血糖値・血圧・心拍数・体重など）を保存・管理・表示するプログラム
  - スポーツのトレーニング管理など、医療・健康以外を目的とするプログラム
  - クラスⅠ相当の低リスクプログラム
- 脚注:クラスⅠ相当のプログラムでも「クラス II 以上の医療機器との認識を与える標ぼうなどを行った場合、医薬品医療機器等法第 68 条等の広告規制に抵触するおそれ」がある — [同 脚注1](https://www.mhlw.go.jp/content/11120000/001082227.pdf)
- 複数機能のうち1つでも医療機器の定義を満たせば、全体として医療機器の流通規制を受ける — [同 3](https://www.mhlw.go.jp/content/11120000/001082227.pdf)

#### 景品表示法・ステマ規制（宣伝）

#### 個人情報保護法（個人データを扱うツール）
- 「個人情報取扱事業者」は「個人情報データベース等を事業の用に供している者」。条文に件数の下限はない — [e-Gov 個人情報保護法16条](https://laws.e-gov.go.jp/law/415AC0000000057)
- 個人の権利利益を害するおそれが大きい漏えい等が起きた場合、個人情報保護委員会への報告義務がある（26条） — [e-Gov 個人情報保護法26条](https://laws.e-gov.go.jp/law/415AC0000000057)

#### 電気通信事業法（メッセージ機能・解析タグ）
- 「電気通信役務」は「電気通信設備を用いて他人の通信を媒介し、その他電気通信設備を他人の通信の用に供すること」と定義される（2条3号）。登録が要らない電気通信事業も、原則は総務大臣への届出が必要（16条） — [e-Gov 電気通信事業法2条・16条](https://laws.e-gov.go.jp/law/359AC0000000086)
- 適用除外の「第三号事業」は、他人の通信を媒介する役務以外の役務を、回線設備を設置せずに提供する事業（ドメイン名・検索・媒介相当役務の指定分を除く）。媒介をしないツールは原則ここに入る — [e-Gov 電気通信事業法164条](https://laws.e-gov.go.jp/law/359AC0000000086)
- 外部送信規律（27条の12、2023年6月16日施行）:「利用者の利益に及ぼす影響が少なくないもの」として総務省令で定める役務の提供者が対象。第三号事業者を含む。利用者端末から外部に情報を送らせるタグ等について、通知・公表、同意、オプトアウトのいずれかが必要 — [e-Gov 電気通信事業法27条の12](https://laws.e-gov.go.jp/law/359AC0000000086)
- 対象役務の類型には「各種情報のオンライン提供」（ニュース、気象、動画、地図など）がある（総務省の省令案資料。検索結果の要約による） — [総務省資料](https://www.soumu.go.jp/main_content/000831301.pdf)

#### 特定商取引法（通信販売の表示・最終確認画面・返品）
- 個人事業者が表示すべきもの — [消費者庁 特商法ガイド 通信販売の広告](https://www.no-trouble.caa.go.jp/what/mailorder/advertising.html)
  - 「氏名又は登記された商号、住所及び電話番号」。通称・屋号・サイト名は不可
  - 住所は「現に活動している住所」
  - ソフトウェアは「動作環境（OSの種類、CPUの種類、メモリの容量…）」の表示が必要
  - 返品特約は条件を具体的に書く。「その都度御相談に応じます」は不適切とされている
- 法11条ただし書:請求があれば表示事項を記載した書面・電磁的記録を**遅滞なく提供する旨を広告に表示**すれば、一部を表示しないことができる — [e-Gov 特商法11条](https://laws.e-gov.go.jp/law/351AC0000000057)
- 通信販売広告Q&A — [消費者庁 通信販売広告Q&A](https://www.no-trouble.caa.go.jp/qa/advertising.html)
  - Q15・Q17:請求時に遅滞なく提供する旨の表示と、実際に提供できる措置があれば、氏名・住所・電話番号を省略できる
  - Q18:プラットフォーム事業者やバーチャルオフィスの住所・電話番号でも要請を満たし得る。条件は、取引がそのプラットフォーム上で行われること、連絡先として機能する合意があること、運営者が現住所と本人名義の電話番号を把握していること
  - Q19:私書箱は不可
  - Q20:夜間の留守電は可
- 最終確認画面（12条の6、いわゆる詐欺的定期購入対策）:オンラインの申込画面に「分量」と11条1〜5号の事項（価格・支払時期・引渡時期・申込期間・撤回解除の条件など）を表示しなければならない — [e-Gov 特商法12条の6](https://laws.e-gov.go.jp/law/351AC0000000057)
- 法定返品権（15条の3）:商品・特定権利は引渡しから8日以内なら撤回・解除できる。ただし返品特約を広告に表示していれば適用されない。電子消費者契約の場合の表示方法は主務省令で定める構造になっている — [e-Gov 特商法15条の3](https://laws.e-gov.go.jp/law/351AC0000000057)

- 8条3項:軽過失の場合の一部免除でも、条項が「重大な過失を除く過失による行為にのみ適用されることを明らかにしていないもの」は無効 — [e-Gov 消費者契約法8条3項](https://laws.e-gov.go.jp/law/412AC0000000061)。この項は2023年6月1日施行の改正で追加された — [BUSINESS LAWYERS](https://www.businesslawyers.jp/articles/1370)
- 10条:信義則に反して消費者の利益を一方的に害する条項は無効 — [e-Gov 消費者契約法10条](https://laws.e-gov.go.jp/law/412AC0000000061)

#### 資金決済法（ポイント・クレジット・送金）
- 前払式支払手段:金額や数量に応じた対価を得て発行し、代価の弁済に使えるもの（3条） — [e-Gov 資金決済法3条](https://laws.e-gov.go.jp/law/421AC0000000059)
- 適用除外:「発行の日から政令で定める一定の期間内に限り使用できる」もの（4条2号）。政令の期間は**六月** — [e-Gov 資金決済法4条](https://laws.e-gov.go.jp/law/421AC0000000059)、[e-Gov 同施行令4条2項](https://laws.e-gov.go.jp/law/422CO0000000019)
- 自家型（自社サービスだけで使えるもの）の発行者は、法人だけでなく個人も対象。基準日（3/31・9/30）の未使用残高が基準額を超えたら届出が必要（5条）。基準額は**千万円**で、超えると未使用残高の2分の1以上を供託（14条） — [e-Gov 資金決済法5条・14条](https://laws.e-gov.go.jp/law/421AC0000000059)、[e-Gov 同施行令6条](https://laws.e-gov.go.jp/law/422CO0000000019)
- 資金移動業（送金の仲介）は内閣総理大臣の登録が必要（37条） — [e-Gov 資金決済法37条](https://laws.e-gov.go.jp/law/421AC0000000059)

- 2割特例の終了時期は、多くの解説が2026年9月末としているが、「2026年いっぱい」とする記事もあり食い違う。一次資料（国税庁）で未確認。

### Inferences
- **計算・変換ツールは「ソフトの販売」に寄せれば安全側**。国税庁が「申告書等の作成ソフト」の販売は税理士業務に当たらないとしている。一般的な計算機（税額、和暦、社会保険料の概算、日割りなど）を売ることは、同じ理屈で士業法の外に置ける可能性が高い。境界を越えやすいのは次の3つ。
  - AI チャットで「あなたの場合は経費にできます」など**個別具体的な質問に答える**機能。「業」に有償は要らないので、無料でも危うい
  - 運営者が利用者の代わりに書類を**作成して提出する**サービス
  - 脱税を示唆する内容
- **法律系は「紛争前提」を外すこと**。2026年ガイドラインは訴状・和解契約書など紛争前提の書面作成サービスを、典型的な抵触例に挙げている。内容証明（督促・解除通知など）、示談書、退職代行文書、クーリングオフ以外の紛争文書の生成ツールは、設計上「事件性」案件向けと評価されやすい。避けるのが妥当。逆に、契約書の**汎用ひな形**や条項の一般解説は比較的安全側。ただしガイドラインは「ビジネス分野」向けで、消費者向けの扱いは未確定。
- **行政書士法の2026年改正で「名目を問わず報酬」が明文化された**。許認可申請書、補助金申請書、在留資格書類などを運営者が利用者ごとに作るサービスは危険度が上がった。利用者が自分で記入する汎用フォーム・計算補助なら、税理士 Q&A 6-3 と同じく「ソフトの販売」と整理できる余地がある。ただし行政書士法について公式の同旨見解は見つからなかった。
- **健康ツールは「表示」で決まる**。体重・歩数・血圧の記録や表示は非該当の典型例。「〜の予防に」「〜のリスクを判定」「診断」とうたうと、機能が同じでも医療機器（未承認なら広告違反）側に倒れる。AI が書く宣伝文・解説文の表現チェックが要る。
- **免責は「一切責任を負いません」では効かない**（消費者向け）。8条3項に合わせて「当方の軽過失による損害の賠償は、購入代金を上限とする（故意・重過失を除く）」のように範囲を明示する形が要る。AI だけで作ったことを理由に責任を逃れることはできない、と考えるべき。
- **ポイント・クレジット制は避ける（使うなら有効期限6か月以内）**。サブスクか買い切りにすれば資金決済法の論点自体が消える。
- **利用者間のメッセージ・掲示板・ファイル共有の中継は作らない**。他人の通信の媒介になると届出、通信の秘密、障害対応が要り、「手を離す」が成り立たない。
- **既存の無料サイトで AdSense・GA4 を使っている点**について。外部送信規律の対象役務に当たるかはグレーだが、送信先・目的をプライバシーポリシーで公表しておけば、どちらに転んでも安全側になる（推測）。

### Gaps
- 2026年法務省ガイドラインの本文（12〜14頁の具体例）と2023年版本文は、法務省PDFの直接取得が403で読めなかった。概要版のみ確認。**消費者向けツール（内容証明作成など）への当てはめ**を明示した公的資料は見つからなかった。
- 行政書士法19条の「定型的かつ容易に行える手続」の総務省令の中身は未確認。書類作成**ソフトの販売**を行政書士法上どう扱うかの公的見解も見つからなかった。社労士法も同様。
- 外部送信規律の対象役務が、小規模なツールサイトにどこまで及ぶか（総務省FAQ・ガイダンスの最新版）は一次資料で未確認。
- デジタル商品（ダウンロードソフト）が特商法15条の3の「商品」に当たるのか「役務」なのかは未確認。いずれにしても返品特約の明示が実務上の答えになる。
- インボイス:2割特例の終了日と3割特例の成立状況は国税庁の一次資料で未確認（⚠）。MoR（Apple・Stripe 等）経由で売る場合の消費税・インボイスの扱いも未調査。
- 子どもの個人データに特化した日本の規制は今回調べていない。

## 2. 販売チャネルの費用・ルール（日本の個人が使う場合）

### Takeaway
「オーナーは登録だけ」に最も合うのは次の2つ。
- Web 直販 + Stripe（とくに Stripe が販売者になる **Managed Payments**。2026年時点で日本の事業者が使える）
- BOOTH / Gumroad などのマーケット

iOS と Android は手間が大きい。
- iOS:年会費と審査があり、実名が販売元に出る
- Android:新規の個人アカウントは**12人×14日のクローズドテスト**が必須で、収益化すると**住所が公開**される

Chrome 拡張は Web Store の決済が廃止済みで、外部決済が前提。

- 日本の標準料金:カード・ウォレット3.6%（通貨換算+2%）、初期・月額なし。Stripe Tax 0.5%、Billing 0.7% — [Stripe 料金（日本）](https://stripe.com/jp/pricing)

## 3. サポート・運用負担（製品形態ごとの差）

### Takeaway
小規模ソフトの「顧客あたり問い合わせ件数」の信頼できる公開ベンチマークは見つからなかった。数字は弱い二次情報のみ。構造的には、次の順でサポート・障害対応・法的義務が減る。
1. アカウントとデータ保管を持つ SaaS（最大）
2. ライセンスキーだけの Web アプリ
3. 端末内で完結するアプリ
4. オフラインのダウンロード商品

MoR は決済まわりの問い合わせを肩代わりする。

### Cited Findings
- 問い合わせ件数の目安（いずれもベンダーブログの二次引用で、原典は未確認）
  - SaaS の上位組織で月0.5件/ユーザー（MetricNet 引用）、B2B SaaS で問い合わせる顧客は10〜30%（Zendesk 引用） — [Monetizely](https://www.getmonetizely.com/articles/how-to-calculate-support-cost-per-customer-a-strategic-guide-for-saas-executives)
  - 広く出回る「エージェントあたり月294件」は2012年の Zendesk ホワイトペーパーが出所で、2025年版の出典は検証できなかったという指摘がある — [Fin.ai](https://fin.ai/learn/how-many-support-tickets-justify-a-helpdesk)
- Stripe Managed Payments は取引単位のカスタマーサポートと紛争対応を Stripe が担う — [Stripe Docs](https://docs.stripe.com/payments/managed-payments)
- 返金・返品の表示義務 — [消費者庁 特商法ガイド](https://www.no-trouble.caa.go.jp/what/mailorder/advertising.html)、[e-Gov 特商法12条の6・15条の3](https://laws.e-gov.go.jp/law/351AC0000000057)
  - 返品特約は具体的に書く必要がある（「欠陥がある場合を除き返品に応じません」は可、「その都度御相談」は不可）
  - 最終確認画面に撤回・解除の条件を出す必要がある
- 特商法の電話番号は「確実に連絡が取れる番号」が原則。請求時開示で表示を省略しても、請求があれば提供できる体制が要る — [消費者庁 通信販売広告Q&A Q17](https://www.no-trouble.caa.go.jp/qa/advertising.html)
- 個人データの漏えい時には個人情報保護委員会への報告義務がある — [e-Gov 個人情報保護法26条](https://laws.e-gov.go.jp/law/415AC0000000057)
- 法務省ガイドラインは、AI 法務支援の提供者に国内のインシデント対応窓口の設置を推奨している — [法務省 2026年GL概要](https://www.moj.go.jp/content/001469039.pdf)

### Inferences
- **サポート量は「状態を持つかどうか」で決まる**（推測）。

  | 形態 | 主な問い合わせ・負担 |
  |---|---|
  | アカウント・保存データ・同期を持つ SaaS | パスワード再設定、データ消失、障害、退会・削除依頼、漏えい時の報告義務 |
  | 端末内処理の Web アプリ / 拡張 / ダウンロード商品 | 「買ったのに使えない」（ライセンス・ブラウザ差）と返金に集中 |

- 最小構成の例:
  - 返金ポリシーを固定文で示す（例:購入後14日以内・理由不問で全額返金）。人が判断する場面をなくす
  - MoR に返金と紛争処理を任せる
  - 問い合わせはメールのみ（特商法でメールは必須）。FAQ で自己解決させる
- 特商法表記の「請求時開示」は、**請求が来たら開示する作業が残る**。完全な無人化はできない。バーチャルオフィスを使う場合、Q18 は運営者が現住所と本人名義の電話を把握していることを求めている。
- Google Play の12人テスター、Apple の審査やり取り、Stripe のセキュリティ申告は、どれもオーナーの手作業として最初に一度発生する。

### Gaps
- 個人開発・買い切りソフトの実際の問い合わせ率、返金率、チャージバック率の信頼できる統計は見つからなかった。
- Stripe Managed Payments の「transaction-level customer support」が日本語で対応するかは未確認。

## 4. AIだけで作るコードの品質・責任リスクと、最低限の安全策

### Takeaway
2023〜2026年の研究と事故は同じ方向を示している。
- AI 生成コードは**約半数のケースで脆弱性**を含む
- 新しいモデルほど安全になる傾向は確認されていない
- 実際の事故は「サーバー側にデータベースがあり、鍵がフロントに露出し、アクセス制御が未設定」のパターンに集中している

サーバー側に個人データを持たず、ブラウザ内で処理する構成なら、この典型パターンをほぼ丸ごと避けられる。

### Cited Findings
- **Veracode 2025 GenAI Code Security Report**（2025年7月30日） — [Veracode プレスリリース](https://www.veracode.com/press-release/ai-generated-code-poses-major-security-risks-in-nearly-half-of-all-development-tasks-veracode-research-reveals/)、[Help Net Security](https://www.helpnetsecurity.com/2025/08/07/create-ai-code-security-risks/)
  - 100超の LLM に80タスクを与えた結果、**45%** が OWASP Top 10 の脆弱性を含んだ

### Inferences
- **最大の安全策は構成で脆弱性の種類を消すこと**（推測）。
  - サーバー・DB・ログイン・秘密鍵を持たない静的サイト＋ブラウザ内処理にする。上の事故類型（DB 誤設定、鍵露出、本番 DB 削除）は構造上起きない
  - 決済は Stripe のホスト型 Checkout / Payment Links で完結させる。カード情報に触れない
- 残るリスクと対策の例:
  - XSS（Veracode で86%失敗）→ 入力を DOM に入れる箇所の自動テスト、CSP ヘッダー、innerHTML の禁止ルール
  - 依存ライブラリ汚染 → 既存方針（CDN・外部ライブラリ禁止）がそのまま効く
  - **計算の誤り** → 代表値・境界値の自動テスト。根拠（法令・公式資料）と確認日を画面に出す（既存の TOOL_SPEC と同じ方針）
- **「AI だけ」の弱点は過信**（Perry ら）。オーナーのデプロイ承認は、コードを読む審査の代わりにはならない。そこで次を CI に入れ、「通らなければ公開されない」状態にするのが現実的。
  - 機械的なゲート:テスト、静的解析・シークレットスキャン（例:GitHub の secret scanning、Claude Code の security-review など）、外部送信の有無チェック
- **有料版でサーバーが必要になったら**（同期、AI API 呼び出し、ライセンス検証）、範囲を最小にする。
  - 認証は外部 IdP、DB は行単位のアクセス制御を必ずテストし、鍵はサーバー側だけに置く
  - それでも「個人データ保管」は避ける側に置く
- **免責条項は保険にならない**。誤計算で損害が出た場合、軽過失なら購入代金を上限とする条項は一般に有効になり得る（8条3項の書き方に合わせた場合）。重過失（明白なバグを放置したなど）は免責できない。AI が書いたことは事業者の過失評価を下げない、と考えるべき。

### Gaps
- Claude Code（または2026年時点の最新モデル）に限ったセキュリティ評価の公的研究は見つからなかった。Veracode は「100超の LLM」の総体を見ている。
- AI 生成コードの不具合で事業者責任が問われた日本の裁判例・行政処分は見つからなかった。
- Escape.tech の調査時期（2025年10月とする二次情報あり）と、RedAccess の別調査（約5,000アプリ）との異同は一次資料で確認していない。

## 5. 結論材料：「AIが作り、オーナーは手を離す」に向く領域・避ける領域

### Takeaway
向くのは「端末内で完結し、結果を利用者が自分で判断する、根拠を示せる計算・変換・ファイル処理・テンプレ」。避けるのは、送金・ポイント、医療効果、紛争前提の法律文書、個別の税務・労務の相談回答、他人のための官公署書類作成、子ども向け、顧客データの保管、利用者間メッセージ。
販売は Web 直販＋Stripe（できれば Managed Payments）か BOOTH / Gumroad。Android は人手が要るので後回し。

### Cited Findings
（根拠は1〜4節の出典。ここでは判断に直結するものだけ再掲する）
- ソフトの開発・販売は税理士業務に当たらない（国税庁 Q&A 問6-3）。個別具体的な質問への答弁・指示は税務相談で、無償でも「業」になり得る（問2-1・2-2） — [国税庁 Q&A](https://www.nta.go.jp/taxes/zeirishi/zeirishiseido/qa/pdf/all.pdf)
- 紛争前提の書面（訴状・和解契約書など）の作成サービスは72条に抵触すると評価され得る — [法務省 2026年GL概要](https://www.moj.go.jp/content/001469039.pdf)

### Inferences

#### 向く（◎）〜条件付き（○）

- 既存の「エンジニアの道具箱」（静的・完全クライアントサイド・外部送信なし）は、上表の◎とほぼ一致している。段2の有料化は次の順が、法令・運用・品質のどの面でも最も低リスク（推測）。
  1. 同じ構成のまま Pro 機能を Stripe（Managed Payments）で売る
  2. テンプレ類を BOOTH で売る
  3. 余力があれば Chrome 拡張
- 例外として「AI API を使う有料機能」（文章生成など）がある。サーバー側で API キーを持つ必要があり、状態・費用・不正利用・外部送信の論点が一気に増える。手離れの観点では後回しが妥当（推測）。

### Gaps
- 「概算の税額・社会保険料の計算機」が、表示の仕方（「あなたの納税額」と断定するか、「概算・目安」とするか）で税務相談と評価されるかについて、公的な当てはめ例は見つからなかった。国税庁 Q&A 6-3 は「申告書等の作成ソフト」についての回答で、計算ツール一般への明示はない。
- 子ども・教育向けツールの日本法上の追加義務（同意取得年齢など）は今回の範囲外で未調査。

## Q1. note で何を売れるか（ファイル・リポジトリ招待・規約・手数料・出金）

### Takeaway
note では有料記事に**ファイルを直接添付して販売できる**（1ファイル50MBまで）。規約上、ソフトウェアやコードの販売そのものは禁止されていない。禁止対象は「マルチ商法等、当社がユーザーに不利益をもたらすと判断する情報商材」「『必ずもうかる』等の誤解を招く表現」「売上を公開して購入を煽る行為」「有害なプログラム」など。実質の手数料はクレジットカード決済なら約14.5%、キャリア決済なら約23.5%で、ほかに出金1回ごと270円がかかる。メンバーシップは**月額課金のみ**で、外部コミュニティ（Slack/Discord）からの自動退会はできない。このため GitHub リポジトリへの招待・解除は手作業になる。

### Cited Findings
**ファイル配布**
- 公式ヘルプ:「記事に価格を設定(=有料記事を作成)し、有料エリアに動画を埋め込んだり、ファイル自体を記事に添付することで、動画やファイルの販売をすることが可能です。」— [note ヘルプ「動画やファイルを販売する」(更新 2026-10-16)](https://www.help-note.com/hc/ja/articles/19598976562457)
- アップロードの上限は1ファイル50MB。1日にアップロードできる回数は無料会員10回、noteプレミアム100回、note pro 300回。「ファイルがアップロードできない場合は、Zip形式に圧縮してアップロードしてみてください」とある。ファイルはウイルスチェックされ、ダウンロードは公開後に有効になる。「利用規約に反するファイルは運営側で削除することがあります。」— [note ヘルプ「ファイルアップロード機能について」(更新 2026-10-16)](https://www.help-note.com/hc/ja/articles/360016349894)
- 規約上の扱い:「本サービスのプラットフォーム上でクリエイターが配信し、ユーザーが購入することのできるデジタルコンテンツは、当社が指定するデータ形式またはファイル形式によるデジタルコンテンツに限られます。」— [note ご利用規約 第24版（2026-10-08制定）](https://terms.help-note.com/hc/ja/articles/44943817565465)
- 外部リンク先も審査の対象になる:「クリエイターがアップロードした有料または無料のデジタルコンテンツの内容（パスワード等の識別符号によりアクセスが制限されているリンク先の外部サイトや添付ファイルを含みます。）を確認することができる」— [note ご利用規約 第24版](https://terms.help-note.com/hc/ja/articles/44943817565465)

**メンバーシップ（継続課金）と外部サービス連携**
- 「メンバーシップは月額会費のみです。」— [note ヘルプ「メンバーシップに関するよくあるお問い合わせ」(更新 2026-10-02)](https://www.help-note.com/hc/ja/articles/900000164086)
- Slack・Discord・Facebook と連動して運営していても、メンバーシップを退会したときの自動退会は「できません。メンバーご自身にご退会いただくか、オーナーによる手動での退会手続きをお願いいたします。」— 同上
- 特典には「外部サービスへの参加リンク」を設定できる。メンバー限定エリアにリンクを貼れば、限定コンテンツとして提供できる。— 同上
- メンバーシップ利用者の「ユーザー名、プラン名、その他ユーザーが本サービス上で設定した情報（外部サービスのアカウント名、メールアドレスなど）がクリエイターに提供されます。」— [note ご利用規約 第24版](https://terms.help-note.com/hc/ja/articles/44943817565465)
- 無料招待で参加できるのは10名まで。— [note メンバーシップ FAQ](https://www.help-note.com/hc/ja/articles/900000164086)

**禁止事項（情報商材・誇大表現など）**
- 禁止事項には次のものが含まれる（抜粋）:「マルチ商法等、当社がユーザーに不利益をもたらすと判断する情報商材」「『必ずもうかる』等、ユーザーに著しい誤解を招く表現を用いたもの」「コンピュータウィルスその他有害なコンピューター・プログラムを含むもの」「盗作、剽窃など、他者の著作権等を侵害しているもの」「前各号の内容が掲載されているサイトへのリンクがあるもの」。— [note ご利用規約 第24版](https://terms.help-note.com/hc/ja/articles/44943817565465)、[コミュニティガイドライン(更新 2026-10-17)](https://www.help-note.com/hc/ja/articles/4409925863193)
- 利用停止の事由:「確定・未確定を問わず売上、利益その他これに類するものを公開して、本サービス上で配信するデジタルコンテンツや各種サービスの購入を煽る場合」。悪質な違反の場合は代金を支払わず、違約金として没収されることもある。— [note ご利用規約 第24版](https://terms.help-note.com/hc/ja/articles/44943817565465)
- note は、配信されたコンテンツを「機械学習等の学習データとして第三者に無償または有償で提供することができる」。有償提供はクリエイターが設定でオプトアウトできる。— [note ご利用規約 第24版](https://terms.help-note.com/hc/ja/articles/44943817565465)

**返金**
- 返金を受け付けるかどうかは、クリエイターが（note が指定した種類のコンテンツについて）選ぶ。返金可にした場合、購入から24時間以内に購入者が申し出て note が認めれば契約が解除される。— [note ご利用規約 第24版](https://terms.help-note.com/hc/ja/articles/44943817565465)

**手数料・出金**
- 事務手数料（購入者の決済手段で決まる）: クレジットカード5%、携帯キャリア15%、PayPay 7%、Amazon Pay 7%、noteポイント10%、PayPal 6.5%。プラットフォーム利用料（事務手数料を引いた後の額に掛かる）: 有料記事・有料マガジン・チップ・メンバーシップは10%、定期購読マガジンは20%。振込手数料は1回270円。計算例では、1,000円の記事がカード決済で売れると145円引かれ、出金1回分を含めた振込額は585円。— [note ヘルプ「コンテンツを販売する際に引かれる手数料」(更新 2026-10-12)](https://www.help-note.com/hc/ja/articles/360011358873)
- 出金は代金が確定してから180日以内に申請する。期限を過ぎても申請がなく代金が1,000円以上なら、登録口座に自動で出金される。1,000円未満なら Amazon ギフトカードで送られることがある。— [note ご利用規約 第24版](https://terms.help-note.com/hc/ja/articles/44943817565465)
- 特定商取引法に基づく表示はクリエイターが自分のページに載せる。インボイスは、登録番号を入力したクリエイターについて note が「媒介者交付特例」で代わりに発行する機能がある。— [note ご利用規約 第24版](https://terms.help-note.com/hc/ja/articles/44943817565465)

### Inferences
- note に対応する形は二つある。①**有料記事＋zip添付**（買い切り）と、②**メンバーシップ＋限定記事に GitHub 招待の手順を書き、GitHub ユーザー名を集めて手動で招待する**方式（継続課金）。②は自動の退会連動がないので、解約者の collaborator 権限を外す作業を毎月自分でやる必要がある（Slack/Discord が自動退会しないという公式回答からの類推）。
- 「Claude Code で月◯万円稼げる」「売上◯万円突破」といった訴求は、「必ずもうかる」の禁止と「売上を公開して購入を煽る」の利用停止事由に当たりやすい。ツールの機能・解決する作業で訴求するのが安全。
- zip を添付するなら返金は「不可」にしておくのが妥当。返金可だと、ダウンロードした後に返金できてしまう。
- 有料記事の本文にコードを直接書く場合は、学習データ提供のオプトアウトも確認したほうがよい。
- カード決済以外（キャリア決済15%）が混ざると実質の手数料は20%を超える。1,000円未満の商品は、出金手数料270円の重みも大きくなる。

### Gaps
- note で「GitHub プライベートリポジトリへの招待」を特典にしている販売者の具体例（ブログや X の投稿）は、検索では見つからなかった。
- note の規約・ガイドラインには、ソフトウェア・プログラム販売を名指しで扱う条項（可否・推奨・禁止）が見当たらない。「当社が指定するデータ形式またはファイル形式」の具体的な一覧も確認できていない。
- 返金を選べる「当社が指定した種類のデジタルコンテンツ」に、ファイル添付記事が含まれるかは未確認。

## Q2. 代替販路の手数料と機能（BOOTH / Zenn / Gumroad / Lemon Squeezy / Polar / Stripe / GitHub Sponsors / ライセンスキー）と日本の個人販売者への向き不向き

### Takeaway
国内の販路で手数料が最も安いのは **BOOTH（ダウンロード商品は5.6%＋45円）**。Zenn の本は3.6%＋残額の10%だが、**Zenn が売れるのは本（文章）であってファイル配布ではない**。海外の MoR（販売事業者を代行するサービス。Gumroad・Lemon Squeezy・Polar）は購入者側の VAT・売上税を代わりに処理してくれる。Polar は「GitHub リポジトリへの自動招待」と「ライセンスキー」の特典を標準で持っており、Claude Code のプラグインやリポジトリ配布とは技術的にいちばん相性がよい。一方で、日本への出金が使えるか、為替コストがいくらかは公式ページで確認できなかった。

### Cited Findings
**BOOTH（pixiv）**
- サービス利用料は、ダウンロード商品なら「商品価格 × 5.6％ + 45円」。決済手段に関係なく同じで、無料配布には掛からない。— [BOOTH ヘルプ「売上にかかるサービス利用料が知りたい」(更新 2026-10-10)](https://booth.pixiv.help/hc/ja/articles/115004576874)
- 振込手数料は銀行振込で、3万円未満なら200円、3万円以上なら300円（税込）。PayPal は無料。— [BOOTH ヘルプ「振込手数料はいくらですか？」(更新 2026-10-14)](https://booth.pixiv.help/hc/ja/articles/231284808)
- インボイスを発行できるのは、事業者情報にインボイス発行事業者の登録内容を設定したショップに限られる。— [BOOTH ヘルプ「インボイス制度とは何ですか？」(更新 2026-02-10)](https://booth.pixiv.help/hc/ja/articles/21344574016793)
- ダウンロード商品を非公開にしたときの過去購入者の扱いや、再ダウンロードについての FAQ がある（アップデート配布の運用に関係する）。— [BOOTH ヘルプ 360002964114](https://booth.pixiv.help/hc/ja/articles/360002964114)、[360009206893](https://booth.pixiv.help/hc/ja/articles/360009206893)
- 禁止商品・要修正商品の基準は「ピクシブのサービス共通利用規約第14条」に基づき、2022-12-15 から適用されている。— [BOOTH ヘルプ「規約で禁止されている取引や商品とは何ですか？」](https://booth.pixiv.help/hc/ja/articles/13002463227545)

**Zenn（本）**
- 決済手数料は販売価格の3.6%（「Stripe の決済手数料に準拠」）。プラットフォーム利用料は、決済手数料を引いた額の10%。振込手数料は申請1回350円。例として、1,000円の本の受取額は ¥868。— Zenn FAQ「販売や振込の手数料は？」（[zenn.dev/faq/sales](https://zenn.dev/faq/sales)、2026-10-17 にページの JS バンドルから取得）
- 収益は毎月末に確定する。受け取りは現金（銀行振込）か Amazon ギフトカードを選ぶ。現金での申請は受取額の合計が ¥1,000 以上のときだけできる。— [Zenn FAQ「収益はどうやって受け取る？」](https://zenn.dev/faq/payout)
- 「本の購入とは、購入したアカウントに有料コンテンツを閲覧するアクセス権を付与すること」。1アカウントを複数人で使うことはできない。— Zenn FAQ（[zenn.dev/faq](https://zenn.dev/faq)）
- インボイスは、著者が適格請求書発行事業者として事業者番号を登録している場合に限り、購入者の要求に応じて発行される。— [Zenn FAQ「インボイス制度への対応は？」](https://zenn.dev/faq/invoice-issuer)

**Gumroad**
- 自分のページや直接リンクからの販売は「10% + $0.50」。Discover（Gumroad 内の発見機能）経由で新しい顧客が来た場合は30%。月額料金はない。— [Gumroad Pricing](https://gumroad.com/pricing)
- 「Since January 1, 2025, Gumroad handles ALL your tax obligations」。Gumroad が MoR として、納税義務のある地域で税を徴収する。— [Gumroad Pricing](https://gumroad.com/pricing)
- 料金ページには、ライセンスキー機能も日本向け出金の可否も書かれていない。— 同上

**Lemon Squeezy**
- 「5% + 50¢」。米国外の取引には追加手数料がかかる場合がある（料率は別ドキュメント）。MoR として税の計算・徴収を引き受ける。「Automatically issue license keys for your software and apps after each sale.」とある。— [Lemon Squeezy Pricing](https://www.lemonsqueezy.com/pricing)
- 料金ページの上部に「2026 Update: Lemon Squeezy + Stripe Managed Payments」のバナーがあり、フッターは「Sold through Link, LLC f/k/a Lemon Squeezy LLC」。— 同上
- 第三者の解説によると、Stripe Managed Payments（Stripe の MoR 製品）は2026年初めに公開プレビューが始まった。Checkout と Payment Links でしか使えず、Lemon Squeezy のデジタルダウンロード機能やアフィリエイト機能は含まれない。ただし料率については情報源どうしで食い違っている。— [Dodo Payments ブログ](https://dodopayments.com/blogs/lemonsqueezy-alternatives)、[Fungies](https://fungies.io/lemon-squeezy-stripe-acquisition-saas-founders-2026/)（どちらも競合ベンダーのブログで、偏りがありうる）

**Polar**
- Starter プランは無料で 5% + 50¢。Pro は月$20で 3.8% + 40¢（以下、Growth・Scale と段階がある）。米国外カードは +1.5%。出金には Stripe の手数料（アクティブな出金がある月ごとに$2、加えて出金1回につき 0.25% + $0.25）、為替手数料 0.25〜1%、チャージバックは1件$15。Polar は MoR。— [Polar Pricing](https://polar.sh/resources/pricing)
- 特典（Benefits）の種類は Credits、License Keys、Feature Flags、File Downloads、**GitHub Repository Access（「Automatically invite subscribers to private GitHub repo(s)」）**、Discord Invite、Shared Slack Channel。期限切れ（解約済み）のサブスク会員は特典にアクセスできない。— [Polar Docs: Benefits](https://polar.sh/docs/features/benefits/introduction)

**Stripe（Payment Links など、自前で決済する場合）**
- 国内発行カードの決済手数料は一律3.6%（第三者のレビューサイトでの記載。Zenn も「Stripe の決済手数料に準拠」として 3.6% を使っている）。— [BOXIL レビュー](https://boxil.jp/service/6393/reviews/60392/)、Zenn FAQ（上記）

**日本の消費税まわり（大まかに）**
- 2025-04-01 から「プラットフォーム課税」が始まった。対象は**国外事業者**がデジタルプラットフォームを通じて行う、消費者向けの電気通信利用役務の提供で、特定プラットフォーム事業者が代わりに申告・納税する。国内事業者が提供する場合は対象外。— [国税庁 タックスアンサー No.6568](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6568.htm)（検索結果の要約から引用。本文は直接読めていない）

### Inferences
- ¥3,000 の商品1件あたりの手数料を試算すると次のとおり（出金手数料は含まない）。
  - BOOTH: 168円＋45円＝約213円（約7.1%）
  - Zenn 本: 108円＋289円＝約397円（約13.2%）
  - note（カード決済）: 150円＋285円＝435円（14.5%）。キャリア決済なら705円（23.5%）
  - Polar Starter（日本のカード）: 6.5%＋50¢
  - Gumroad 直販: 10%＋50¢
  - USD 建ての3社は、このほかに為替・出金手数料がかかる。上の料率から計算したもので、実際の請求額は未検証。
- 国内向けに**ファイル（zip）を買い切りで売る**なら BOOTH が最も安く、既存のエンジニア・クリエイター層にも届く。note は手数料が高いが、記事本文の集客力と「解説記事＋ファイル」を一体で売れる点が強み。Zenn は「解説本」を売る場で、ツール本体を配る場ではない。本の購入者に GitHub リンクを案内する使い方はありうるが、規約上の可否は未確認。
- **継続課金＋リポジトリ招待を自動化したい**なら、標準機能で対応しているのは Polar（GitHub Repository Access と License Keys）。Lemon Squeezy は Stripe への移行期にあたるため、新しく採用するならリスクを確認する必要がある。
- 海外 MoR を使うと、海外購入者の VAT・売上税は MoR が処理する。ただし日本の居住者としての所得税申告、消費税（課税事業者か免税事業者か、インボイス登録をするか）の判断は販売者に残る。具体的には国税庁の資料か税理士に確認するべき。国内事業者は上記のプラットフォーム課税の対象外。

### Gaps
- GitHub Sponsors の手数料・日本での受け取り条件、Keygen（ライセンスキー SaaS）の料金は、今回の調査では一次情報を取得できなかった。
- Gumroad・Polar・Lemon Squeezy が日本の銀行口座への出金に対応しているか、その条件も公式ページで確認できなかった。
- Lemon Squeezy の新規受付・移行スケジュールと、Stripe Managed Payments の正式な料率は、Stripe 公式で未確認。
- BOOTH のダウンロード商品の容量上限と、ソフトウェア販売に関するガイドライン本文は未取得。
- Zenn の本の価格帯（下限・上限）と「記事は有料で販売できる？」への回答は未取得。

## Q3. Claude Code のプラグイン/マーケットプレイスの仕組みと、有料・非公開配布の可否

### Takeaway
プラグインは `.claude-plugin/marketplace.json` を置いた git リポジトリ（または URL や zip）で配布する。**リポジトリが非公開ならマーケットプレイスも非公開になる**。marketplace.json に支払いの欄はないが、①**非公開 GitHub リポジトリ＋購入者の招待**（Polar などで自動化できる）、②**`archive`（zip）ソースに `headers`/`headersHelper` で認証ヘッダーを付ける**（トークンで制限したダウンロード）、という二つのやり方で「買った人だけがインストールできる」形は技術的に作れる。Anthropic 公式ディレクトリには有料掲載の仕組みは見当たらない。有料のコミュニティマーケットはまだ小さい。

### Cited Findings
- マーケットプレイスは `.claude-plugin/marketplace.json` を持つディレクトリかリポジトリ。「The repository can be private」。プラグインのソースとして選べるのは、相対パス、`github`、`git-subdir`、`url`、`archive`（HTTPS で落とす zip）、`npm`、`command`。— [Claude Code Docs: Create a marketplace](https://code.claude.com/docs/en/plugin-marketplaces)
- マーケットプレイスを使わずに配ることもできる。フォルダか `.zip` を送れば、`claude --plugin-dir` で読み込むか `~/.claude/skills/` に置いて使える。この場合は自動更新されない。— [Claude Code Docs: Publish and distribute a plugin](https://code.claude.com/docs/en/plugins/publish)
- 「Anyone who can clone the repository can install from it, so if the repository is private, the marketplace is private too.」 自動更新は既定でオフ。— 同上
- 非公開リポジトリへのアクセスには、ユーザーのマシンにある git 認証情報（SSH 鍵、または `gh auth login` と `gh auth setup-git` で保存した認証情報）を使う。「Claude Code has no git token of its own, and `marketplace.json` has no field for one.」— [Claude Code Docs: Host and maintain a marketplace](https://code.claude.com/docs/en/plugins/host-marketplace)
- `archive` ソースは git アカウントがなくても使える（v2.1.224 以上）。`sha256` で内容を固定できる。認証ヘッダーは `headers` か、短命トークンを発行する `headersHelper` コマンドで付ける（プラグインエントリへの設定は v2.1.238 以上）。たとえば `{"Authorization": "Bearer ..."}` を出力させる。エントリ側の `headersHelper` は、ユーザーがインストール・更新のたびに承認する必要がある。— 同上
- 「entries carry no audience field, and every user who adds the marketplace sees the whole catalog. Host separate marketplaces for separate audiences.」— 同上
- Team/Enterprise プランでは、claude.ai の組織設定から非公開リポジトリを同期して配布できる。その場合、トップレベルに `bin/` ディレクトリがあるプラグインは拒否される。— 同上
- Anthropic のディレクトリ（claude.ai/directory）に申請するには有料の claude.ai プランが必要。公式マーケットプレイス `claude-plugins-official` は、ディレクトリのポータルからは申請を受け付けていない。プラグインの中身として、フックや MCP サーバー設定は `${CLAUDE_PLUGIN_ROOT}/...` でファイルを参照する。— [Claude Code Docs: Publish](https://code.claude.com/docs/en/plugins/publish)
- `claude-plugins-official` などの公式名は予約されていて、同じ名前のマーケットプレイスは追加を拒否される。— [Create a marketplace](https://code.claude.com/docs/en/plugin-marketplaces)
- 有料のコミュニティマーケットとして Agensi と Agent37 という名前が挙がっているが、「early」で変化が速いとされている。— [ryandoser.com（個人ブログ）](https://ryandoser.com/claude-skills-marketplace/)。claudemarketplaces.com のようなコミュニティのディレクトリは GitHub のものを索引しているだけで、プラグイン自体はホストしていない。— [alexcloudstar.com（個人ブログ）](https://www.alexcloudstar.com/blog/claude-code-plugin-marketplace-skills-2026)
- 公開されている有料商品の例: Gumroad の「Claude Code Power User Kit」（CLAUDE.md テンプレート、コマンド、フック、設定プリセット。買い切りで「Lifetime free updates. 30-day money-back guarantee」）。— [Gumroad](https://retrieverdev.gumroad.com/l/claude-code-power-user-kit)。日本語サイトでは「CLAUDE.md テンプレート集」などを販売している例がある。— [claudecode-lab.com](https://claudecode-lab.com/products)

### Inferences
- 個人が売る場合の構成として現実的なのは、次の三つ。
  - (a) BOOTH/note で zip を売り、`--plugin-dir` か `~/.claude/skills/` に置いてもらう（更新は再ダウンロード）。
  - (b) Polar の GitHub Repository Access で非公開マーケットプレイスのリポジトリに自動招待する（解約すると特典が失効する。`claude plugin update` で更新を届けられる）。
  - (c) 自前のライセンスサーバーと `archive` の `headersHelper` で、トークン付きの zip を配る（実装の手間が大きく、ユーザーの承認も毎回必要）。
- (b) は購入者に GitHub アカウントと `gh auth` の設定を求める。非エンジニアや Cowork のユーザーには向かない。
- 法人に売る場合は、相手が自分の組織の非公開リポジトリと claude.ai の組織同期で配る形になる。トップレベルの `bin/` を避ける設計にしておくとよい。

### Gaps
- プラグインの構成要素（skills / agents / commands / hooks / MCP / LSP）の正式な一覧ページ（plugins/components）は未取得。上の記述は取得したページに出てきた範囲（skills、hooks、MCP サーバー設定）に限られる。
- Anthropic ディレクトリの審査基準に、有料プラグインや外部課金への誘導についての規定があるかは未確認（claude.com の submit / pre-submission ページは未取得）。
- Agensi・Agent37 の手数料、規約、実績は未確認。

## Q4. 商品を制約しうる Anthropic の規約（サブスク OAuth、再販、プロキシ、自動化、商標）と2026年の取り締まり

### Takeaway
ユーザー自身の Claude Code の中で動く **Skills・フック・サブエージェント・プラグイン・MCP サーバー・設定テンプレートの販売は、Anthropic の規約と衝突しない**。危ないのは次のような商品。Claude.ai のログインや OAuth トークンを第三者のアプリで扱うもの（トークンの抽出・保存・中継）。購入者の代わりに Claude の利用料を払う・再販する・中継する（プロキシやルーター）。1つのアカウントを共有させる。自前のハーネスでサブスク枠を使わせる。2026年には1月にサーバー側で遮断され、2月に文書で明確化され、4月4日には OpenClaw などのサードパーティ製ハーネスがサブスク枠の対象から外された。加えて、**製品名やロゴに「Claude Code」「Anthropic」を使うことは認められていない**。

### Cited Findings
- 「Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must complete through Anthropic's own flow.」 Agent SDK を使う開発者は API キー認証を使うこと。ただし「Nor does it prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription」。「Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice.」— [Claude Code Docs: Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)（2026-10-17 取得）
- 「Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK.」— 同上
- 自社製品に Claude Code を組み込む場合: 「The Claude Code binary must not be modified」「Customers may not pay for, resell, or intermediate Claude usage on their end users' behalf. Each end user must authenticate with their own Anthropic API key, Claude subscription plan credentials, or 3P inference provider credential」。Commercial Terms への同意が必要。— 同上
- 名前とロゴ: 「you can't use the Claude Code or Anthropic names or logos as part of your own product, feature, or company name, in your own logo, or in a way that suggests Anthropic built, endorses, or is partnered with your product.」 それ以外の使い方は Trademark Guidelines に従い、書面での許可が必要。— 同上
- Consumer Terms（Free/Pro/Max に適用、Effective October 8, 2025）: 「Except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it, to access the Services through automated or non-human means, whether through a bot, script, or otherwise」を禁止している。アカウントのログイン情報・API キーの共有、アカウントを他人に使わせること、「resell the Services」も禁止。競合する製品・サービスの開発やモデルの学習に使うことも禁止。Outputs の権利は利用者に譲渡される。— [Anthropic Consumer Terms](https://www.anthropic.com/legal/consumer-terms)
- 2026年4月4日から、Claude のサブスクに接続した OpenClaw などの「third-party harnesses」は extra usage（追加購入分）から引かれるようになった。API 利用者には影響なし。Boris Cherny（Claude Code 責任者）は「our subscriptions weren't built for the usage patterns of these third-party tools」と述べた。補償として月額相当の一回限りのクレジットが出た。— [InfoWorld, 2026-04-06](https://www.infoworld.com/article/4154435/anthropic-cuts-openclaw-access-from-claude-subscriptions-offers-credits-to-ease-transition.html)
- それ以前の経緯（二次情報）: 2026-01-09 にサーバー側でサブスク OAuth トークンが公式アプリの外では使えなくなり、OpenCode、Cline、RooCode などに影響した。2月には文書で「Free/Pro/Max の OAuth は Claude Code と Claude.ai 専用」と明記された。— [GIGAZINE 英語版 2026-02-20](https://gigazine.net/gsc_news/en/20260220-anthropic-third-party-block)、[AlternativeTo 2026-02](https://alternativeto.net/news/2026/2/anthropic-officially-bans-using-subscription-authentication-for-third-party-claude-use)。3月に OpenCode へ法的な要求があったという報道もある。— [Sovereign Magazine](https://www.sovereignmagazine.com/article/anthropic-blocks-openclaw-claude-subscriptions)（裏付けは弱い）

### Inferences
- **安全な形**: ユーザーのマシン上で、改変していない Claude Code に読み込ませる設定やコード（SKILL.md、フック用スクリプト、サブエージェント定義、MCP サーバー、CLAUDE.md テンプレート）。認証はユーザー自身の Claude Code に任せる。

## Q5. コピー・海賊版のリスクと対策

### Takeaway
Skills・CLAUDE.md・フック・サブエージェント定義は平文で、購入者のマシンに完全な形でコピーされる。このため**再配布を技術的に防ぐ手段はほぼない**。売れ続けている例は、「更新し続けること（継続課金と自動更新）」「サポート」「解説・導入支援」「ライセンスキーやサーバー側の機能」で価値を作っている。

### Cited Findings
- 自分がホストするマーケットプレイスからインストールした人は、プラグインのコピーをローカルのキャッシュに受け取る（「People who install from your hosted marketplace get a copy in the plugin cache instead.」）。— [Claude Code Docs: Create a marketplace](https://code.claude.com/docs/en/plugin-marketplaces)
- マーケットプレイスを使わない配布は「send people the plugin's directory or a `.zip` of it」。— [Claude Code Docs: Publish](https://code.claude.com/docs/en/plugins/publish)
- Skill は、関連する場面で Claude が読む指示を書いた SKILL.md と、任意のスクリプトやテンプレートでできている。主な配布元は GitHub。— [MindStudio ブログ](https://www.mindstudio.ai/blog/claude-code-skills-install-customize-marketplace)
- 公開マーケットでは、無料の Skills が2,000以上出回っているとされる（2026年5月時点の個人ブログ）。— [alexcloudstar.com](https://www.alexcloudstar.com/blog/claude-code-plugin-marketplace-skills-2026)
- 対策に使える機能: Lemon Squeezy の自動ライセンスキー発行（無効化・再発行ができる）— [Lemon Squeezy Pricing](https://www.lemonsqueezy.com/pricing)。Polar の License Keys と GitHub Repository Access（解約すると失効）— [Polar Docs](https://polar.sh/docs/features/benefits/introduction)。`archive` ソースの認証ヘッダーと `sha256` での固定 — [Host and maintain a marketplace](https://code.claude.com/docs/en/plugins/host-marketplace)
- 販売例の訴求は「Lifetime free updates. 30-day money-back guarantee」で、更新と保証が中心になっている。— [Gumroad: Claude Code Power User Kit](https://retrieverdev.gumroad.com/l/claude-code-power-user-kit)
- あるコンサルタントは Skill を単体では売らず、成果物（サービス）として提供しているという。— [mejba.me](https://www.mejba.me/blog/claude-code-skills-businesses-pay-for-2026)
- note は、購入者情報としてユーザー名とアカウント URL をクリエイターに通知する（特段の設定をしない場合）。— [note ご利用規約 第24版](https://terms.help-note.com/hc/ja/articles/44943817565465)。Zenn も著者の販売履歴に購入者のユーザー名を表示する。— Zenn FAQ（[zenn.dev/faq](https://zenn.dev/faq)）

### Inferences
- 中身が平文の商品（プロンプト、CLAUDE.md、Skills）は「一度売れたら共有される」前提で値付けするべき。低価格（数百〜数千円）の買い切りにして、量と更新で稼ぐ形が合う。
- コピーされにくくする構成の候補は次のとおり。
  - ①**継続更新**: 非公開リポジトリと auto-update で、モデルや Claude Code の仕様変更に追従し続けること自体を商品にする。
  - ②**サーバー側の機能**: MCP サーバーの中核をホスト型にし、API キーやライセンスで認証する。ただし Q4 のとおり、Claude の利用料の中継はしない。
  - ③**コンパイル済みバイナリ**（Go/Rust の CLI）＋ライセンスキー。
  - ④**解説記事・動画・コミュニティ・サポート**を価値の中心に置き、コード自体は MIT で公開する。
- note や Zenn は購入者のユーザー名がわかるので、透かし（購入者ごとの識別子をファイルに埋め込む）で流出元を追える可能性はある。ただし抑止効果は限定的。

### Gaps
- note・BOOTH で販売された Claude Code 向け商品が無断で再配布された具体例、それへの対応例は見つからなかった。
- 有料 Skill と無料 Skill の売上規模や継続率を示すデータは見つからなかった。

## Q6. OSS ライセンスの落とし穴（ccusage・Serena・Repomix などを使う・包む場合）

### Takeaway
**ccusage と Repomix は MIT** で、有料の製品に組み込んで売ることもできる。条件は著作権表示と許諾表示を残すこと。**Serena は v2 から GPL-3.0-or-later に変わった**（最後の MIT 版は v1.7.0）。v2 以降を組み込んで配布すると、その組み合わせ全体に GPL が掛かり、購入者には再配布する自由が生じる。このため有料のクローズドな商品にはできない。

### Cited Findings
- ccusage: `apps/ccusage/LICENSE` は「MIT License / Copyright (c) 2025 ryoppippi」。— [GitHub: ryoppippi/ccusage apps/ccusage/LICENSE](https://raw.githubusercontent.com/ryoppippi/ccusage/main/apps/ccusage/LICENSE)（2026-10-17 取得）
- Repomix: MIT（「Copyright 2024 Kazuki Yamada / Permission is hereby granted, free of charge, ... to use, copy, modify, merge, publish, distribute, sublicense, and/or sell copies of the Software ... subject to the following conditions」）。— [GitHub: yamadashy/repomix LICENSE](https://raw.githubusercontent.com/yamadashy/repomix/main/LICENSE)（2026-10-17 取得）
- Serena: 「This repository is licensed per component: SolidLSP under the MIT License and the Serena application under GPL-3.0-or-later.」「any distribution that combines both - such as the `serena-agent` package - is as a whole subject to the terms of GPL-3.0-or-later.」 履歴: GPLv2 で始まり、2025-05-01 に MIT へ変わり、v2 から GPL-3.0-or-later。「Last MIT-licensed release: v1.7.0」「The license change is NOT retroactive.」 コントリビューションには CLA が必要。— [GitHub: oraios/serena LICENSE](https://raw.githubusercontent.com/oraios/serena/main/LICENSE)（2026-10-17 取得）
- note の禁止事項には「盗作、剽窃など、他者の著作権等を侵害しているもの」が含まれる。— [note ご利用規約 第24版](https://terms.help-note.com/hc/ja/articles/44943817565465)

### Inferences
- **MIT / Apache-2.0** は、コードを同梱するなら LICENSE ファイル（Apache なら NOTICE も）を zip に入れることが条件になる。名前の後ろに商品名を付けるだけの「ccusage Pro」のような命名は、作者が公認しているように見える。商標の観点からも避けたほうがよい。
- **GPL-3.0（Serena v2 以降）** を同じ配布物に組み込んだり改変して同梱したりすると、配布物全体の GPL 準拠（ソースの提供と再配布の許可）が必要になる。有料で売ること自体は GPL でもできるが、購入者が自由に再配布できるため、価格を維持できない。ユーザーに別途 `uvx` などでインストールしてもらい、MCP 設定で参照するだけにすれば「同梱して配布」を避けやすい。ただし結合の解釈はケースによるので、法的判断ではない。
- **AGPL** のコードをホスト型サービス（SaaS 部分）に使うと、ネットワーク越しに提供するだけでソースの開示義務が生じうる。今回の3つは AGPL ではないが、MCP サーバーなどの依存関係に AGPL が混ざっていないか確認が必要。
- 人気 OSS は**ライセンスが途中で変わる**（Serena が実例）。依存先のバージョンを固定し、更新のたびに LICENSE の差分を確認する運用が必要になる。

### Gaps
- Apache-2.0 や AGPL の条文そのもの、FSF・OSI の解説は今回取得していない（上の推論は一般的な理解に基づく）。
- 「別プロセスとして呼び出す・MCP で接続するだけなら GPL の結合に当たらない」という点について、権威ある解釈（FSF FAQ など）は今回取得していない。
- ccusage はモノレポで、パッケージごとにライセンスが違う可能性がある。全パッケージは確認していない。
